# Первый настоящий проект

[English](first-run-v1.en.md) · [Русский](first-run-v1.md) · [Документация](index.ru.md)

**Цель:** открыть Studio для нового проекта, подключить инструмент и понять, как осознанно запустить работу.
Если хотите только посмотреть интерфейс, начните с [демо без аккаунтов](../README.ru.md#попробуйте-демо).

Если у вас уже есть локальная папка проекта, начните с неё после установки сборки. Сначала один
раз настройте общий профиль в терминале: `conduct providers --profile`. Затем остановите другие
`conduct up` и агентов, работающих в этой папке, и явно добавьте её:

```text
conduct projects add --dir "<абсолютный путь к папке>" --legacy-writers-stopped
```

Замените текст в угловых скобках настоящим абсолютным путём. Команда сама проверит папку и git,
создаст данные проекта, если их ещё нет, скопирует конфигурацию профиля и зарегистрирует проект.
Она не запускает харнесс и не делает платный вызов. Если `conduct hub` уже работает, проект
появится на его странице после обновления данных; сама команда не меняет активный проект.

Понадобятся Python 3.11+, сборка кандидата V1 и штатные coding-инструменты, которыми вы будете пользоваться.
**Wheel** — установочный файл Python с расширением `.whl`; **виртуальное окружение** — папка для отдельной установки.
Для разработки из исходников используйте [CONTRIBUTING](../CONTRIBUTING.ru.md).

## 1. Установите конкретную сборку

Возьмите wheel и SHA256 кандидата у сопровождающего проекта или из указанного им запуска CI.
Установка основной ветки или совпадение номера `0.1.0` ещё не означает, что это тот же кандидат.
Результаты приёмки записаны в [заметках к кандидату](release-notes-v1-alpha.ru.md); эта инструкция не подтверждает проверку платформ.

<details open>
<summary><strong>Windows · PowerShell</strong></summary>

В первой строке укажите настоящий путь к wheel. Следующие блоки выполняйте в том же терминале, где определена переменная `$conduct`.

```powershell
$wheel = 'C:\Downloads\agent_conductor-0.1.0-py3-none-any.whl'
Get-FileHash -Algorithm SHA256 -LiteralPath $wheel
$install = Join-Path $env:LOCALAPPDATA 'DecemberCommand\app-v1'
py -3 -m venv $install
$python = Join-Path $install 'Scripts\python.exe'
$conduct = Join-Path $install 'Scripts\conduct.exe'
& $python -m pip install $wheel
& $conduct --help
```

Если команды `py` нет, подставьте вместо `py -3` полный путь к `python.exe` версии 3.11 или новее.

</details>

<details>
<summary><strong>macOS / Linux · терминал</strong></summary>

Используйте новую папку установки и настоящий путь к wheel. Сравните его хеш с выданным SHA256.
Оставьте этот терминал открытым для следующих шагов.

```sh
wheel="$HOME/Downloads/agent_conductor-0.1.0-py3-none-any.whl"
python3 -c 'import hashlib,sys; print(hashlib.sha256(open(sys.argv[1], "rb").read()).hexdigest())' "$wheel"
install_dir="$HOME/.local/share/december-command/app-v1"
python3 -m venv "$install_dir"
python_bin="$install_dir/bin/python"
conduct="$install_dir/bin/conduct"
"$python_bin" -m pip install "$wheel"
"$conduct" --help
```

</details>

**Вы должны увидеть:** справку с командами `ownership`, `providers` и `up`.
Если их нет, проверьте путь к исполняемому файлу и сборку, прежде чем продолжать.

## 2. Создайте новый пробный проект

Для первого запуска выберите новую папку. Если в `DecemberTrial` уже есть данные проекта, используйте другое имя.

На Windows держите путь проекта коротким: не длиннее 82 символов, как `%USERPROFILE%\DecemberTrial`.
`init`, активация и `up` работают при любой длине, но сохранение черновика процесса отказывает
с `windows_path_too_long`, если путь проекта плюс 49 плюс длина идентификатора процесса (до 128
символов) больше 259. Для черновика предел корня проекта — 82 (корень + 49 + идентификатор ≤ 259).
У `conduct projects add` отдельный отказ `root_path_too_long` со своим пределом: путь проекта не
длиннее 100 символов; на `init`, активацию и `up` он не влияет.

**Windows**

```powershell
$project = Join-Path $env:USERPROFILE 'DecemberTrial'
New-Item -ItemType Directory -Path $project | Out-Null
& $conduct init --template default-orbit --dir $project
& $conduct ownership activate --legacy-writers-stopped --dir $project
& $conduct ownership status --dir $project
```

**macOS / Linux**

```sh
project="$HOME/DecemberTrial"
mkdir "$project"
"$conduct" init --template default-orbit --dir "$project"
"$conduct" ownership activate --legacy-writers-stopped --dir "$project"
"$conduct" ownership status --dir "$project"
```

**Вы должны увидеть:** начальную инструкцию после `init` и состояние владения `active` после активации.
Начальная инструкция помогает агенту заполнить карту проекта; её печать не запускает агента.

Владение означает, что этот экземпляр приложения управляет записью данных проекта.
Активация переносит данные `conductor/` в `conductor.v3/`, создаёт служебные записи `.conduct/`
и оставляет файл `conductor`, который не пускает прежних писателей. Не переименовывайте и не удаляйте эти объекты вручную.
Флаг `--legacy-writers-stopped` подтверждает, что старые процессы записи остановлены; в новом пробном проекте их ещё нет.
Это инструкция для нового проекта, а не перенос уже работающих запусков.

## 3. Подключите нужные инструменты

**Провайдер** здесь — настроенное подключение к harness: исполняемый файл, профиль входа и разрешённое окружение.
Для знакомства не обязательно подключать все пять. Для исполнения процесса должны быть готовы все участники, которых он использует.

Откройте интерактивный мастер один раз для каждого нужного подключения:

```powershell
# Windows
& $conduct providers --dir $project
```

```sh
# macOS / Linux
"$conduct" providers --dir "$project"
```

| Инструмент | Версия, закреплённая в кандидате | Что указать мастеру | Для задач в V1 |
| --- | --- | --- | --- |
| Claude Code | 2.1.239 | Штатный исполняемый файл, вход по подписке (читаются квоты), выделенный `CLAUDE_CONFIG_DIR`. | Нужен API-ключ: имя `ANTHROPIC_API_KEY` в `env_allow`. |
| Codex | 0.112.0 | Штатный исполняемый файл, вход по подписке (читаются квоты), выделенный `CODEX_HOME`. | Нужен API-ключ: имя `OPENAI_API_KEY` в `env_allow`. |
| Kimi Code | 0.38.0 | Штатный исполняемый файл, вход по подписке (читаются квоты), выделенный `KIMI_CODE_HOME` с управляемым OAuth-входом. | Нужен API-ключ: имя переменной в `env_allow`. Работу по API-ключу с настоящим вендором продукт не проверял. |
| Grok Build | 1.0.5 | Штатный исполняемый файл, вход по подписке (читаются квоты), выделенный `GROK_HOME` со штатным входом. | Нужен API-ключ: имя переменной в `env_allow`. Работу по API-ключу с настоящим вендором продукт не проверял. |
| DeepSeek Harness | 0.1.0-rc.7 | Исполняемый файл Node **и** entrypoint-скрипт DSH; режим API-ключа; разрешённое имя `DEEPSEEK_API_KEY`. | Тот же режим API-ключа. |

Настройка подключения не означает, что задача исполнится: см. [Где задачи исполняются в этой сборке](#где-задачи-исполняются-в-этой-сборке).

В мастере вопрос о входе выглядит так: `1` — собственный вход по подписке, `2` — ключ из окружения.
Под ним мастер печатает (только по-английски): «In this version only 2 runs tasks inside the
execution boundary (on Windows); with 1 the quotas are read and every task is refused before it
starts.» Для настоящих задач выбирайте `2` и разрешите имя переменной; пункт `1` оставляет только
чтение квот. `env_allow` — список разрешённых имён переменных окружения (не значений).

Чтобы использовать подключения в нескольких проектах, один раз настройте общий
профиль командой `conduct providers --profile` в терминале — повторите её для
каждого подключения. Файл лежит в `~/.december-command/providers.json` либо в
папке `CONDUCT_HOME`. Затем примените профиль к каждому **остановленному** проекту:

```powershell
& $conduct providers --dir $project --from-profile
```

```sh
"$conduct" providers --dir "$project" --from-profile
```

Применение не задаёт вопросов. Подключения с тем же id провайдера заменяются,
остальные подключения проекта сохраняются. Папки входа остаются на месте:
учётные данные и файлы логинов не копируются. Если профиль повреждён, вся
операция отказывается, файл проекта остаётся прежним. Для отдельного проекта
по-прежнему можно использовать мастер настройки выше.

У четырёх подписных инструментов нужен штатный исполняемый файл, а не `.cmd` или PowerShell-обёртка.
Мастер проверяет пути, штатный вызов — закреплённую версию. Более новая версия не становится совместимой автоматически.
Десктопное приложение DSH не заменяет CLI-entrypoint в этой настройке.

Для подписки (в V1 она нужна только для чтения квот) выберите выделенный профиль, в котором уже выполнен штатный вход.
Мастер печатает инструкцию входа, но сам не авторизует вас. Рабочий вход в подходящем профиле не нужно повторять.
Дополнительные hooks, плагины, MCP-настройки или нестандартная маршрутизация могут сделать профиль неподходящим.
Пока Studio использует профиль, не открывайте в нём параллельную личную сессию: очистка состояния шага не отличает её файлы от своих.

В вопросе об окружении вводите **имена переменных**, а не значения секретов.
Обычная основа для Windows — `SYSTEMROOT WINDIR PATH TEMP TMP`; добавляйте только нужные инструменту имена.
Не передавайте API-ключи в подписное подключение: это меняет источник оплаты. Для задач в V1
настройте подключение по API-ключу (пункт `2` выше): имя переменной в `env_allow`, значение в окружении сервера.

### Где задачи исполняются в этой сборке

Задача исполняется внутри изоляции (execution boundary). Для V1 это решение владельца H5-V1
(21.10.2026, [OPEN-DECISIONS](recovery/2026-10-20/OPEN-DECISIONS.md)): настоящие задачи исполняются
только по API-ключу; вход по подписке внутри изоляции отказывает до запуска; схема с временной
копией credentials — после V1.

- **Windows.** Изоляция есть. Задача исполняется по дороге API-ключа: мастер разрешает *имя*
  переменной (например, `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `DEEPSEEK_API_KEY`), а значение
  лежит в окружении запускаемого вами сервера. Закреплённая сборка инструмента должна быть
  установлена в папку вида `...\harnesses\<имя>\<версия>\`; иначе изоляцию предоставить нельзя,
  и шаг откажет.
- **Подписка.** Подключение, настроенное на вход по подписке, в V1 не исполняет задачи внутри
  изоляции: шаг отказывает до запуска, ничего не стартует. Это решение владельца, а не сбой.
  Подписка в V1 служит для чтения квот; для задач настройте подключение по API-ключу.
  Оговорка: чтение квот — не задача, но это запуск CLI вендора. Проверка версии и запрос квот
  (RPC вендора) выполняются **вне** изоляции, с настоящим каталогом входа (login-home) вашего
  выделенного профиля, поэтому держите в нём только штатную конфигурацию (см. выше).
  Отказ читается так:

  | Где | Что написано |
  | --- | --- |
  | План и API (дверь плана) | `step '…' demands sandbox route 'execution-boundary' that this build does not provide` |
  | Мастер desk, шаг запуска (`wizard.chain.boundary`) | «Этому шагу нужна изоляция (execution boundary), а выбранному агенту этот компьютер её дать не может, поэтому ничего не запускалось. В этой версии задача исполняется в изоляции только на Windows, только у агента со входом по API-ключу (не по подписке) и только из сборки, установленной в `...\harnesses\<имя>\<версия>\`.» (EN: «This step needs the isolation (execution boundary), and this computer cannot give it to the agent chosen, so nothing was started. In this version a task runs in the isolation only on Windows, only for an agent that signs in with an API key (not a subscription), and only from a build installed under `...\harnesses\<name>\<version>\`.») |
  | Квитанция попытки (появляется, только если транспорт вызван в обход дверей; в обычном пути шаг отказывает раньше, на двери плана) | `this <tool> connection signs in with a subscription, and in this version a task runs inside the execution boundary only with an API key, so no task was spawned`; экран «Запуски» читает её словами runtime: `a subscription login does not run tasks inside the execution boundary in this version`. Подписка называется причиной, только если это единственная недостающая причина; на macOS / Linux и при сборке вне `harnesses\<имя>\<версия>` квитанция говорит общее: изоляция для этой попытки не предоставлена. |
  | Экран «Участники», строка провайдера: текст рядом с меткой `subscription` | «Настроена собственная авторизация провайдера в отдельном каталоге. В этой версии она служит только для чтения квот: задача исполняется в изоляции только с API-ключом.» |
  | `conduct providers` | две строки под вопросом о входе (см. выше) |

  Схема с временной копией credentials отложена на после V1; сейчас её нет.
- **macOS и Linux.** Изоляция на этих системах не предоставляется. Установка, создание проекта,
  Studio, редактор процессов, решения и экран «Участники» работают, но любой шаг, который должен
  исполнить задачу, отказывает до запуска тем же сообщением, каким бы ни был вход. Команды для
  macOS / Linux выше нужны, чтобы настроить и осмотреть проект, а не чтобы исполнить работу.

### DeepSeek: баланс, ключ и перезапуск сервера

Пополняйте баланс **у DeepSeek**. Для прямого DeepSeek API ключ должен быть доступен в окружении как `DEEPSEEK_API_KEY`.
Мастер записывает разрешённое имя; вставлять ключ в Studio или файл проекта не требуется.
В Windows переменную пользователя можно задать через системное окно **«Переменные среды»**,
затем открыть новый терминал, чтобы он получил значение. В других системах передайте переменную процессу сервера через локальную настройку окружения.
Источник баланса поддерживает прямой `https://api.deepseek.com`; произвольный base URL не подтверждает такой же баланс.

Закончите настройку провайдеров до запуска Studio. Если позже поменяли конфигурацию входа или окружение,
остановите сервер через Ctrl+C и запустите его из окружения с новыми значениями.

## 4. Откройте Studio

Блоки ниже восстанавливают пути, если после настройки ключа вы открыли новый терминал.
Если меняли папки в примерах, укажите здесь выбранные вами пути установки и проекта.

```powershell
# Windows
$conduct = Join-Path $env:LOCALAPPDATA 'DecemberCommand\app-v1\Scripts\conduct.exe'
$project = Join-Path $env:USERPROFILE 'DecemberTrial'
& $conduct up --dir $project --port 7777
```

```sh
# macOS / Linux
conduct="$HOME/.local/share/december-command/app-v1/bin/conduct"
project="$HOME/DecemberTrial"
"$conduct" up --dir "$project" --port 7777
```

Откройте напечатанный локальный адрес. Сервер занимает терминал до нажатия **Ctrl+C**.
Пока он работает, состояние владения — `opened`, после штатной остановки — `closed`.
Следующий `up` открывает проект снова. В Studio есть переключатели RU/EN и светлой/тёмной темы.

Останавливайте сервер только через Ctrl+C в его окне и только после того, как напечатан адрес.
Не запускайте его скрыто в фоне (`-WindowStyle Hidden`): Ctrl+C из другого окна до него не дойдёт.
Принудительное завершение (например, `Stop-Process`) оставляет состояние `opened`: следующий `up`
откажет с `recovery_required`, а `ownership status` не отличит живой сервер от убитого.
Восстановление на Windows описано в таблице ниже.

**Вы должны увидеть:** «Обзор» с состоянием нового проекта и экраны «Процесс», «Запуски», «Решения», «Участники».
Пустой новый проект — нормальное состояние. Бесконечная загрузка или пустая страница — нет.

На экране **«Участники»** посмотрите подключения и показания ресурсов.
Открытие Studio запускает чтение источников квот, но не модельную работу. Обновление показаний на странице перечитывает кэш сервера.
Смотрите на источник, время и статус вместе с числом: отсутствие данных не означает нулевой расход,
а отложенное обновление сохраняет возраст прежнего наблюдения. DeepSeek показывает деньги и валюту; сброс не применяется.
Что уже проверено с настоящими аккаунтами, указано в [заметках к кандидату](release-notes-v1-alpha.ru.md).

## 5. Разберитесь с первой настоящей задачей

1. Создайте небольшую задачу с наблюдаемым результатом, например короткий документ для пробного проекта.
2. На экране «Процесс» выберите **«Стандартный цикл»** (`dalio-v5`) и назначьте участников, включая отдельного проверяющего.
3. Опубликуйте версию процесса и откройте запуск для нужной задачи. Проверьте задачу и место выполнения работы.
4. Добавьте инструкцию и необходимые входные документы. Перед разрешением исполнения прочитайте предложение и предпросмотр.
5. Начните с режима **Confirm**, чтобы решать по каждому действию. Для **Policy** отдельно просмотрите бюджеты и разрешите ограниченный запуск.
6. Следите за «Запусками» и «Решениями». Отвечайте на шаги с решением человека и читайте результат проверки до приёмки работы.

Policy не обходит решения человека. Пауза, отзыв разрешения и явное возобновление — разные действия.
Отклонённую работу можно исправить только в пределах плана и разрешения; неопределённый исход не превращается в успех молчаливым повтором.
Шаги 4–6 предполагают исполнение задачи: на macOS / Linux и при входе по подписке такой шаг
отказывает до запуска (см. [Где задачи исполняются в этой сборке](#где-задачи-исполняются-в-этой-сборке)).
Подробный наблюдаемый сценарий есть в [личной приёмке](owner-acceptance.ru.md) и [приёмке двух задач](acceptance-two-tasks.ru.md).

## Если что-то мешает

| Что видно | Следующий шаг |
| --- | --- |
| Нет команды `ownership` | Проверить путь к исполняемому файлу и конкретную сборку. |
| `owner_busy` | Штатно остановить другой сервер этого проекта. Обновление браузера не освобождает владение. |
| `recovery_required` | Выполнить явную проверку восстановления: `conduct ownership recover --dir <project>`. Не удалять служебные записи. Эта команда не запускает модельную работу. На Windows запись старой сборки сначала требует [подготовленной перезагрузки](#восстановление-старой-записи-на-windows). Если сервер этой сборки завершили принудительно (не через Ctrl+C), на Windows нужна полная перезагрузка (**Перезагрузка**, не завершение работы), затем та же команда; `--prepare-restart` для такой записи не нужен, команда сама об этом сообщает. |
| `login_recovery_required` | Тот же путь для общей аренды входа: [подготовленная перезагрузка](#восстановление-старой-записи-на-windows), если её просят, затем `conduct ownership recover-login --auth-home <login directory>`. Эта команда не запускает модельную работу. |
| `not_authenticated` | Завершить штатный вход в настроенном выделенном профиле, затем повторить нужное чтение. |
| У DSH нет данных | Проверить разрешённое имя ключа в настройках и наличие переменной в окружении запущенного сервера. |
| Провайдер не запускается | Проверить штатный путь и закреплённую версию; одного `available` недостаточно для подтверждения входа. |
| Порт 7777 занят | Остановить другой сервер или выбрать порт, например `--port 8080`. |

На macOS / Linux эта сборка задачи не исполняет. Вход по подписке в V1 задачи не исполняет (решение владельца H5-V1): настройте подключение по API-ключу (пункт `2` в `conduct providers`). ### Восстановление старой записи на Windows

Запись проекта или общая аренда входа, которые старая сборка создала на Windows, сами по себе не
доказывают, что компьютер перезапускали. Для такой записи `conduct ownership recover` отказывает и
отправляет сюда. Путь состоит из трёх шагов; выполняйте их по порядку. Сначала остановите сервер проекта,
хаб для него и любой инструмент, работающий через общий вход: живой владелец заставляет команду
отказать, ничего не записав.

1. Подготовьте. Каждая команда пишет одну запись, ничего не освобождает, ничего не запускает и не читает
   токены и файлы входа. Она сообщает, что владение НЕ освобождено, и какую команду выполнить после
   перезагрузки.

   ```text
   conduct ownership recover --prepare-restart --dir "<абсолютный путь к проекту>"
   conduct ownership recover-login --prepare-restart --auth-home "<абсолютный путь к каталогу входа>"
   ```

   Первую строку выполняйте при `recovery_required`, вторую — при `login_recovery_required`.
2. Перезапустите Windows через меню «Пуск» командой **Перезагрузка**. Не используйте **Завершение работы**
   и **Обновить и перезагрузить**: этот путь описан только для полной перезагрузки.
3. Восстановите обычной командой:

   ```text
   conduct ownership recover --dir "<абсолютный путь к проекту>"
   conduct ownership recover-login --auth-home "<абсолютный путь к каталогу входа>"
   ```

Между шагами 1 и 3 проект не открывается: подготовленная запись не освобождает владение. Если на шаге 3
снова просят перезапуск, выполните полную перезагрузку и повторите только шаг 3. Если на шаге 3 сказано,
что записанная среда загрузки не совпадает с текущей, ещё одна перезагрузка не поможет: выполните шаг 1
снова. Только эта команда, запущенная вами, подготовит запись в текущей среде (она добавляет новую
подготовку и сохраняет прежние); затем выполните полную перезагрузку и повторите шаг 3. Если отказ по
другой причине, сохраните вывод для сообщения об ошибке и не удаляйте служебные записи. Запись, которой
подготовка не нужна, сообщает об этом; для неё достаточно обычной команды.

Ещё два вида записей идут тем же путём и с тем же флагом: незавершённые клонирования хаба и займы каталогов
контейнеров активированного проекта (только Windows). Для клонирований сначала остановите хаб: работающий
хаб держит их, и команда откажет. Для займов контейнеров сначала восстановите проект, как выше:

```text
conduct ownership recover-clones --prepare-restart
conduct ownership recover-containers --prepare-restart --dir "<абсолютный путь к проекту>"
```

Выполните полную перезагрузку, затем те же команды без флага. Пока для записи не доказана перезагрузка,
ничего не удаляется: обычный запуск только перечисляет незавершённое и называет действие для каждой записи.
Подготовка сообщает, что ничего не было убрано.
