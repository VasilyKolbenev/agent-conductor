# Первый запуск V1 на Windows

English version: [first-run-v1.en.md](first-run-v1.en.md). Оба документа описывают одни и те же двери и обновляются вместе.

Нужны Python 3.11+, проверяемая сборка December Command и уже установленные поддерживаемые harness. Эти команды относятся к текущему кандидату V1: установка прежней версии из GitHub не гарантирует наличие нового владения, автоматических циклов и источников квот.

## Установка кандидата

В PowerShell укажи путь к полученному wheel. Для локальной разработки вместо wheel можно установить каталог именно проверяемого исходного дерева через `pip install -e`.

```powershell
$candidate = 'C:\Downloads\agent_conductor-0.1.0-py3-none-any.whl'
$install = Join-Path $env:LOCALAPPDATA 'DecemberCommand\app-v1'
python -m venv $install
$python = Join-Path $install 'Scripts\python.exe'
$conduct = Join-Path $install 'Scripts\conduct.exe'
& $python -m pip install $candidate
& $conduct --help
```

В справке должна быть команда `ownership`. Номер Python-пакета пока `0.1.0`: сам по себе он не подтверждает, что установлен текущий кандидат V1. Используй выданный файл сборки и его контрольную сумму.

Файлы пакета кандидата установлены в чистый venv и проверены на Windows (из локально пересобранного архива, файлы пакета побайтно совпадают с кандидатом) и — из самого wheel кандидата — на Linux (WSL Ubuntu): `init` → `ownership activate` → два срока жизни сервера, каждый остановлен Ctrl+C (на Linux — SIGINT) → `closed`. Ни в одной проверке не настраивался аккаунт вендора, а macOS не проверен. Подробности — в [заметках к выпуску](release-notes-v1-alpha.ru.md).

## Новый проект и владение

Для первого знакомства используй новый каталог без прежних данных December Command. Код своего проекта можно подключать позже; этот сценарий не переносит действующие запуски из другой сессии.

```powershell
$project = 'C:\Projects\DecemberTrial'
New-Item -ItemType Directory -Path $project | Out-Null
& $conduct init --template default-orbit --dir $project
& $conduct ownership activate --legacy-writers-stopped --dir $project
& $conduct ownership status --dir $project
```

Сразу после активации `status` сообщает `active`. Флаг `--legacy-writers-stopped` подтверждает, что прежние процессы записи остановлены; в только что созданном проекте их ещё нет.

Активация переносит свежий каталог `conductor/` в `conductor.v3/`, создаёт служебные записи `.conduct/` и оставляет по имени `conductor` файл, блокирующий прежних писателей. Это штатный переход имён: не переименовывай и не удаляй эти объекты вручную. Повторный `init` для активированного проекта не нужен. Новые команды сами находят актуальный каталог данных.

Если в выбранном проекте уже есть рабочие данные, не используй этот краткий сценарий как миграцию. У активации есть отдельные проверки остановки писателей, незавершённых действий и целостности журнала. Для знакомства выбери новый каталог.

## Подключение уже авторизованных инструментов

До запуска сервера выполни в интерактивном терминале:

```powershell
& $conduct providers --dir $project
```

Повтори команду для каждого нужного провайдера. Она сохраняет остальные записи и заменяет выбранного провайдера по его ID. Протокол выбирается автоматически.

| Провайдер | Закреплённая версия | Что указать |
| --- | --- | --- |
| Claude Code | 2.1.239 | Полный путь к нативному исполняемому файлу; `subscription`; каталог уже выполненного нативного входа (`CLAUDE_CONFIG_DIR`). |
| Codex | 0.112.0 | Полный путь к нативному исполняемому файлу; `subscription`; каталог уже выполненного нативного входа (`CODEX_HOME`). |
| Kimi Code | 0.38.0 | Полный путь к нативному исполняемому файлу; `subscription`; каталог `KIMI_CODE_HOME` со стандартным managed OAuth-профилем. |
| Grok Build | 1.0.5 | Полный путь к нативному исполняемому файлу; `subscription`; каталог `GROK_HOME` с нативным cached-token входом. |
| DeepSeek Harness | 0.1.0-rc.7 | Полный путь к Node и отдельно к DSH entrypoint; `api_key`; разрешённое имя `DEEPSEEK_API_KEY`. |

Для подписок выбери первый пункт способа входа и укажи **тот отдельный нативный профиль, в котором вход уже выполнен**. Мастер печатает команды входа, но сам их не запускает. Для уже авторизованного подходящего профиля повторный вход не требуется. Произвольный основной профиль с дополнительными плагинами, MCP, хуками или нестандартным маршрутом модели может быть отклонён: подключение не сводится к копированию файла с токеном.

Пока сервер работает, этот профиль принадлежит продукту: не запускай в нём одновременно свою сессию того же инструмента. После каждого шага продукт забирает служебное состояние одного запуска (сессии, снимки оболочки), появившееся в профиле за время шага, и не может отличить состояние параллельной сессии от состояния шага.

Четырём нативным исполняемым файлам entrypoint не нужен; `.cmd`/PowerShell-обёртка не заменяет нативный исполняемый файл. Мастер проверяет наличие путей, а соответствие закреплённой версии подтверждается при нативном вызове.

В вопросе об окружении вводи только имена. Для обычного Windows-запуска базовый набор — `SYSTEMROOT WINDIR PATH TEMP TMP`; добавляй лишь необходимые своему инструменту имена. На подписном пути не передавай переменные API-ключей: это другой источник оплаты. DSH читает существующее значение `DEEPSEEK_API_KEY` из окружения процесса, который запустит сервер. В файл настроек и в ответы мастеру значение ключа не вводится. Для баланса поддержан прямой `https://api.deepseek.com`; нестандартный `DEEPSEEK_BASE_URL` не даёт показаний этого источника.

Перед запуском сервера заверши настройку и самостоятельную работу с тем же выделенным login-профилем. Если позже потребуется изменить конфигурацию, сначала останови `conduct up`, затем снова запусти мастер и сервер. Настройки провайдеров и выбранные значения окружения считываются при старте сервера.

## Studio и показания

```powershell
& $conduct up --dir $project --port 7777
```

Открой напечатанный адрес, обычно `http://127.0.0.1:7777/`. Терминал остаётся занят сервером; `Ctrl+C` завершает его штатно. В настройках Studio доступны русский и английский языки. Пока сервер работает, состояние владения — `opened`; после штатного выхода — `closed`, и следующий `up` может снова открыть проект.

На экране «Участники» находятся настроенные harness и раздел «Лимиты, баланс и сброс». Сервер читает источники последовательно; страница обновляет показания раз в минуту. «Обновить показания» перечитывает кэш сервера, а не запускает модельную задачу или отдельный запрос к провайдеру.

Вживую пока подтверждено только показание Claude. Для Claude продукт сам читает окна подписки 5 часов и 7 дней; показанное время наблюдения — собственное время кэша вендора. Пока идёт шаг проекта, показание не обновляется: оно показывает «обновление отложено» с прежними данными и их собственным временем. Codex, Grok и Kimi показывают «Источник не подтвердил авторизацию.» (состояние `not_authenticated`), пока в названном для них выделенном каталоге входа не выполнен вход; показания Kimi приходят из собственного OAuth-эндпоинта использования вендора, и ему нужен этот вход. DSH не показывает данных, пока не задан `DEEPSEEK_API_KEY`; его показание — точные денежные суммы, валюта и сообщённая источником доступность средств, сброс не применяется. Отсутствие авторизации, неподдерживаемая настройка, ошибка источника и устаревшее наблюдение остаются явными состояниями; они не превращаются в нулевой расход. «Платёжный аккаунт неизвестен» означает, что показание не объединяется с показаниями других подключений.

Само открытие Studio запускает чтение квот, но не модельную работу. Создай задачу, выбери или опубликуй процесс и открой запуск. Для ограниченного автоматического процесса нужны режим Policy, просмотр конкретных границ и отдельное разрешение «Разрешить ограниченный запуск». Решения человека, которые есть в плане, продолжают ждать человека.

## Linux и macOS

Команды `conduct` те же; отличаются только пути виртуального окружения (`bin/` вместо `Scripts\`) и оболочка вокруг них. На Linux (WSL Ubuntu) путь установки выше — чистый venv, `init`, `ownership activate`, два срока жизни сервера, каждый остановлен SIGINT, `closed` — пройден на wheel кандидата от пользователя без root на ext4, без настроенного аккаунта вендора. macOS не проверен: Mac для проверки не было, а подготовленная CI-задача для Linux и macOS ещё не запускалась.

## Если не получилось

- Нет команды `ownership`: установлен другой или прежний пакет; проверь путь к `conduct.exe` и кандидат установки.
- `owner_busy`: проект уже открыт другим процессом; заверши тот процесс штатно. Повторное чтение страницы не освобождает владельца.
- `recovery_required`: прежнее завершение не подтверждено. Команда `ownership recover --dir ...` выполняет явную проверку восстановления и не запускает работу; не удаляй служебные файлы для обхода отказа.
- Провайдер недоступен: проверь полный путь и закреплённую версию. `available` в списке ещё не доказывает успешную авторизацию.
- Квоты недоступны: проверь способ входа и выбранный профиль; для DSH — наличие разрешённой переменной в окружении до запуска сервера. После изменения окружения перезапусти сервер.

Этот документ описывает реализованные двери по исходному коду. Он не является свидетельством чистой установки wheel или проверки действующих аккаунтов; они записаны отдельно.
