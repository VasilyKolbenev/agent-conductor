# Первый настоящий проект

[English](first-run-v1.en.md) · [Русский](first-run-v1.md) · [Документация](index.ru.md)

**Цель:** открыть Studio для нового проекта, подключить инструмент и понять, как осознанно запустить работу.
Если хотите только посмотреть интерфейс, начните с [демо без аккаунтов](../README.ru.md#попробуйте-демо).

Если у вас уже есть локальная папка проекта, начните с неё после установки сборки. Сначала один
раз настройте общий профиль в терминале: `conduct providers --profile`. Затем остановите другие
`conduct up` и агентов, работающих в этой папке, и явно добавьте её:

```text
conduct projects add --dir "<абсолютный путь к папке>" --legacy-writers-stopped
```

Замените текст в угловых скобках настоящим абсолютным путём. Команда сама проверит папку и git,
создаст данные проекта, если их ещё нет, скопирует конфигурацию профиля и зарегистрирует проект.
Она не запускает харнесс и не делает платный вызов. Если `conduct hub` уже работает, проект
появится на его странице после обновления данных; сама команда не меняет активный проект.

Понадобятся Python 3.11+, сборка кандидата V1 и штатные coding-инструменты, которыми вы будете пользоваться.
**Wheel** — установочный файл Python с расширением `.whl`; **виртуальное окружение** — папка для отдельной установки.
Для разработки из исходников используйте [CONTRIBUTING](../CONTRIBUTING.ru.md).

## 1. Установите конкретную сборку

Возьмите wheel и SHA256 кандидата у сопровождающего проекта или из указанного им запуска CI.
Установка основной ветки или совпадение номера `0.1.0` ещё не означает, что это тот же кандидат.
Результаты приёмки записаны в [заметках к кандидату](release-notes-v1-alpha.ru.md); эта инструкция не подтверждает проверку платформ.

<details open>
<summary><strong>Windows · PowerShell</strong></summary>

Откройте PowerShell из меню «Пуск», а не из терминала внутри приложения Claude или Codex: окно,
запущенное этими приложениями, хранит то, что в нём установлено в `%LOCALAPPDATA%`, в собственной
папке пакета приложения, и ваше обычное окно этого не видит.

В первой строке укажите настоящий путь к wheel. Следующие блоки выполняйте в том же терминале, где определена переменная `$conduct`.

```powershell
$wheel = 'C:\Downloads\agent_conductor-0.1.0-py3-none-any.whl'
Get-FileHash -Algorithm SHA256 -LiteralPath $wheel
$install = Join-Path $env:LOCALAPPDATA 'DecemberCommand\app-v1'
py -3 -m venv $install
$python = Join-Path $install 'Scripts\python.exe'
$conduct = Join-Path $install 'Scripts\conduct.exe'
& $python -m pip install $wheel
& $conduct --help
```

Если команды `py` нет, подставьте вместо `py -3` полный путь к `python.exe` версии 3.11 или новее.

Эта папка установки — общая. Собственная проверка дороги подписки у сопровождающего ставит сборку в
защищённую `%USERPROFILE%\DecemberCommand\product\<build id>`, рядом с инструментами и входами
шага 3; эта инструкция папку выше не меняет.

</details>

<details>
<summary><strong>macOS / Linux · терминал</strong></summary>

Используйте новую папку установки и настоящий путь к wheel. Сравните его хеш с выданным SHA256.
Оставьте этот терминал открытым для следующих шагов.

```sh
wheel="$HOME/Downloads/agent_conductor-0.1.0-py3-none-any.whl"
python3 -c 'import hashlib,sys; print(hashlib.sha256(open(sys.argv[1], "rb").read()).hexdigest())' "$wheel"
install_dir="$HOME/.local/share/december-command/app-v1"
python3 -m venv "$install_dir"
python_bin="$install_dir/bin/python"
conduct="$install_dir/bin/conduct"
"$python_bin" -m pip install "$wheel"
"$conduct" --help
```

</details>

**Вы должны увидеть:** справку с командами `ownership`, `providers` и `up`.
Если их нет, проверьте путь к исполняемому файлу и сборку, прежде чем продолжать.

Нужна сборка с дорогой подписки для Claude Code и Codex. Узнать её можно на шаге 3: вопрос о входе в
`conduct providers` говорит, что с пунктом `1` задача исполняется в изоляции на копии входа. У более
старой сборки такой фразы нет. Сделанная до изоляции (сборка из заметок к кандидату, от 25 сентября)
исполняет задачу по входу по подписке без изоляции; сделанная после изоляции, но до этой дороги,
отказывает любой такой задаче. Опубликованного кандидата с дорогой подписки пока нет: сопровождающий
назовёт ту сборку, в которой она есть.

## 2. Создайте новый пробный проект

Для первого запуска выберите новую папку. Если в `DecemberTrial` уже есть данные проекта, используйте другое имя.

На Windows держите путь проекта коротким: не длиннее 82 символов, как `%USERPROFILE%\DecemberTrial`.
`init`, активация и `up` работают при любой длине, но сохранение черновика процесса отказывает
с `windows_path_too_long`, если путь проекта плюс 49 плюс длина идентификатора процесса (до 128
символов) больше 259. Для черновика предел корня проекта — 82 (корень + 49 + идентификатор ≤ 259).
У `conduct projects add` отдельный отказ `root_path_too_long` со своим пределом: путь проекта не
длиннее 100 символов; на `init`, активацию и `up` он не влияет.

**Windows**

```powershell
$project = Join-Path $env:USERPROFILE 'DecemberTrial'
New-Item -ItemType Directory -Path $project | Out-Null
& $conduct init --template default-orbit --dir $project
& $conduct ownership activate --legacy-writers-stopped --dir $project
& $conduct ownership status --dir $project
```

**macOS / Linux**

```sh
project="$HOME/DecemberTrial"
mkdir "$project"
"$conduct" init --template default-orbit --dir "$project"
"$conduct" ownership activate --legacy-writers-stopped --dir "$project"
"$conduct" ownership status --dir "$project"
```

**Вы должны увидеть:** начальную инструкцию после `init` и состояние владения `active` после активации.
Начальная инструкция помогает агенту заполнить карту проекта; её печать не запускает агента.

Владение означает, что этот экземпляр приложения управляет записью данных проекта.
Активация переносит данные `conductor/` в `conductor.v3/`, создаёт служебные записи `.conduct/`
и оставляет файл `conductor`, который не пускает прежних писателей. Не переименовывайте и не удаляйте эти объекты вручную.
Флаг `--legacy-writers-stopped` подтверждает, что старые процессы записи остановлены; в новом пробном проекте их ещё нет.
Это инструкция для нового проекта, а не перенос уже работающих запусков.

## 3. Подключите нужные инструменты

**Провайдер** здесь — настроенное подключение к harness: исполняемый файл, профиль входа и разрешённое окружение.
Для знакомства не обязательно подключать все пять. Для исполнения процесса должны быть готовы все участники, которых он использует.

Откройте интерактивный мастер один раз для каждого нужного подключения:

```powershell
# Windows
& $conduct providers --dir $project
```

```sh
# macOS / Linux
"$conduct" providers --dir "$project"
```

### Где взять закреплённые сборки

Инструмент должен лежать в `%USERPROFILE%\DecemberCommand\harnesses\<имя>\<версия>\`. Обычная
установка инструмента вендора в другом месте вашего профиля не принимается, а эта сборка сама
инструмент не устанавливает. В альфе сопровождающий выдаёт эти папки вместе со сборкой. Если вы
кладёте их сами:

- **Claude Code 2.1.239.** Возьмите `claude.exe` этой версии из хранилища выпусков, которое читает
  собственный установщик вендора, и сверьте его sha256 с `platforms.win32-x64.checksum` в
  `manifest.json` той же версии оттуда же:

  ```text
  https://downloads.claude.ai/claude-code-releases/2.1.239/win32-x64/claude.exe
  https://downloads.claude.ai/claude-code-releases/2.1.239/manifest.json
  ```

  Положите файл в `...\harnesses\claude-code\2.1.239\`.
- **Codex 0.112.0.** Windows-сборка — вторая версия того же npm-пакета, а не отдельный пакет:
  `@openai/codex-win32-x64` в реестре нет. Скачайте из реестра npm архивы `@openai/codex@0.112.0`
  и `@openai/codex@0.112.0-win32-x64` и сверьте каждый со значением `integrity`, которое даёт
  реестр. Установочных скриптов не запускайте. Содержимое папки `package` первого архива положите
  в `...\harnesses\codex\0.112.0\node_modules\@openai\codex`, второго — в
  `...\harnesses\codex\0.112.0\node_modules\@openai\codex-win32-x64`.
  Исполняемый файл — `codex.exe` в `codex-win32-x64`, который называют строки входа ниже.

**Запускайте мастер при остановленном сервере** (Ctrl+C в его окне; иначе команда откажет с
`owner_busy`), затем снова запустите `conduct up`: провайдеры читаются один раз, при старте.

В мастере вопрос о входе выглядит так: `1` — собственный вход по подписке, `2` — ключ из окружения.
Под ним мастер печатает заметку (только по-английски) о том, что даёт пункт `1` для этого
инструмента:

- **Claude Code и Codex.** Пункт `1` — дорога без API-ключа: «On Windows, with 1 a task runs
  inside the execution boundary on a copy of that login that has no refresh token; the login folder
  itself is never given to a task.» Эта фраза говорит, что сборка делает со входом; она не говорит,
  что инструмент вендора его принимает (см.
  [что проверено с настоящим вендором](#что-проверено-с-настоящим-вендором)).
  Мастер спрашивает папку входа. Она должна называться
  `<что-то>\DecemberCommand\logins\<имя>`; вводите полный путь, например
  `C:\Users\you\DecemberCommand\logins\claude-code` (это
  `%USERPROFILE%\DecemberCommand\logins\<id>`, мастер печатает его с id инструмента). Любая другая
  папка отвергается сразу и спрашивается заново: строка с другой папкой отказывала бы каждой задаче
  до запуска.
- **Kimi Code и Grok Build.** Пункт `1` оставляет любую названную вами папку; квоты читаются, а
  «every task is refused before it starts: a subscription login for this harness is not supported
  inside the execution boundary yet». Для задач выбирайте `2` и разрешите имя переменной.

`env_allow` — список разрешённых имён переменных окружения (не значений).

Чтобы использовать подключения в нескольких проектах, один раз настройте общий
профиль командой `conduct providers --profile` в терминале — повторите её для
каждого подключения. Файл лежит в `~/.december-command/providers.json` либо в
папке `CONDUCT_HOME`. Затем примените профиль к каждому **остановленному** проекту:

```powershell
& $conduct providers --dir $project --from-profile
```

```sh
"$conduct" providers --dir "$project" --from-profile
```

Применение не задаёт вопросов. Подключения с тем же id провайдера заменяются,
остальные подключения проекта сохраняются. Папки входа остаются на месте:
учётные данные и файлы логинов не копируются. Если профиль повреждён, вся
операция отказывается, файл проекта остаётся прежним. Для отдельного проекта
по-прежнему можно использовать мастер настройки выше.

У четырёх подписных инструментов нужен штатный исполняемый файл, а не `.cmd` или PowerShell-обёртка.
Мастер проверяет пути, штатный вызов — закреплённую версию. Более новая версия не становится совместимой автоматически.
Десктопное приложение DSH не заменяет CLI-entrypoint в этой настройке.

Для подписки используйте выделенную папку входа продукта, а не свой профиль инструмента.
Мастер печатает две строки, которые вы выполняете **в своём PowerShell**; сам он не авторизует вас.
Первая направляет инструмент на папку входа, вторая — штатная команда входа инструмента. Мастер не
создаёт папку входа, а Codex завершается с ошибкой, если его домашней папки нет, поэтому создайте
папку до этих двух строк (строка `New-Item` в каждом блоке ниже):

```powershell
# Claude Code
$login = Join-Path $env:USERPROFILE 'DecemberCommand\logins\claude-code'
New-Item -ItemType Directory -Force -Path $login | Out-Null
$env:CLAUDE_CONFIG_DIR = $login
$claude = Join-Path $env:USERPROFILE 'DecemberCommand\harnesses\claude-code\2.1.239\claude.exe'
& $claude auth login --claudeai
```

```powershell
# Codex (пара -c ... хранит вход в файле, который продукт может скопировать)
$login = Join-Path $env:USERPROFILE 'DecemberCommand\logins\codex'
New-Item -ItemType Directory -Force -Path $login | Out-Null
$env:CODEX_HOME = $login
$codex = Join-Path $env:USERPROFILE 'DecemberCommand\harnesses\codex\0.112.0\node_modules\@openai\codex-win32-x64\vendor\x86_64-pc-windows-msvc\codex\codex.exe'
& $codex -c cli_auth_credentials_store="file" login
```

Мастер печатает две строки (переменная, затем вход) с теми путями, которые вы ему дали: копируйте
его строки, а не эти примеры. Строку, которая создаёт папку, он не печатает. Завершите вход в
браузере своим аккаунтом подписки. Без переменной инструмент входит в ваш личный профиль, а папка
продукта остаётся пустой. Рабочий вход повторять не нужно, но у
access-токена ограниченный срок: перед каждой задачей продукт требует, чтобы он пережил таймаут
шага минимум на десять минут, иначе отказывает до запуска и просит войти заново теми же двумя
строками. Обновлять вход вне изоляции продукт в этой версии не умеет, а refresh-токен в задачу
никогда не копирует.
Дополнительные hooks, плагины, MCP-настройки или нестандартная маршрутизация могут сделать папку
входа неподходящей. Пока Studio использует папку, не открывайте в ней параллельную личную сессию:
очистка состояния шага не отличает её файлы от своих.

В вопросе об окружении вводите **имена переменных**, а не значения секретов.
Обычная основа для Windows — `SYSTEMROOT WINDIR PATH TEMP TMP`; добавляйте только нужные инструменту имена.
Не передавайте API-ключи в подписное подключение: это меняет источник оплаты. Имена, которые
заменяют вход или переправляют его трафик (токен, прокси, base URL, сертификаты), отвергаются для
него сразу при вводе. Для задачи по API-ключу настройте подключение пунктом `2` выше: имя
переменной в `env_allow`, значение в окружении сервера.

### Где задачи исполняются в этой сборке

Задача исполняется внутри изоляции (execution boundary) и только по такому входу или ключу, который
эта сборка может ей дать.

- **Windows.** Изоляция есть. Закреплённая сборка инструмента должна быть установлена в папку вида
  `...\harnesses\<имя>\<версия>\` (защищённое место владельца —
  `%USERPROFILE%\DecemberCommand\harnesses\<имя>\<версия>\`); иначе изоляцию предоставить нельзя,
  и шаг откажет. Дорог две.
  - **Вход по подписке Claude Code или Codex**, без API-ключа. Вход лежит в
    `...\DecemberCommand\logins\<имя>`. Перед задачей продукт проверяет, что это обычный вход по
    подписке и что он переживёт шаг, затем копирует его access-токен, **без refresh-токена**, в
    свежую relay-папку под `...\DecemberCommand\relay\` вне проекта. Задача исполняется внутри
    изоляции, и домом инструмента служит эта папка; по окончании попытки она перечитывается и
    удаляется. Саму папку входа задача не получает, и ничего не копируется обратно. Проверка версии,
    статус входа и запрос квот (RPC вендора) по-прежнему выполняются **вне** изоляции, с папкой
    входа, поэтому держите в ней только штатную конфигурацию. Задача отказывает до запуска, если
    папка входа названа иначе, входа нет, это API-ключ или консольный план, срок входа мал либо в
    окружении есть имя, заменяющее вход. Что инструмент вендора после этого работает на копии, с
    настоящим вендором ещё не показано: см.
    [что проверено с настоящим вендором](#что-проверено-с-настоящим-вендором).
  - **API-ключ** для любого инструмента: мастер разрешает *имя* переменной (например,
    `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `DEEPSEEK_API_KEY`), а значение лежит в окружении
    запускаемого вами сервера.
- **Вход по подписке Kimi Code или Grok Build.** В изоляции он пока не поддержан: шаг отказывает до
  запуска, ничего не стартует, а подписка служит для чтения квот. Чтение квот — не задача, но это
  запуск CLI вендора: проверка версии и запрос квот выполняются **вне** изоляции, с настоящим
  каталогом входа вашего выделенного профиля. Отказ читается так:

  | Где | Что написано |
  | --- | --- |
  | План и API (дверь плана) | `step '…' demands sandbox route 'execution-boundary' that this build does not provide` |
  | Мастер desk, шаг запуска (`wizard.chain.boundary`) | «Этому шагу нужна изоляция (execution boundary), а выбранному агенту этот компьютер её дать не может, поэтому ничего не запускалось. A task runs in the isolation only on Windows and only from a build installed under `...\harnesses\<name>\<version>\`.») |
  | Мастер desk, если выбранный агент входит по подписке и его дорога задачи — отказ (`wizard.chain.boundary_login`) | то же, затем: «Выбранный агент входит по подписке, и задача с этим входом отклоняется до запуска: каталог входа должен называться `...\DecemberCommand\logins\<имя>` (задайте его командой conduct providers при остановленном сервере), а вход по подписке для некоторых агентов в изоляции пока не поддержан. Выберите другого агента или агента со входом по API-ключу.» |
  | Квитанция попытки (появляется, только если транспорт вызван в обход дверей; в обычном пути шаг отказывает раньше, на двери плана) | Kimi Code, Grok Build: `this <tool> connection signs in with a subscription, which is not supported inside the execution boundary for this harness yet, so no task was spawned`; экран «Запуски» читает её словами runtime: `a subscription login for this harness is not supported inside the execution boundary yet`. Claude Code, Codex: `the <tool> login is not ready for an isolated attempt: <причина>, so no task was spawned` (с `; sign in again with …`, когда помогает только новый вход) или `the <tool> attempt could not start in isolation: <причина>, so no task was spawned`; экран «Запуски» этих предложений не показывает, он показывает слова runtime, `adapter reported failed: <слова>` (например, `adapter reported failed: the pinned login expires before the attempt would end; sign in again`), и таблица [Если что-то мешает](#если-что-то-мешает) построена по этим словам. Подписка называется причиной, только если это единственная недостающая причина; на macOS / Linux, при сборке вне `harnesses\<имя>\<версия>` и при папке входа, названной не `DecemberCommand\logins\<имя>`, квитанция говорит общее: изоляция для этой попытки не предоставлена. |
  | Экран «Участники», строка инструмента, который компьютер может запустить: метка `boundary` или `refused` и текст рядом с меткой `subscription` | `boundary`: «Настроена собственная авторизация провайдера в отдельном каталоге. Задача исполняется в изоляции на копии этого входа без refresh-токена; сам каталог входа задаче не выдаётся.» `refused`: «… Задача с этим входом отклоняется до запуска. Возможные причины: вход по подписке для этого агента в изоляции пока не поддержан; каталог входа не называется `...\DecemberCommand\logins\<имя>`; либо этот компьютер не даёт изоляцию (нужны Windows и сборка, установленная в `...\harnesses\<имя>\<версия>`).» |
  | `conduct providers` | заметка под вопросом о входе и, для Claude Code и Codex, отказ папке, названной не `<что-то>\DecemberCommand\logins\<имя>` (см. выше) |

- **macOS и Linux.** Изоляция на этих системах не предоставляется. Установка, создание проекта,
  Studio, редактор процессов, решения и экран «Участники» работают, но любой шаг, который должен
  исполнить задачу, отказывает до запуска тем же сообщением, каким бы ни был вход. Команды для
  macOS / Linux выше нужны, чтобы настроить и осмотреть проект, а не чтобы исполнить работу.

### Что проверено с настоящим вендором

Дорога подписки для Claude Code и Codex построена и проверена на поддельных инструментах и входах.
С настоящими вендорами:

- **Claude Code.** Один настоящий ответ получен от инструмента на копии входа без refresh-токена,
  вне изоляции. Задача внутри изоляции, на собственной копии продукта, ещё не выполнялась; первый
  такой запуск станет первой проверкой, а не повторением.
- **Codex.** Задача на нём с настоящим вендором не выполнялась. Сервер вендора отклонил обе пробы
  закреплённой версии 0.112.0 (по модели), поэтому задача может закончиться
  `the process exited non-zero`. Новая версия для закрепления ещё не выбрана.

Заметки мастера и метки на экране «Участники» говорят, что эта сборка делает с папкой и компьютером.
Ни одна из них не говорит, что вендор принимает вход.

### DeepSeek: баланс, ключ и перезапуск сервера

Пополняйте баланс **у DeepSeek**. Для прямого DeepSeek API ключ должен быть доступен в окружении как `DEEPSEEK_API_KEY`.

затем открыть новый терминал, чтобы он получил значение. В других системах передайте переменную процессу сервера через локальную настройку окружения.

Закончите настройку провайдеров до запуска Studio. Если позже поменяли конфигурацию входа или окружение,
остановите сервер через Ctrl+C и запустите его из окружения с новыми значениями.

## 4. Откройте Studio

Блоки ниже восстанавливают пути, если после настройки ключа вы открыли новый терминал.
Если меняли папки в примерах, укажите здесь выбранные вами пути установки и проекта.

```powershell
# Windows
$conduct = Join-Path $env:LOCALAPPDATA 'DecemberCommand\app-v1\Scripts\conduct.exe'
$project = Join-Path $env:USERPROFILE 'DecemberTrial'
& $conduct up --dir $project --port 7777
```

```sh
# macOS / Linux
conduct="$HOME/.local/share/december-command/app-v1/bin/conduct"
project="$HOME/DecemberTrial"
"$conduct" up --dir "$project" --port 7777
```

Откройте напечатанный локальный адрес. Сервер занимает терминал до нажатия **Ctrl+C**.
Пока он работает, состояние владения — `opened`, после штатной остановки — `closed`.
Следующий `up` открывает проект снова. В Studio есть переключатели RU/EN и светлой/тёмной темы.

Останавливайте сервер только через Ctrl+C в его окне и только после того, как напечатан адрес.
Не запускайте его скрыто в фоне (`-WindowStyle Hidden`): Ctrl+C из другого окна до него не дойдёт.
Принудительное завершение (например, `Stop-Process`) оставляет состояние `opened`: следующий `up`
откажет с `recovery_required`, а `ownership status` не отличит живой сервер от убитого.
Восстановление на Windows описано в таблице ниже.

**Вы должны увидеть:** «Обзор» с состоянием нового проекта и экраны «Процесс», «Запуски», «Решения», «Участники».
Пустой новый проект — нормальное состояние. Бесконечная загрузка или пустая страница — нет.

На экране **«Участники»** посмотрите подключения и показания ресурсов. Инструмент, который вы ещё не
настроили, — строка со статусом `unconfigured`. Команду настройки для такой строки экран не
печатает: возьмите её из шага 3 (`conduct providers`, при остановленном сервере). В строке
инструмента, который компьютер может запустить, со входом по подписке рядом с меткой `subscription`
прочитайте метку `boundary` или `refused`: `boundary` — задача этого инструмента на этом
компьютере исполняется внутри изоляции, `refused` — отказывает до запуска, а предложение рядом
называет возможные причины. Строка, где компьютер не может запустить инструмент (доступность не
`available`: `unconfigured`, `executable_absent` или `version_mismatch`), дорогу не показывает.
Открытие Studio запускает чтение источников квот, но не модельную работу. Обновление показаний на странице перечитывает кэш сервера.
Смотрите на источник, время и статус вместе с числом: отсутствие данных не означает нулевой расход,
а отложенное обновление сохраняет возраст прежнего наблюдения. DeepSeek показывает деньги и валюту; сброс не применяется.
Что уже проверено с настоящими аккаунтами, указано в [заметках к кандидату](release-notes-v1-alpha.ru.md).

## 5. Разберитесь с первой настоящей задачей

1. Создайте небольшую задачу с наблюдаемым результатом, например короткий документ для пробного проекта.
2. На экране «Процесс» выберите **«Стандартный цикл»** (`dalio-v5`) и назначьте участников, включая отдельного проверяющего.
3. Опубликуйте версию процесса и откройте запуск для нужной задачи. Проверьте задачу и место выполнения работы.
4. Добавьте инструкцию и необходимые входные документы. Перед разрешением исполнения прочитайте предложение и предпросмотр.
5. Начните с режима **Confirm**, чтобы решать по каждому действию. Для **Policy** отдельно просмотрите бюджеты и разрешите ограниченный запуск.
6. Следите за «Запусками» и «Решениями». Отвечайте на шаги с решением человека и читайте результат проверки до приёмки работы.

Policy не обходит решения человека. Пауза, отзыв разрешения и явное возобновление — разные действия.
Отклонённую работу можно исправить только в пределах плана и разрешения; неопределённый исход не превращается в успех молчаливым повтором.
Шаги 4–6 предполагают исполнение задачи: на macOS / Linux, при входе по подписке Kimi Code или Grok
Build и при входе Claude Code или Codex, лежащем не в `...\DecemberCommand\logins\<имя>`, такой шаг
отказывает до запуска (см. [Где задачи исполняются в этой сборке](#где-задачи-исполняются-в-этой-сборке)).
В мастере desk на шаге ролей предлагаются доступные инструменты; назначьте Claude Code или Codex
по их входу по подписке, а шаг подготовки назовёт причину предложением выше, если выбранный
инструмент нельзя обеспечить изоляцией. Если ни один инструмент ещё не настроен, этот шаг советует
выполнить `conduct providers` или править файл провайдеров: выполняйте команду при остановленном
сервере (шаг 3), а файл вручную не правьте.

Задача с исходом `unknown` не повторяется: не запускайте её снова и не начинайте другую попытку.
Два признака говорят сначала остановить сервер (Ctrl+C):

- Экран «Запуски» говорит `adapter execute lost its result`. Результат шага потерян, а владение
  проектом цело, поэтому одни эти слова перезагрузки не требуют.
- Шаг остаётся начатым без результата, а Studio на каждое действие, которое пишет, отвечает
  «Хранилище запусков недоступно.» Владение проектом стало неопределённым, например потому, что
  закреплённый инструмент не смог запуститься внутри изоляции, и записать больше ничего нельзя.
  Тогда Ctrl+C печатает `stop uncertain`, а следующий `conduct up` откажет с `recovery_required`.

Если `conduct up` или действие откажет с `recovery_required` либо `login_recovery_required`,
перезагрузите Windows (**Перезагрузка**) и выполните команду восстановления для увиденного кода
(см. таблицу ниже). Действие, которое экран «Запуски» отправляет «вне окна», закрывается командой
`conduct reconcile`, а не перезагрузкой (см. таблицу).
Подробный наблюдаемый сценарий есть в [личной приёмке](owner-acceptance.ru.md) и [приёмке двух задач](acceptance-two-tasks.ru.md).

### Восстановление старой записи на Windows

Запись проекта или общая аренда входа, которые старая сборка создала на Windows, сами по себе не
доказывают, что компьютер перезапускали. Для такой записи `conduct ownership recover` отказывает и
отправляет сюда. Путь состоит из трёх шагов; выполняйте их по порядку. Сначала остановите сервер проекта,
хаб для него и любой инструмент, работающий через общий вход: живой владелец заставляет команду
отказать, ничего не записав.

1. Подготовьте. Каждая команда пишет одну запись, ничего не освобождает, ничего не запускает и не читает
   токены и файлы входа. Она сообщает, что владение НЕ освобождено, и какую команду выполнить после
   перезагрузки.

   ```text
   conduct ownership recover --prepare-restart --dir "<абсолютный путь к проекту>"
   conduct ownership recover-login --prepare-restart --auth-home "<абсолютный путь к каталогу входа>"
   ```

   Первую строку выполняйте при `recovery_required`, вторую — при `login_recovery_required`.
2. Перезапустите Windows через меню «Пуск» командой **Перезагрузка**. Не используйте **Завершение работы**
   и **Обновить и перезагрузить**: этот путь описан только для полной перезагрузки.
3. Восстановите обычной командой:

   ```text
   conduct ownership recover --dir "<абсолютный путь к проекту>"
   conduct ownership recover-login --auth-home "<абсолютный путь к каталогу входа>"
   ```

Между шагами 1 и 3 проект не открывается: подготовленная запись не освобождает владение. Если на шаге 3
снова просят перезапуск, выполните полную перезагрузку и повторите только шаг 3. Если на шаге 3 сказано,
что записанная среда загрузки не совпадает с текущей, ещё одна перезагрузка не поможет: выполните шаг 1
снова. Только эта команда, запущенная вами, подготовит запись в текущей среде (она добавляет новую
подготовку и сохраняет прежние); затем выполните полную перезагрузку и повторите шаг 3. Если отказ по
другой причине, сохраните вывод для сообщения об ошибке и не удаляйте служебные записи. Запись, которой
подготовка не нужна, сообщает об этом; для неё достаточно обычной команды.

Ещё два вида записей идут тем же путём и с тем же флагом: незавершённые клонирования хаба и займы каталогов
контейнеров активированного проекта (только Windows). Для клонирований сначала остановите хаб: работающий
хаб держит их, и команда откажет. Для займов контейнеров сначала восстановите проект, как выше:

```text
conduct ownership recover-clones --prepare-restart
conduct ownership recover-containers --prepare-restart --dir "<абсолютный путь к проекту>"
```

Выполните полную перезагрузку, затем те же команды без флага. Пока для записи не доказана перезагрузка,
ничего не удаляется: обычный запуск только перечисляет незавершённое и называет действие для каждой записи.
Подготовка сообщает, что ничего не было убрано.
