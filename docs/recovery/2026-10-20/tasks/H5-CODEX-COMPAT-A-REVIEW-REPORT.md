### Р1 — принять защищённый корень и копирование

`%USERPROFILE%\DecemberCommand\harnesses`; SYSTEM, Administrators и фактический владелец.
Независимо прочитаны ACL: чужая запись в `Documents\Codex` подтверждена; у нового родителя
её нет. Это не свидетельство того, что существующие бинарники уже были подменены.

Создать свежий защищённый root, скопировать без ACL источника. `/inheritance:r /grant:r`
не удаляет произвольные явные ACE: проверить итоговый DACL, родительскую цепочку и дерево,
отсутствие подменяющих reparse points. SID владельца не брать из личности sandbox-процесса.
Claude 2.1.239 скопировать и сверить sha256 с ожидаемым из записи установки до B; обновить
путь продукта и оформить новый грант. Исходную установку сохранить. Codex 0.112.0 и Grok
переносить до их следующего использования с учётными данными, включая откат/П11.
Не менять ACL всего `Documents\Codex`. RX-аренда продукта остаётся разрешённой.

### Р3 — принять ограниченно, только для access-only процессов

`CODEX_REFRESH_TOKEN_URL_OVERRIDE=http://127.0.0.1:9/oauth/token` — точное значение продукта.
По S164 override приоритетнее `oauth_provenance`; это дополнительное ограничение маршрута,
не гарантированное выключение refresh. На порту 9 может быть listener; нельзя обещать,
что любой запрос обязательно закончится локально, только на основании этой строки.
Не применять её к входу/выходу владельца и разрешённому refresh настоящего login-home.
Настоящий refresh token в relay по-прежнему запрещён; copy-out отсутствует.

Обязательный шов: текущий `relay_attempt.py:192–195` проверяет через `spec.forbids` уже
объединённый env. Простое добавление в `forced_env` поэтому заблокирует все Codex-попытки.
Нужен узкий допуск именно значения, внесённого кодом, при сохранении запрета пользовательского
источника. Не разрешать весь `forced_env` и не удалять имя из запретов конфигурации пользователя.
Синтетическая регрессия через публичный preflight: code-owned проходит, чужой адрес/источник
отказывает до claim; поддельные credentials проверяют путь refresh без живого токена.

Поправить env §4 и §6: точное разрешённое значение присутствует при access-only проверках;
остальные маршрутные/token env отсутствуют. Отсутствие refresh-строк и неизменный hash означают
«попытка refresh не наблюдалась», а не доказательство отсутствия сетевого запроса.
Сохранить запас минимум 10 минут сверх всей оставшейся цепочки таймаутов одной копии;
не уменьшать прежний запас до 6 минут. Проверять заново после human gate и перед checker.

### Р4 — выбрать точечный opt-out после П6а

Предпочесть `initialize.params.capabilities.optOutNotificationMethods` для конечного списка
измеренных обычных нотификаций. Не включать experimental API автоматически и не подавлять
warnings/errors ради зелёного результата. Если opt-out не покрывает конкретный штатный метод,
допустим существующий строгий `SubscriptionRpc.notifications` для этого метода; общий decoder
не ослаблять. Неизвестные сообщения, неверные/повторные id и неполный ответ остаются отказом.

П6а должен подтвердить окончательный payload; при изменении после выявленной нотификации
разрешена одна дополнительная metadata-сессия с исправленным payload, без inference.
Профиль/payload/forced env входят в digest, старый грант не переиспользовать.
Контракт exact-match подтверждён в
[официальной документации app-server](https://learn.chatgpt.com/docs/app-server#notification-opt-out).
