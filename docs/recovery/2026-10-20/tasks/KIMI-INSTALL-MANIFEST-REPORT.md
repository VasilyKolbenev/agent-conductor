# Опись кандидата Kimi Code 0.38.0 для Windows x64

Итог — две физически разные копии дали одинаковый SHA-256 описи
`8e0ae4d8916a64123f2a393743ca8df9612d6fab5bbd830f8e14ccb323b49a39`.
TASK/DESIGN `7bb81df`, код и регрессия `679a1a9`. Временная проверка состоялась
16 ноября 2026 года на Windows, Python 3.12.14. Подписка и вход не использовались.

## Как сверить свою копию

Из venv с установленным `conductor` укажите абсолютный путь к ранее подготовленному
комплекту. Скрипт поставляется в исходном репозитории.

```powershell
python -I -B scripts/kimi_windows_kit.py manifest $Kit
```

Успех — exit 0 и JSON с `manifest` и `sha256`. Команда сверяет фактические файлы
и выводит переносимую опись с относительными путями. Публикуется SHA-256 канонических
UTF-8 байтов объекта `manifest`. Отдельный хеш ZIP Kimi и исходные хеши трёх файлов
приведены в [отчёте о комплекте](KIMI-OFFLINE-KIT-REPORT.md).

## Результаты

- В чистой временной папке создана раскладка `harnesses/kimi-code/0.38.0`: `kimi.exe`,
  `shell/sh.exe` и `shell/msys-2.0.dll`. Сборка взяла Kimi из исходного проверенного
  архива и два файла shell из ранее зафиксированного локального комплекта. Опись совпала
  с описью его оригинальной копии. Имена машины и пользователя в результат не входят.
- Отдельный нативный свидетель сверил владельца и DACL семи объектов от `harnesses`
  до файлов. Тестовый корень имел защищённую DACL, потомки наследовали разрешения.
  Доступ имели владелец, SYSTEM и Administrators. После проверки временный корень
  удалён. Команда `manifest` свидетельствует о содержимом, проверка DACL в этом
  эксперименте выполнена отдельно. В продуктовой установке ничего не менялось.
- Исходный ZIP Kimi по-прежнему совпадает с pin. В текущей поставке Git из инструментария
  Codex оба файла shell изменились. Начала хешей `b5a0d9f5e7be` и `513cc5fb15a6`;
  сборщик отказал, каталог версии не появился. Повторить исходную поставку по одному
  пути к «текущему Git» нельзя. Проверенные байты сохранились в предыдущем комплекте.
  У его двух PE-файлов Windows показала действительную подпись OpenAI OpCo, LLC.
  Независимая привязка к выпуску Git for Windows и условия распространения этих
  конкретных байтов пока не подтверждены.
- Красная фаза — неизвестная команда `manifest`. Изменение одного байта того же
  размера приводит к коду 2 без выдачи описи. В двух кодировках прошли по 13 проверок
  (11 функциональных, две проверки длины строк). Независимый проверяющий повторил
  все 11 функциональных тестов.

## Передача

Первый открытый вопрос поставки — закрепить воспроизводимый источник shell и его
зависимости, пригодный для выдачи коллегам. Далее требуется проверить права и identity
всей выбранной установки на машине владельца и связать её, конфигурацию Read и перенос
входа с разрешением конкретной попытки. Отпечаток здесь не выдаёт полномочий.
Проверка shell внутри изоляции, восстановление временного доступа и первое чтение
учебного файла на оплаченной подписке имеют свои критерии. Роль Kimi остаётся закрытой.
