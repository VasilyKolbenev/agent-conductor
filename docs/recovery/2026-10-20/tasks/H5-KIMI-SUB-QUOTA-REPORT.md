# K1b — квота Kimi проверяет выбранный региональный вход

Итог: локально проверено, код b442d01, TASK 884df9a, исходный дизайн 8c22a47. До обращения к CLI клиент проверяет конкретный credential из допустимой пары региона. Отсутствующий вход получает not_authenticated. Неподдержанная форма или небезопасное расположение получает not_supported. Испытания проведены на синтетических профилях; ни исходный бинарник, ни платная подписка не использовались.

## Что доказано

При fake-сервере, готовом сообщать authenticated и usage, старая версия предоставляла квоту даже при отсутствующем токене, неверном регионе, неподдерживаемом JSON, duplicate key и Windows junction. Первое воспроизведение на настоящей Windows вне песочницы: 11 failed, 1 passed по выбранным случаям. С дополнительным тестом удержания каталогов на нетронутой базе 884df9a: 12 failed, 1 passed. Не учитывать предварительный sandbox run с пропущенной junction — создание там было запрещено.

На изменённом коде оба тестовых региона дали данные через штатный quota reader. Побочные/неизвестные файлы, подмена поля, hardlink или junction дают закрытый отказ с нулём subprocess. Вход проверяется в известном каталоге, обход посторонних файлов по содержимому не нужен. В Windows каталог входа и его credentials удерживаются до окончания чтения квоты. В тесте попытки их переименования были отклонены, штатная атомарная замена файла токена прошла, после чтения оба каталога снова можно переименовать. Допустимый метаданный запрос не требует горизонта действия, который предназначен для копии входа при запуске задачи.

Файловая проверка даёт сведения до процесса. Её вывод не гарантирует неизменность содержимого после начала чтения: сам нативный CLI вправе обновить свой реальный токен, а продукт координирует свои вызовы арендой. Настоящий AppContainer relay задачи, POSIX-защита от произвольного локального противника и чтение живой подписки этим тестом не измерены.

## Проверки

- В двух независимых временных каталогах Windows: 644 passed с UTF-8 (58,08 с) и 644 passed с cp1251 (58,91 с). Покрыты Kimi transport/metadata, общий provider/relay, snapshots прежних CLI, граф модулей, subscription road. Свидетели: Documents/Codex/work/kimi-sub-k1a/{utf8-k1b,cp1251-k1b}.txt.
- Отдельная временная копия, M0: 13 passed. Убрана проверка credential: 12 failed, 1 passed. Подменён выбор региона: 1 failed. Допущено неизвестное поле: 1 failed. Ослаблена проверка типа срока: 1 failed. Отпущен native hold до чтения: 1 failed. Для каждого из последних четырёх оставшиеся 12 прошли. Логи k1b-*.txt, копия после проверки SHA и удаления.
- Чужие изменения общей документации и UX в коммит не включались. Открытый дизайн ba83a60 отдельно описывает вложенный relay и требует ревью. Ни этот дизайн, ни K1b не включают подписочное выполнение.

Последний доказанный шаг — распознавание синтетического регионального входа до запуска метаданного сервера. Первый несделанный — независимое ревью вложенной файловой границы, затем проверка исходного бинарника с фиктивной сетью. Не повторять: положительный ответ fake сервера с неверным входом не считается доступом аккаунта, правильная квота не считается результатом задачи.
