# Первый экран и приёмка в Studio

Локально проверено: с первого экрана Studio открывается диалог собственной задачи. Владелец видит проверенные файлы прямо в нужном решении и может записать приёмку с телефона.

Задание и дизайн `94fb276`, реализация `f063262`, бюджет наблюдения браузерного теста `2349625`. База `44aaeaa`; взята однострочная правка конца исходного отчёта из `13972e2`.

* В обычном проекте ссылка открывает настоящий Desk с `new=task`. В демо рядом доступно учебное упражнение. Переход сохраняет язык и настройки оформления и не записывает задачу. Одно ожидающее решение открывает свой запуск; в выбранной задаче чужой запуск эту кнопку не получает.
* Пустой проект предлагает поставить задачу. Непрочитанная задача не считается пустым проектом. У проекта с процессом сохраняются сводки готовности. Подсказка «Начать упражнение» есть только там, где действительно доступна эта кнопка.
* На мобильном экране выбор точки решения переносит фокус к её заголовку и проверенным файлам. Список берётся из того же проверенного снимка, что и в Runs, и только от непосредственных шагов, открывших выбранную точку.
* На старом интерфейсе отсутствовала ссылка в мастер, у настоящего решения отсутствовали файлы. Дополнительный красный свидетель показал, что на 375 px файл находился целиком за краем экрана даже после выбора решения. Замена источника на все шаги запуска обнаружена тестом соседней точки. После офлайн `prepare → apply → check` браузер подтвердил два файла, проверяющего `checker`, отсутствие изменённого позже файла и одну записанную владельцем приёмку. В тесте использованы учебные CLI-двойники.

Проверки: 442/442 теста в каждой из двух кодировок и 77/77 тестов Chromium в каждой. В отдельном контроле старый тест ошибочно истёк через 15.0 с; то же действие завершилось через 20.44 с внутри просмотренного бюджета. Исправленный тест дождался завершения через 20.86 с. Продуктовые пределы сохранены.
