# H5-CODEX-QUOTA-LIVE-DIAG — различить причину source_error

Решение Codex, 28.10.2026. Объём: одно измерение штатного metadata-пути, без inference.

## Факт и цель

На защищённом продукте `9788eb9289bb61d5055061e7fdf3309dcc78de92` сервер проекта
`DecemberCodexFirst` показывает Codex как available/subscription/boundary, но его штатный
опрос квоты возвращает `source_error`. GET кэша не содержит различающей диагностики.
Отдельный corrected P6 и M2 успешны; они не доказывают этот путь: другой home, окружение,
cwd и предел вывода. Конкретная причина пока не установлена.

Цель — узнать стадию и исход отказа без предположительного исправления и без раскрытия
содержимого входа или ответа. Не менять установленный продукт либо ослаблять его проверки.

## Разрешённое измерение

- Сначала закончить либо отложить Goal по решению владельца. Сервер остановить только Ctrl+C;
  подтвердить closed, отсутствие слушателя 7802 и отсутствие активного действия.
- Исходник helper: `Documents/Codex/work/codex-first-product/diagnose-quota.py`, внешний файл.
  Перед живым запуском ведущий читает его, проверяет offline guards, фиксирует хеш и копирует
  в защищённый `%USERPROFILE%/DecemberCommand/h5-a/tools`. Живой helper отказывает из другого
  пути. Маркер остаётся в защищённом h5-a, безопасный отчёт — во внешней папке подготовки.
- Использовать защищённый Python и установленный `9788eb9`; проверить manifest, импорт,
  точный pin 0.164.0, конфигурацию проекта и окружение стартера. Не читать auth напрямую.
- Под acquire_owner создать обычный provider resolution, без запуска сервера/collector.
  Выполнить ровно один штатный `plan.request.read()` — version и quota RPC, как у приложения.
  Маркер создаётся эксклюзивно до read и сохраняется при любом исходе. Автоповтора нет.
- Observer делегирует настоящий ProcessRunner и adapter._attempt ровно один раз с исходными
  аргументами. Не меняет argv, env, cwd, timeout, cap, возвращённый объект или исключение.
  Только два ожидаемых этапа; дополнительные вызовы отклоняются до исполнения.
- Никаких model/list, login/logout, M2, задач модели, ключей API, новых env-переключателей,
  ручного refresh, обратной записи, расширения census или изменения защит Windows.

## Безопасный результат

Разрешены только фиксированная стадия, status, exit code, длины вывода, признаки усечения,
доставки stdin, secret echo, retained/residue и тип исключения без его текста.
Из RPC — лишь ожидаемые числовые response IDs и числовой error.code. Содержимое result,
error.message, stdout/stderr, значения окружения, account ID и credentials не сохранять.
Секретные файлы читает только штатный код внутри своего lease; observer их не открывает.
При неизвестной структуре записать фиксированный отказ, не сериализовать объект целиком.

После read проверить завершение процесса и состояние аренды/владения. Не удалять удержанные
следы или неизвестные остатки. Любая неопределённость останавливает дальнейшие действия.
Причину и решение об исправлении оформить по результату; не выдавать гипотезу за факт.

## Проверка и передача

Offline witness должен различать стадии version/RPC/decode, original exception, усечение,
недоставленный stdin и удержание, а также отсутствие повторного read после маркера.
Подтвердить точное делегирование аргументов/результата и отсутствие сырых данных в отчёте.
Это проверка внешнего измерителя, не новый полный прогон продукта.

Последний доказанный: полный core в обеих кодировках и M2; live quota cache — source_error.
Первый несделанный: одно различающее измерение после остановки сервера и ревью helper.
Не повторять P11, P6/catalog, P8/P9, M2 или полный core без новой причины.
