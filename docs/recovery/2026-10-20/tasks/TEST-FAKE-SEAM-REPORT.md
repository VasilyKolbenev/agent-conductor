# Отчёт по задаче: TEST-FAKE-SEAM — шов запуска фейков на Windows

- Исполнитель: Sonnet (workflow `wf_581253cc-176`), ведущий и ревью — Opus 5.5 (PROC-NO-CODEX).
- Исходный commit: `14f94cf`. Задание: `tasks/TEST-FAKE-SEAM-TASK.md`.
- Цель: снять причину двух красных полного core только в cp1251 (`56d0a22` и `14f94cf`).

## Причина (по коду и измерено)

Шов `tests/_fakeprocess.py` запускает зарегистрированный фейк текущим Python, а не как
неподписанный PE. `conftest.py` ставил его через общую фикстуру `monkeypatch`, поэтому
`monkeypatch.undo()` теста снимал и шов; дочерний интерпретатор `python -c` (`ATTEMPT` в
`test_login_ownership.py`) шва не имел вовсе. Фейк уходил в настоящий запуск, и Windows App Control
то пропускал его, то блокировал (`WinError 4551`), после чего займ процесса не доказывал
завершения (`recovery_required`). Мутант M2 (ребёнок без шва) воспроизвёл именно симптом `56d0a22`;
мутант M5 (шва нет) — `WinError 4551` в журнале.

## Изменения

- `tests/conftest.py` — шов в собственном `pytest.MonkeyPatch.context()`; `undo()` теста его не
  снимает.
- `tests/test_login_ownership.py` — `ATTEMPT` ставит шов сам до `a_harness`; свидетель (б) с
  регистратором под швом (видит argv после перезаписи); таймаут свидетеля — `SETUP_DEADLINE`,
  вывод ребёнка декодируется с заменой (P3 ревью F1, F2, правка ведущего).
- `tests/test_fake_process_runner.py` — свидетель (а): после `monkeypatch.undo()` `subprocess.Popen`
  на Windows остаётся обёрткой шва.
- Детей, которые фейки не строят, не трогали; перечень проверенных — в журнале workflow.
