# Windows: нативная проверка прав файла входа

Исправлена фикстура. На настоящем NTFS проверка продукта принимает приватный
профиль и отказывает, когда встроенная группа Users получает чтение файла.

## Что произошло

В [журнале Windows 3.11](https://github.com/VasilyKolbenev/agent-conductor/actions/runs/43847340640/job/133230695977)
первая проверка закончилась на строке 93 `provider_install_security.py`: при
проверке одного из двух каталогов. До выдачи права `BU:FR` тест не дошёл.
Ни конкретный каталог, ни дескриптор безопасности в журнале не записаны.

Старая настройка передавала `O:<sid>` в `acl_set`, который устанавливает
только DACL. Она также ожидала, что дочерние объекты получат права родителя.
Нативный свидетель до исправления обнаружил у дочернего каталога наследуемую
DACL. В отдельном контрпримере дочерний каталог с защищённой DACL и правом
чтения для Users сохранил это право после изменения родителя. Получен тот же
отказ на проверке каталога. Точное состояние прежней машины CI неизвестно.

## Проверка после исправления

Временный `auth.json` содержит только локальную фиктивную метку. Тест явно
назначает владельцем текущего пользователя и последовательно защищает файл,
его каталог и родительский каталог. Для каждого объекта Win32 возвращает
ожидаемый SID владельца, флаг защиты и побайтно равную DACL. Затем первая
проверка проходит, а добавление одного права чтения Users только файлу
приводит к отказу именно на записи каталога.

Windows x64, по 33 пройденных теста модуля и структурных проверок в каждой
комбинации: Python 3.11.9 и 3.12.14, UTF-8 и CP1251. Проверены мутанты пустой
проверки и снятия требования приватности. Оба обнаружены отсутствием
ожидаемого отказа на файле. Код проверки продукта не менялся.

```text
python -m pytest tests/test_provider_subscription_setup.py tests/test_command_line_cap.py -k provider_subscription_setup
```
