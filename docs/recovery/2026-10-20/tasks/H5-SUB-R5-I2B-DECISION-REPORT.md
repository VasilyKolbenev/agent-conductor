## Вопросы 6, 8, 11, 12, 13

### Q6: аккаунт в доказательствах

Принять хеш идентификатора аккаунта, не access/refresh/id token. Для B достаточно локального
evidence вне Git: источник, vendor и SHA256 идентификатора из проверенного source/relay под
реальной lease; исходное значение не выводить. Не создавать новый token fingerprint.
Если сопоставление не получено допустимым способом, записать «не проверено».

Это идентичность исходного входа/копии, не независимое подтверждение аккаунта сервером.
Не добавлять новое поле продуктового журнала попутно в I3. Полное сохранение `Ready.account` /
`Ticket.account` в доказательствах продукта — до передачи альфы другим пользователям.

### Q8: oauthAccount и F10

По коду `claude_relay.py:74–88` сейчас копируются все плоские значения oauthAccount;
обязательны accountUuid и organizationUuid. Закрытого набора остальных ключей нет.
**Для ограниченного B принять это явным исключением**: целый профиль не копируется,
вложенные значения исключены, настоящий refresh не переносится. Не называть это выполненным
allowlist дизайна. До распространения альфы закрепить измеренный набор; не сужать до двух UUID
вслепую и не расширять схему по одному только сообщению об ошибке.

Для B зафиксировать точные env_allow и forced-env подготовленной конфигурации, вместе с digest.

### Q11: окно теста общей lease

Подтверждён дефект предусловия теста, а не причина задержки ОС: `entered.wait(8)` ограничивает
подготовку, которая измеренно занимала до 17 с. В callback `release.wait(15)` также ограничивает
время запуска второго процесса вместо проверяемого отношения владения. Зелёные повторы не
закрывают прежний красный. Причина разброса старта остаётся неизвестной.

Разрешить точечную правку **после сохранения текущей итерации I3**, перед итоговым полным набором:
явный handshake «первый дошёл до удерживаемого cleanup» с отдельным проверяемым setup deadline;
удержание до сигнала родителя в finally. Ограничители защиты от зависания можно сделать 60 с
для setup и 90 с для ожидания release, как явное отклонение на основании замеров выше.
Это не продуктовый SLA и не retry. Ошибка worker или недостигнутый handshake — красный с
названием нарушенного предусловия; не skip. Смысл теста неизменен: второй не запускается во
время удержания, после освобождения запускается. Product timeout и правила lease не менять.
Зафиксировать старый красный и новый адресный результат; не объяснять задержку неподтверждённой
гипотезой об антивирусе или I2b. Задание: `H5-SUB-R5-I2B-CLOSE-TASK.md`.

### Q12: исчезновение pinned exe

Сохранить fail-closed `recovery_required` / uncertain. В `process.py` неудачный spawn даёт
`loan.retire(False)`; доказательства полного отсутствия child/loan нет. Автоматический повтор,
очистка записи и ослабление правила не разрешены. I3 уже добавляет восстановление в runbook B:
этого достаточно; отдельный ремонт runner перед B не нужен.

### Q13: checker claim

Разрешить новый закрытый reason **claim_refused** только для `NotStarted("claim")`:
«Проверяющий не смог зарезервировать проверку; запуск не состоялся».
`claim_standing` остаётся `marker_standing`, включая нечитаемый marker. Не добавлять retry.
Обновить reason-set, runtime mapping, слова и существующий различающий тест. Это необходимая
правка достоверности, не перестройка lifecycle. Исполнять после текущей итерации I3 по CLOSE-TASK;
его новый коммит снимает прежнее исключение Q13 только в этом объёме.

## D13: узкий A2 перед B

Принять A2 с исправлением обещания: **нативный запуск и освобождение ресурсов**.
Fake token при `-p` не исключает запрос к модели. Поэтому A2 запускает только настоящий
защищённый `claude.exe` 2.1.239 с `--version`, без prompt и настоящего входа.

Реальные relay mint/copy-in/discard, lease, ProcessRunner и AppContainer; синтетические credentials.
Два режима boundary — dispatch и review (checker использует review), два режима кодировки,
последовательно: максимум четыре запуска, timeout каждого 60 с. Это явно разрешённые
неинференсные проверки одного native-сценария, не четыре платных probe и не перебор CLI.
Точный контракт, проверки и stop-условия — в CLOSE-TASK.

Не требовать от этого smoke публичных dispatch/review/checker: их CLI argv содержат inference.
Не подменять половину протокола ради названия E2E. A2 не доказывает авторизацию, чтение токена
CLI, отсутствие refresh во время задачи, модель, verdict или сам цикл. **Всё это впервые
проверяется в B.** Если запуск/retirement неизвестны — остановка и восстановление, не retry.

## Р7–Р10 из отчёта A П0–П5

### Р7 — принять до B

Wheel и venv B находятся в `%USERPROFILE%\DecemberCommand\product\<sha>` с защищённым DACL.
Защищается вся исполняемая цепочка: site-packages, `.pth`, pyvenv.cfg, launcher, базовый Python
и загружаемые библиотеки. Хеши только python.exe/conduct.exe недостаточны: venv может ссылаться
на изменяемый базовый Python. Проверить родителей, фактические пути и возможность замены файлов.

Защищённый manifest содержит точный code SHA, wheel SHA256, canonical paths и inventory
установленного дерева/внешних зависимостей. Его основание — проверенная сборка, не значения из
изменяемого run-ready.json. `$KIT\run-ready.json` — только указатель и копия сведений;
preflight сопоставляет их с защищённым источником и закрыто отказывает при несовпадении.

Прочитанный `h5-a\tools\preflight.ps1` проверяет harnesses/downloads/h5-a, но не product:
его прежние «0 problems» не покрывают новую установку. Дополнить подготовку B этой проверкой,
не проектировать новый installer. Если базовый runtime доступен sandbox-группе на запись,
использовать проверенную защищённую копию для B; защитить только маленький venv недостаточно.

### Р8 — исправить исходное предположение

По коду I2b `harness_attempt.py:54,120–131,507` confined_spec уже заменяет LOCALAPPDATA,
TEMP, TMP на отдельный runtime попытки; relay использует этот же путь. Общий TEMP владельца
не является task-TEMP только потому, что его имя присутствует в allowlist.

Для preflight/quota/login вне boundary использовать защищённый scratch в окружении выделенного
процесса B, без глобальной правки Windows. Убедиться, что итоговый task-TEMP по-прежнему задаётся
confined_spec. Новую реализацию изолированного TEMP не заказывать. Наблюдаемое создание профиля
и runtime отметить в A2; содержимое окружения с секретами не печатать.

### Р9 — принять в A-I1, не препятствие B

Claude был вне AppContainer; отсутствие refresh в продуктовом цикле ещё предстоит подтвердить.
