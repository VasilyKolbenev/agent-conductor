# Первый вход по подписке на Windows

Руководство и приёмка теперь используют один проверенный путь установки. Мастер печатает команды, с которыми Windows PowerShell передаёт Codex нужную строку TOML, а Grok получает запрет автообновления. Локально проверено. Задания `b9b3f12`, `bff9ab5`; реализация и тесты `f3ca4bb`, инструкции `5adc9eb`.

**Исправлено.** Старый путь вёл к снятому Codex 0.112.0 и к подпапке `codex/` вместо `bin/` в актуальном пакете. Новый путь указывает на 0.164.0. RU/EN содержат хеши, требования к правам новой папки на Windows, сборку продукта по проверенному wheel, отдельные папки входа и команды для Claude, Codex, Grok. README и owner acceptance больше не предлагают считать Grok доступным только для квот или Codex никогда не запускавшимся через приложение. Указаны завершённый Goal Claude, технически успешный Goal Codex с непринятым содержанием, допущенный Grok review с неуспешным результатом и оставшаяся живая проверка Kimi.

**Измерено.** Две новые проверки получают строку из диалога `conduct providers`, подменяют только программу на процесс-заглушку и читают argv после настоящей оболочки оператора. До правки: 2 failed. Codex получил `cli_auth_credentials_store=file` без буквальных кавычек, Grok получил только `login`. После правки: 2 passed, входов и модельных вызовов 0. Только в печатаемой строке Windows используется stop-parsing `--%` перед аргументами, которым нужны кавычки. В POSIX шов использует `shlex.join`; Windows PowerShell и POSIX sh из Git for Windows независимо передали точный argv обоих CLI. Запуск дочернего процесса продукта с argv не менялся.

Прогон шести профильных модулей (документы, мастер и Grok) — 152 passed с `PYTHONUTF8=0`, 152 passed с `1`. На последних правках четыре модуля (документы и диалог) — 95 passed и 95 passed. M0 двух новых случаев прошёл. Отмена защиты TOML убила только Codex-свидетель, удаление `--no-auto-update` убило только Grok-свидетель. Исходные SHA256 файлов восстановлены, копия удалена. Диагностика и журналы мутантов: `Documents/Codex/work/pub-nov-timing/`.

Обе памятки дали один блок установки и исполняемые файлы Codex/Grok с ожидаемым sha256. Блок проверен на временном профиле в Windows PowerShell: локальный wheel прежнего кандидата `5d5e5f58d564` установился без сети в `product/<commit12>/venv`, установленный `conduct --help` показал ожидаемые команды. Для прогона подставлены локальный путь и хеш wheel, путь временного профиля, абсолютный Python вместо отсутствующего launcher `py`. В тестовой среде отдельно восстановлен штатный каталог модулей Windows PowerShell, чтобы работал `Get-FileHash`. Настройка прав через Проводник и вход внешнего пользователя в этот прогон не входили. Проверенные ссылки и хеши соответствуют материалам зафиксированных установок; повторных скачиваний вендоров не было.

Последний доказанный шаг — локальные команды установки и точные аргументы входов. Следующий шаг — приёмка финального wheel с собственными подписками владельца по актуальному чеклисту. Не повторять: попытку Codex 0.112.0 и незапланированные живые диагнозы Grok. При обновлении возможностей Kimi пересмотреть соответствующую строку в обеих версиях инструкции.
