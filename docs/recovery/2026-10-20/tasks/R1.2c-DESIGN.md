## 1. Где run становится terminal `stalled`

### 1.1 Кто пишет окончание

`RunTerminal` пишет только `run_closing.close_if_terminal` (`run_closing.py:35-74`). Запись идёт
внутри той же транзакции, что и факт, закончивший план:

- результат попытки: `runtime.py:726-730`, затем `self._notify`, который будит драйвер
  (`policy_wiring.notify_run`); `reconcile` кончается тем же `_finish`;
- решение человека: `http_writes.py:554`, затем `api._publish_run`.

После `RunTerminal` хранилище отказывает в любой записи (`RunClosed`). История авторизации
отказывает в гранте, pause, resume, revoke (`authorization_history.py:164-165`). Дверь решения
отказывает `run_terminal`. Журнал не может «открыть» план снова, и исправление его не трогает.

### 1.2 Откуда слово `stalled`

`graph_schedule._run_state` (`:575-619`) говорит `stalled`, когда ничего не runnable, ничего не в
полёте, есть `blocked`, и этот `blocked` навсегда. У него два источника (докстринг
`run_terminal.py:47-54`):

| Путь | Как | Достижим из desk/Studio |
| --- | --- | --- |
| исчерпанный `attempt_bound` (`_spent`, `:526-530`) при неустроенном шаге | `unknown` на шаге с `attempt_bound=1`; цикл, который просит ещё проход у шага с исчерпанными попытками (`test_command_schedule_laps.py:489`, `:594`); `reconcile` даёт `unknown` | да: `attempt_bound` редактируется в инспекторе desk (`desk-flow-inspector.js:22`) |
| halt (`failure_policy: "halt_run"` и исход из `FAILED_OUTCOMES`, `_is_halted`, `:622-642`) при ещё runnable или ждущем документа шаге | ветка с halt падает, параллельная ветка была runnable (`_stop_runnable`, `:654-669`) | да, через `ext.failure_policy` |

Решение человека тоже может закончить план словом `stalled`, если откроет дорогу к шагу с
исчерпанными попытками. Исправление общее и от пути не зависит.

### 1.3 Путь драйвера, чтения и слота сейчас

- `_tick` (`policy_driver.py:199-207`) → settler: для terminal он после R1.2b отвечает `True` →
  `_admit_next` → `_select_next` → `_next_node`. После R1.2b `_next_node` (`:300-325`) отвечает
  `(None, "stalled")`, не бросая исключения на `unknown`. Но `_select_next` вызывает `deactivate`
  только при `reason == "complete"` (`:259-262`). Run остаётся активным. Причина драйвера —
  `stalled`.
- `automation_view` → `_state` (`policy_view.py:44-75`):
  - пока драйвер держит run — `("stalled", "stalled")`, в окне до тика — `("stalled",
    "plan_stalled")`;
  - драйвер не держит run (после перезапуска) — `("restart_required",
    "explicit_resume_required")`;
  - run на паузе — `("paused", "paused")`;
  - грант истёк — `("expired", "expired")`.
- `slot_reading` (`queue_reading.py:52-88`): `stalled` ∈ `_STUCK` → `stuck/stalled`. Насос
  очереди стоит (`policy_driver.py:156-158`), прямой authorize другого run получает `SlotBusy`.

## 4. Дизайн исправления

### 4.1 Правки

(а) `policy_driver.py`, `_select_next`:

```python
            if selected is None:
                ended = reason in TERMINAL_STATES
                if ended:
                    self.deactivate(run_id)
                return None, ended
```

`_next_node` возвращает слово плана только при `run_state != "open"`. Поэтому `reason in
TERMINAL_STATES` — ровно «план закончился». Остальные причины (`running`, `waiting`,
`feedback_required`, `ready`) не пересекаются с этим множеством. Кадр публикует `_admit_next` после
`deactivate`: держатель в кадре — `None`.

(б) `policy_view.py`, `_state`: вместо `computed.run_state == "complete"` —
`computed.run_state in TERMINAL_STATES`. Строка остаётся на своём месте: после `grant is None`, до
revoke. Над ней — комментарий о порядке, по образцу уже существующего комментария о часах.

Журнал, логи, хранилище, двери, очередь, хаб, JS и тексты не меняются.

### 4.2 Почему `complete/plan_ended`, а не `stalled` с другой причиной

| Вариант | Что меняется | Цена | Итог |
| --- | --- | --- | --- |
| A1. `("complete", "plan_ended")` для любого окончания (выбран) | `policy_view`: одно слово в условии | каждый читатель уже понимает `complete` как «закончен»: Studio без кнопок и без формы гранта, desk без release, без «ждёт вас», без флага; хаб считает проект свободным; окно до тика — `busy/plan_ended`, строка таблицы 4.4.6, принятая для `complete` (R1.2-W); новых пар состояние/причина нет | честно и минимально; различие двух окончаний остаётся в заголовке Studio («Встал»), в `RunTerminal` и в чтении run |
| A2. `("complete", "plan_stalled")` | то же, но причина `plan_stalled` | строка Studio «В плане нет допустимого следующего шага.» без «не оценка качества»; новая пара слота `busy/plan_stalled` на один тик вне таблицы 4.4.6 | возможна, если владелец хочет различать окончания в automation read (вопрос В1) |
| A3. `stalled` + новая причина (`run_ended`) | новое слово в `AUTOMATION_REASONS` и копии EN/RU; кнопки Studio; `grantItems` и `BUCKETS` desk; `HOLDING` хаба; `_STUCK`/`_BUSY` очереди (окно); заголовок Studio «Требует внимания перед продолжением» всё равно обещает продолжение | 6+ файлов (Python и JS), правка текстов, фикстуры desk с `stalled/plan_stalled` | отвергнут |
| A4. Только (а), без (б) | — | проба `r12c_release_only`: слот свободен, но везде `restart_required/explicit_resume_required`: «На контрольной точке · нужно продолжить», «Продолжить» в хабе, run во флаге, resume в Studio | отвергнут (как и предупреждал R1.2b, раздел 4) |
| A5. Только (б), без (а) | — | проба `r12c_view_only`: честные слова, но `busy/plan_ended` навсегда, `SlotBusy` для других | отвергнут |
| A6. Явная дверь «освободить» или pause после terminal | новая API или ослабление `authorization_history` | переписывает правило «после окончания — ничего», задевает журнал | отвергнут (условие «история не переписывается») |

Условие строки (б) — слово плана, вычисленное `schedule`, как и у существующей строки
`complete`. Можно было бы спрашивать `RunTerminal`. Для журналов эпохи terminal это одно и то же:
replay сверяет terminal с планом. В старом журнале без `RunTerminal`, но с планом `stalled`, двери
pause/revoke/resume ещё приняли бы запись. Интерфейс их не предложит, а resume лишь вернул бы run
в слот до следующего тика. Так уже читает Studio (`endingOf`).

### 4.3 Совместимость с R1.2b и свидетельством R1.2

- Порядок `_tick` не меняется. Settler по-прежнему спрашивается первым, и для terminal он отвечает
  `True` (R1.2b, V3). `_next_node` по-прежнему спрашивает слово плана до отказа `unknown`
  (R1.2b, D(i)). Иначе слово `stalled` не дошло бы до `_select_next`.
- Новый тест ставит затвор `HeldTick` там же, где свидетельство R1.2 (`policy.seeds`). Он держит
  первый тик, который нашёл окончание. В этом окне run держит слот и читается `complete/plan_ended`,
  слот `busy/plan_ended`, кадров нет. После отпускания тот же тик освобождает слот и публикует
  ровно один кадр: `held.seen == 1`.
- Свидетельство R1.2 `test_a_human_ending_wakes_the_driver_that_frees_the_slot_and_then_publishes_a_frame`
  на копии: 1 passed ×3.
