# A single local ACP session in a network-disabled boundary

Use the existing protected pin, review isolation, login lease, original login digest,
fresh home, empty read-only work area and cleanup guards from the authenticate witness.
Keep the previous diagnostic invocable without changing its behavior or protected file.
The new operating mode has its own protected script path, receipt and working directory.

Do not pipeline session/new with authenticate. Observe complete bounded RPC replies
from the existing process runner's host-side capture while its final-id feeder is open.
Accept only the original protocol's valid cached-token exchange with no gate, and
only then send the fixed fourth request on the same pipe. Supply the exact absolute cwd
and an empty mcpServers list. Never accept a caller's method, input, path or command.
Require a matching JSON-RPC result with a nonempty sessionId to confirm creation.
Record neither the identifier nor raw replies. The runner closes on response 4 and
terminates the process group on timeout. Do not start a second process.

An online probe would not bound implicit new-session background traffic. Use
internet_client=false for the whole process, OIDC-only generated configuration,
disabled compatibility imports, no external plugins, hooks, memory jobs or incoming
MCP requests to execute. No interactive fallback. This proves only offline session
creation in this fixture. A failed offline lookup does not identify the former online
diagnose failure.
