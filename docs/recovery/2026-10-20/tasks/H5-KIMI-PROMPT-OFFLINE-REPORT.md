# Kimi 0.38.0 — что потребовал штатный prompt до живой подписки

Итог: одного read-only KIMI_CODE_HOME и отдельного TEMP недостаточно для проверенного запуска. При изменяемом состоянии в scratch с тем же защищённым credential CLI продвинулся до другого отказа. Достаточные условия для выполнения задачи, точный минимальный набор путей и обращение к сервису ещё не установлены. TASK 33d4b79, реальный Windows loan K2b.1 (код 8cb677c, в основной ветке 90d5d8e).

**Два наблюдения.** Последовательные отдельные чистые AppContainer с internet_client=false, исходный официальный Windows x64 архив SHA-256 80e4de3f2bd7c33ba10cfe3c2282492b0758fae9887537f4ff79ec2022957004, одинаковые флаги --output-format text --prompt, короткий тестовый prompt и фиктивные access-only входы. Лимит процесса 18 секунд. Каждый контейнер имел отдельный штатный TEMP. Ни одного настоящего аккаунта, полученного модельного ответа или платного вызова.

| Условие | Что измерено |
| --- | --- |
| A. Дом Kimi только для чтения через настоящий grant; TEMP разрешён | Exit 1 за 3,219 с, 188 байт диагностики без усечения. Закрытый классификатор обнаружил «permission denied». В домашнем каталоге только исходные config.toml и credentials. Не установлено, на каком именно пути или системном вызове отказ. |
| B. Отдельный тестовый дом состояния в штатном scratch | Exit 1 за 3,344 с, 349 байт без усечения. Признак «not found», без «permission denied». В этом состоянии появились workspaces.json, device_id и ещё одно имя вне списка наблюдения. Создавать состояние было можно, а config.toml, каталог credentials и сам лист не получили права записи; проверены защищённые DACL и сохранность байтов. Это экспериментальная переменная, не предлагаемое разрешение продукту. |

Обе исходные копии остались неизменными. Перед B первая сборка контрольного DACL отказала во время сравнения описателя обычного файла, до запуска CLI. После корректировки описателя сделан ровно один B-prompt. Локально сохранены только классы событий и имена из закрытого списка: Documents/Codex/work/kimi-native-038/prompt-readonly.json и prompt-state.json. Неизвестное имя не идентифицировалось. Сетевой попытки к модели не измеряли: «not found» может возникать в других фазах. Число или стоимость запросов к сервису по этому тексту вычислить нельзя.

Исходник закреплённого релиза создаёт session до запуска prompt turn, workspace registry описывает атомарное обновление workspaces.json, token identity использует device_id. Это объясняет, почему создание состояния заслуживает проверки; эти участки не называют виновный путь первого отказа и не доказывают обязательность каждого имени. ## Передача для W3 и внешнего k-* relay

1. При следующем согласованном исследовании снять на синтетическом входе последовательность отказов по конкретному файлу и запрашиваемой операции (create, write, replace, rename). Для кандидатов workspaces.json, device_id и session/cache проверять по одному разрешению. Критерий продвижения — новый наблюдаемый этап через независимый локальный свидетель; сетевое «not found» им не является. Измеренные случаи A и B повторять для количества не требуется.
2. Сохранить config и credentials неизменяемыми для контейнера. Для каждого подтверждённого state entry определить место, native identity, предел размера, права и уборку. Сначала проверить поддерживаемую самой версией релокацию состояния или заранее созданные конкретные листья. Атомарная запись через произвольный временный файл и rename рядом с config не становится безопасной выдачей прав на весь родительский каталог: FILE_ADD_FILE в NTFS не фильтрует имя. Если версия не умеет работать с минимальным набором, оставить запуск закрытым до проверенной альтернативы. Не переносить весь login-home, device_id, историю, инструменты или refresh-токен.
3. Привязать внешний новый k-* relay к проверенному исходному региону, digest и сроку с доказанным запасом. Создание только относительно защищённых родительских handles. До первого байта credential сохранить вне выдаваемого дерева несекретную durable опись (ID проекта, запуска и попытки, регион, identity и ожидаемая форма). При передаче проверять фактически удерживаемые объекты и DACL до и после grant, а приёмка должна через настоящий AppContainer отказать в write/rename/execute для credential, permit только проверенные state rights и вернуть проверяемый результат.
4. До возможного внешнего эффекта записывать расход/резерв выбранной попытки и идентификатор запроса. После сбоя восстанавливать receipt и проверять наличие результата/артефакта по тому же action ID. Если исполнение могло начаться, а завершение не доказано, исход остаётся unknown: ни recovery, ни повторное открытие Studio не начинают новый оплачиваемый prompt. При отсутствии запуска возможен только новый осознанный grant по обычной процедуре.
5. Recovery проверяет доверенную опись, identity всего остатка и отсутствие чужих объектов до удаления; снимает только ACE своей попытки. Отметку retire пишет лишь после исчезновения секретных объектов и записей активного grant. Инъекции сбоев до/после записи intent, partial stage, attach, result и удаления должны оставлять внешний sentinel нетронутым; повтор cleanup не повторяет prompt. После отключения провайдера старые журналы всё ещё восстанавливаются.

Последний доказанный шаг — положительный offline ACP и различимый эффект изменяемого состояния в штатном --prompt. Первый несделанный — назвать узкий и проверенный scratch-контракт. Для live затем нужны W3, независимое ревью, подписка владельца, отдельный вход и единственная явно разрешённая проверяемая задача. Ни профиль Kimi, ни права продукта в этой работе не менялись.
