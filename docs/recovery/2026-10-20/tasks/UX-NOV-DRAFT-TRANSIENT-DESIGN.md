# Volatile Desk drafts

The workflow draft persists a workflow definition and serves a different authority. Use a single POST `/command/project/task-draft` on the existing command transport, gated by the regular mutation-session/Origin checks, an explicit matching project identity and active ownership. All four operations carry a scoped project ID. Open allocates an empty row with a **server-generated** 128-bit opaque key and a generated task ID checked against the Desk grammar. Read, save and discard may only address a live row by that key. Read never allocates. An exact typed save uses compare-and-swap on the server revision; an exact repeat of the same revision/data is idempotent. A discard removes the row. A late save cannot recreate it: open never accepts a caller-supplied key, so no tombstone is necessary. Capacity includes every allocated row. Reject new opens at 16 live entries, expire after 30 minutes, reject answers over 32 KiB UTF-8; keep all operations synchronized inside one CommandApi, disappear on restart and do not record answers in files or logs.

Only typed editor fields can round-trip: title, brief, hint, mode flags, source choice, role bindings, manual models, instructions and owner-created material text. A project document carries its ID, reviewed blob and edit operations, never the repository bytes. Preparation results, actor, approval and authorization are not members of this schema. Restore re-reads document content and projects settings into a fresh reducer, never replaying a write.

The current browser history entry holds only the confirmed project ID and opaque key. Saves serialize/coalesce the current form through `door.submit`; reload reads the last ack. An explicit pending/unsaved indication prevents treating a failed, oversized or in-flight change as saved. Starting prepare or closing clears the pointer immediately and discards the capability. Responses from an old editor epoch do not change a new form. Refused or expired reads cannot start a task. The alternative, sending the reducer to an existing workflow endpoint or browser storage, can persist data or authority outside these bounds.
