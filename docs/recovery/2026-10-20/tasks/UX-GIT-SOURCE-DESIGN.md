# Проверка источника материалов

У `GET /command/project/git` уже разные состояния для существующего каталога Git,
который процесс не может прочитать (`unavailable`), и отсутствия репозитория
(`not_git`). Для `unavailable` причина на уровне закреплённого инструмента может
различаться. Использовать только сведения, которые реально возвращает чтение.

На первом экране предложить закрепление Git в Hub либо командой с полным путём,
затем штатный перезапуск проекта и повторное чтение в той же открытой форме.
Проверка закрепления сохраняет ответ на срок жизни процесса, поэтому обычное
обновление страницы не заменяет перезапуск. Не сохранять ответы в браузере на диск.
Стандартный мастер исключает случайный переход к запуску с непрочитанным источником.
Подробный мастер сохраняет возможность выбрать цикл только с решениями человека.
Когда подтверждено отсутствие репозитория, сохранить явный выбор пустой рабочей
папки. Проверить его отдельно. На подготовке не заявлять об отсутствии репозитория
при иной причине.

Сверить новое поведение через обычные кнопки настоящего проекта. Доказать, что из
открытой формы после закрепления получается копия исходного файла и ранее указанный
материал. В случаях с настоящим внешним исполнителем нет необходимости.
