Итог: локально проверено | afd5909 | 851 passed, 0 failed в каждой кодировке | см. отклонения |
следующий шаг — проверить сборку из этого SHA перед отдельной живой приёмкой.

## Что доказано

Контроль прошёл через настоящий планировщик Policy, адаптер Grok, временное хранилище
и локальный двойник CLI. Вход и разрешение были тестовыми. Ниже описан один
ограниченный запуск из документа [grok-g6-session-diagnostic.json](grok-g6-session-diagnostic.json).

1. Шаблон прошёл преобразование Studio в обе стороны. Роль диагноста привязана к Grok.
   В просмотре разрешения отмечен только `diagnose`. Запрос унаследовал
   `grok_diagnostic=session-phase-v1` из замороженного графа и ссылку на разрешение.
2. Планировщик выдал одно действие. Локальный двойник получил `--prompt-file` и
   `--output-format streaming-messages-json`. Его ответ состоял из нескольких
   сообщений ассистента с вызовом инструмента между ними.
3. Новое чтение хранилища вернуло `artifact-causes`, связанный с этим же действием.
   Все 66 байт UTF-8 совпали с ожидаемыми, включая кириллицу, пробелы, табуляцию и
   последний перевод строки. Повтор заключительной фразы из служебного результата,
   внутренние рассуждения и вывод инструмента в артефакт не вошли.
4. На том же адаптере отдельный обычный review сохранил прежний формат и ответ.
   Подмена режима в подготовленном запросе, чужой провайдер и Grok с API-ключом получили отказ.

При штатно завершённой ошибке CLI продукт различает пару одинаковых непустых ID сессии
и явно пустую пару. Повреждённый поток, разные ID и потеря финальной строки не дают
вывода об открытии. При усечении или обнаружении секрета сохраняется соответствующая
безопасная причина. Во всех этих проверках артефакт отсутствовал. Сырые значения
метаданных и токены стенда в журнал не попали.

## Проверки и ревью

- Windows, локально, целевые 18 файлов. UTF-8 — 851 passed за 101 секунду.
  Системная cp1251 — 851 passed за 101 секунду. Прогоны выполнялись параллельно
  в разных временных каталогах. Включены прежние проверки API и обычного JSON Grok.
- Chromium, локальный стенд. Четыре проверки показывают нужный шаг перед разрешением
  в Desk и Studio на русском и английском. Повтор на итоговом дереве — 4 passed.
  Отдельные проверки проекций удерживают пометку при недоступном чтении плана в Desk.
- Проверено по коду от `PolicyService.preview` до обеих форм. Studio сверяет пометку
  с определением графа и его digest. Для старых заявок форма ответа осталась прежней.
- До реализации семь новых сквозных сценариев были красными. Просмотр без
  серверного списка отмеченных шагов падал и на реальном `PolicyService`.
  Проверки ширины строк и точного набора полей API включены в итоговые числа.

## Чужие правки и отклонения

Исходная точка — 6fdb94f. Задание и дизайн зафиксированы в f7d5a2f.
Исполнители работали в раздельно назначенных файлах. Все изменения в коммите относятся
к H5-GROK-STREAM, три новых файла Python включены в CAPPED.

Первый расширенный прогон дал 697 passed и 1 failed в каждой кодировке. Тест
обнаружил прежний закрытый список полей review. Обновлены канонический пример API
и точные списки ожидаемых полей. Ключ остался необязательным. Проверки, которые
не смогли создать каталог pytest в ограниченной среде, прошли с отдельными
временными путями. После добавления отчёта проверка окончаний строк дала 9 passed.

Первый отдельный запуск планировщика из скрипта пропустил обязательную для Windows
настройку запуска локальных двойников из `tests/conftest.py`. Успешной задачи в нём
не было. После подключения штатного механизма тестов в новом временном проекте
получен положительный контроль с 66 байтами. Этот опыт использует тестовую границу.
