# Локальная приёмка роли Kimi с инструментом Read

**Итог.** Зафиксированный Kimi Code 0.38.0 открывает локальную ACP-сессию с конфигурацией одного инструмента `Read`. У этой же версии есть штатная проверка при вызове инструмента, которая разрешает `Read` и отклоняет `Bash`, `Write`, `Edit`, `Agent` и `select_tools`. Вход на подписке, чтение файла моделью и применение политики к её реальному вызову остаются отдельными критериями. Коммит проверки — `39dbadf`.

## Измерено

В фиктивный config.toml временного состояния записана штатная секция этой версии:

```toml
[tools]
enabled = ["Read"]
```

- Настоящий Kimi в AppContainer с запрещённой сетью получил ровно три ACP-сообщения — `initialize`, `authenticate`, `session/new`. Успешный ответ последнего содержит ID реально созданной на диске сессии. Состав файлов входа и их байты проверены после выполнения. Испытание с тем же config.toml и отсутствующим путём к шеллу вернуло `Git Bash was not found`. Для старта роли по-прежнему нужен закреплённый файл шелла. При создании этой сессии исполнение команды Bash не потребовалось.
- ACP на этих трёх сообщениях не возвращает перечень активных инструментов. Поэтому отрицательная проверка выполнена отдельно. Тест проверяет SHA-256 официального EXE, извлекает из него функции политики и класс, регистрирующий обработчик проверки инструментов. Локальный Node запускает эти конкретные функции с фиктивными зависимостями сервиса и тем же `[tools]`. Фактический обработчик пропускает `Read`, а для каждого из пяти запрещённых имён возвращает отказ. При пустых глобальных настройках разрешены все шесть имён. Удаление списка, разрешение Bash или подстановка пустого обработчика ломают тест.
- Этот результат относится к точной версии, конфигурации и перечисленным встроенным инструментам. Какой запрос получил бы модельный API, проверка не измеряет. Открытие одной ACP-сессии само по себе не доказывает применение списка к вызову модели. Встроенный профиль `explore` в данном EXE включает Bash. Верхнеуровневый параметр `--agent-file` обработчик подкоманды `acp` в параметры сервера не передаёт.
- На Windows в каждой кодировке 248 проверок прошли и одна пропущена. Пропуск относится к выделенному ранее тесту исполнения Bash, остающемуся красным при явном включении. Все новые проверки прошли. Для повторения задаются `CONDUCT_TEST_KIMI_ARCHIVE` и `CONDUCT_TEST_KIMI_SHELL` как в KIMI-OFFLINE-KIT-REPORT. Для теста guard также нужен локальный Node с поддержкой `--permission` (на машине 24.22.1).

```powershell
python -m pytest -q tests/test_kimi_session_state_native.py -k 'read-role'
python -m pytest -q tests/test_kimi_read_role_policy.py
```

## Следующий критерий

При подключении роли продукту потребуется сформировать точную конфигурацию временного состояния, зафиксировать её digest и путь к проверенным байтам шелла в разрешении. Первая задача этой роли — диагностика одного учебного файла с независимым свидетелем чтения и проверкой фактического отказа запрещённого действия. Полномочия приложения на запись в папке задачи для такой роли не нужны. До выполнения этих критериев Kimi остаётся локально проверенным кандидатом.
