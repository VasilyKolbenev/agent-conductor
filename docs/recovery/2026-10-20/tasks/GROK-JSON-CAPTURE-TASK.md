# Grok: отдельные бюджеты JSON-конверта и результата

Решение владельца 10.11.2026: локально воспроизвести переполнение обычного
Grok JSON и исправить причину по рабочему стандарту. Без новых вызовов моделей,
смены версии CLI, слепого увеличения лимита или повторения failed Diagnose.
Нижний порог остатка Codex — 30%; исходно 41%. База `52e7244`, чистый status.

Симптом: `counter-src-ff2fbce-r1`, Diagnose, Grok 1.0.13, stdout overflow
после примерно 228 с. Содержимое утраченного stdout не восстановлено;
не утверждать, что в том запуске переполнилось конкретно поле thought.

Нужный результат: обычный review с коротким полным text и большим легитимным
thought успешно публикует ровно text. JSON escaping не уменьшает допустимый
UTF-8 размер результата. Большой итоговый документ, malformed/truncated JSON,
ошибка CLI, вывод секрета и неубранный дом по-прежнему запрещают публикацию.
Новые wire bounds входят в provider digest, чтобы прежнее разрешение не
стало разрешением изменённого транспорта. Другие harness не меняются.

Сначала регрессия через настоящий публичный runtime с локальным CLI-двойником;
затем код и обе оси независимого ревью. Mutants отличают потерю ответа, обход
предела результата, секрета и wire budget. Целевые тесты — UTF-8 и CP1251.
Итоговый код и тесты коммитит ведущий; отчёт и handoff — отдельным коммитом.

Длительные задачи — основной сценарий продукта. Пять действий и 600 секунд
текущего учебного разрешения не становятся универсальными пределами продукта:
действие Далио содержит собственный агентный цикл harness. В этой задаче не
меняем время, число попыток, права, готовый граф или артефактный контракт.
Дальнейший живой запуск требует нового предпросмотра и подтверждения владельца.
