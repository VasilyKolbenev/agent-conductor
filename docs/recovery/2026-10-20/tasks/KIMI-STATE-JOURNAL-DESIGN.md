# Отдельное состояние попытки Kimi

Вариант A — создавать home внутри общего TEMP с правами обычных дочерних объектов.
Его вложенные каталоги и срок жизни не зафиксированы до запуска; после обрыва
есть только identity общего TEMP. Вариант B — именованный набор непосредственно
в существующей описи Windows ACL. Выбран B.

Только внутренний вызов, при mode=review, internet_client=False и staged home
с первоначальной identity. Каталоги известны кодом (корень, sessions, logs,
credentials), не получены из плана. До запуска сохраняются identity и исходные ACL
в той же записи с профилем, nonce проекта и boot witness. Корень получает чтение
и создание обычного файла; именованные sessions/logs допускают изменение данных;
credentials только чтение. Реальные токены в это дерево не записываются. Код не
назначает KIMI_SHELL_PATH из окружения, не предоставляет новый provider capability.

При штатном выходе служебные каталоги проверяются по identity и удерживаются,
портал или hardlink останавливает очистку до удаления потомков. Фиксируется
намерение убрать дерево перед удалением. Восстановление допускается при доказанном
restart согласно существующему контракту, удаляет только записанные корни и их
обычные потомки; повтор не запускает CLI. Старый вид описи не меняется.
Проверка размера и происхождения подписываемого shell и его зависимостей, а также
проверенная запись вложенного access-only credential будут отдельными перед
сетевой работой: защищённой установки Kimi/shell сейчас нет.
