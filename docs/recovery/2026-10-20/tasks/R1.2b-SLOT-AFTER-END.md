## 0. Итог

Дефект продукта подтверждён. Найдено четыре триггера:

- A — потерянная папка задачи у result gate;
- B — потеря папки внутри окна;
- C — новый триггер: seed не устроен с самого начала, а первый gate отклонён; удалять папку не
  нужно;
- D — гипотеза о `unknown` подтвердилась.

Во всех четырёх случаях план в журнале `complete`, `RunTerminal` записан, а run навсегда держит
слот. Освободить его некому.

Корень такой. Завершённый run освобождается в одном месте — в `_select_next`
(`policy_driver.py:258-260`). Это место стоит в конце пути допуска нового действия, и перед ним
есть две проверки, которые могут отказывать вечно:

1. Settler seed (`_tick`, `:205-206`). Если он отвечает `False`, тик выходит.
2. Отказ из-за `unknown` (`_next_node`, `:306-307`). Он спрашивается раньше, чем слово плана
   (`:308-310`), бросает `ContractError`, а `_work` гасит исключение в `admission_refused`.

Выбранное исправление — две маленькие правки, порядок `_tick` не меняется:

1. **`SeedSettler.settle` отвечает `True` для run, в журнале которого стоит `RunTerminal`.**
   Проверка идёт первой после чтения журнала, через единый предикат `standing_terminal`. Тот же
   предикат хранилище использует, чтобы отказать в любой новой записи (`RunClosed`). Значит, такому
   run seed ничем не нужен: ни одно действие в нём уже не начнётся.
2. **`_next_node` спрашивает `run_state` до `failure_sources`.** На открытом плане `unknown`
   по-прежнему запрещает любое предложение. Завершённый план отвечает своим словом, и
   `_select_next` освобождает слот.

Settler остаётся первым, что спрашивает тик. Поэтому свидетельство R1.2 (затвор `HeldTick` в
`policy.seeds`) остаётся совместимым; это проверено. Вариант «освобождать до seed» это
свидетельство ломает.

Проверка в памяти, без изменения репозитория:

- новые тесты без исправления: 4 failed, 2 passed; с исправлением: 6 passed, три прогона подряд;
- каждая половина исправления нужна: каждый мутант краснит свои тесты;
- соседние тесты с исправлением: 365 passed / 2 skipped и 420 passed / 8 skipped, включая
  свидетельство R1.2.

Попутно найден отдельный дефект **R1.2c**. Run, чей план закончился словом `stalled`
(`RunTerminal(state="stalled")`), тоже держит слот навсегда, а pause и revoke дают 422. Это не
R1.2b: нужно решение о контракте (раздел 4).

### 1.2 Механизм

`PolicyDriver._tick` (`policy_driver.py:199-207`):

```python
self._settle_inflight()
with self._admission:
    ...  # hold flag
    if self._seed_owed(run_id):      # settler False -> reason seed_blocked, return
        return
    self._admit_next(run_id, grant_id)   # -> _select_next -> _next_node
```

`_select_next` (`:245-264`) вызывает `deactivate` только для `reason == "complete"` (`:258-260`).
`_next_node` (`:299-319`) сначала вызывает `failure_sources` (`:306-307`), который бросает
исключение на любом `unknown` под текущим грантом, и только потом смотрит `run_state`
(`:308-310`).

Почему run, завершённый по плану, больше никто не освободит:

- pause и revoke отказывают: `validate_authorization_history` не принимает записей после
  `RunTerminal` (`authorization_history.py:164-165`), дверь отвечает 422;
- automation показывает `complete/plan_ended`, потому что проверка `complete` в `_state` стоит
  первой (`policy_view.py:47-48`); настоящая причина (`seed_blocked`, `admission_refused`) не
  видна;
- слот читается как `busy/plan_ended`: `complete` входит в `_BUSY` (`queue_reading.py:43`), а desk
  предлагает release только для `stuck` (`desk-queue-model.js`, `releaseOffer`);
- очередь стоит: насос работает только при `active is None` (`policy_driver.py:156-158`);
- прямой authorize другого run получает `SlotBusy` (`:105-107`), acceptance считает run активным
  (`accept_context.py:78-99`);
- выходов два: перезапуск процесса или, в сценарии с удалённой папкой, её возврат.

Это нарушает контракт `tests/test_policy_driver_queue.py:7-8`: «After a run's plan completes the
driver deactivates it and publishes a frame».

## 2. Почему seed проверяется на каждом тике и какие гарантии нельзя сломать

### 2.1 История

- `c15c81a` (2026-09-30), «feat(command): settle task seeds before driver proposals», добавил
  `_seed_owed` в `_tick` перед `_admit_next`, `SeedSettler` и `tests/test_seed_driver.py`.
  `git log -S "_seed_owed"` находит только этот коммит и документ `57fe629`.
- `7dc500d` (2026-09-30), «fix(seed): contain staging moves and preserve task scope», добавил
  `_hold_scope` в settler и тест «driver» на чужой scope.

Docstring класса `SeedSettler` (`seed_routes.py:238`) и модуля `test_seed_driver.py` говорят «до
первого действия» — это формулировка spec 9.1.4. Реализация строже: settler спрашивается на каждом
тике, до чтения плана.

### 2.2 Почему так

- Состояние seed нигде не хранится. `seed_state` каждый раз читает его с диска
  (`seed_record.py:16-17`, `:401-414`), флага «уже засеян» у драйвера нет.
- Settle нужно повторять, пока оно не удастся. Корень может быть занят (`WorkspaceBusy`), тогда
  перенос пройдёт на следующем тике. Запрос view-сервера выполняется, когда это становится
  возможным. Если папка не пуста, run ждёт, пока её не опустошат.
- Порядок блокировок: settle спрашивается до транзакции хранилища (docstring `_seed_owed`:
  перенос ждёт очереди корня, а dispatch держит очередь и потом берёт хранилище).
- После засева проверка дешёвая: чтение журнала, записи seed и два `lstat`.

### 2.3 Гарантии, которые нельзя сломать

| Гарантия | Чем закреплена |
| --- | --- |
| G1. Пока seed не на месте, ничего не предлагается; run держит слот как `stalled/seed_blocked` | `test_seed_driver.py::test_driver_proposes_nothing_and_reports_seed_blocked_when_the_move_fails` |
| G2. Staged seed переносится под очередью корня до первого предложения | `::test_driver_moves_a_staged_seed_before_the_first_proposal` |
| G3. Запрос view-сервера выполняется из HEAD в момент выполнения; при отказе — `seed_blocked` | `::test_driver_performs_a_requested_seed_from_head_...`, `::test_a_failed_requested_seed_reports_...` |
| G4. Непустая папка задачи держит run, пока её не опустошат | `::test_a_seed_whose_task_folder_filled_up_blocks_the_run_until_it_empties` |
| G5. Seed чужого scope держит run, чужие байты не трогаются | `::test_a_saved_seed_cannot_substitute_another_scope_for_the_tasks_binding[driver-*]` |
| G6. Потерянный seed держит run | settler: `::test_a_lost_seed_holds_the_run_and_the_desk_learns_it_by_asking`. На драйвере посреди run до сих пор не закреплено — новый контроль E |
| G7. Ничего не должны: run без задачи, задача без seed, run без dispatch | `::test_a_run_that_performs_no_dispatch_...`, `::test_a_task_that_was_never_seeded_...`, `::test_nothing_is_owed_...`, `::test_a_review_only_run_...`, `::test_a_run_of_no_task_...` |
| G8. На открытом плане pause освобождает слот `seed_blocked` | скептик 1, `test_pause_is_accepted_while_seed_blocked_and_the_plan_is_open` |

### 2.4 Почему исключение для завершённого run ни одну гарантию не ослабляет

- После `RunTerminal` хранилище отказывает в **любой** записи, кроме самого terminal:
  `_hold_run_accepts_records` → `RunClosed` (`run_store.py:328-356`). Ни proposal, ни request в
  завершённом run уже не появятся, а `_next_node` на плане не в `open` узел не выбирает. Условие
  seed для такого run ничего не защищает и только запирает освобождение слота.
- `standing_terminal` (`graph_causality.py:198-212`) — «ONE predicate» завершённости. Его же
  используют хранилище (`RunClosed`) и история авторизации (отказ pause/revoke). Исключение
  срабатывает ровно на тех run, которые больше никто не может освободить.
- G1–G8 касаются открытого плана, а `RunTerminal` пишется в той же транзакции, что и решение или
  результат, который план завершил. Пока план открыт, settler работает как раньше.

## 3. Второй триггер (`unknown` + `complete`): подтверждён

Воспроизведение: `test_r12b_triggers.py::test_trigger2_unknown_then_gate_correction_completes_and_keeps_the_slot`
(лог `test_r12b_triggers.log`). План: `plan` (review) → `approve` (human, дорога `approved`) →
`analyst` (review, исход `unknown`) → `result` (human).

```
[after unknown]          plan=open     reason='admission_refused' automation=('stalled','admission_refused') slot=stuck
[correction] -> 201      (approve-1 исправлен на reject, supersedes)
[3.5 s after correction] plan=complete terminal=['complete'] holder='run' reason='admission_refused'
                         automation=('complete','plan_ended') slot=busy/plan_ended
[pause] -> 422  [revoke] -> 422
[mechanism] _next_node raises on the complete plan before it reads run_state
```

Условия:

1. Есть результат `unknown` под текущим грантом.
2. Шаг с ним остаётся неустроенным, а при `attempt_bound=None` — ещё и runnable. План остаётся
   открытым, человек может действовать.
3. План завершается человеческими записями, без нового гранта. Новый грант после `RunTerminal`
   невозможен, а `failure_sources` смотрит только запросы текущего гранта.

Самый прямой путь — исправить решение gate, который стоит перед шагом с `unknown`.

Исправление — переставить вопрос о слове плана раньше `failure_sources` в `_next_node`. На
открытом плане порядок «running → unknown-отказ → кандидаты» не меняется. Это закрепляет новый
контроль F.

## 4. Попутная находка R1.2c (вне этого задания)

`_select_next` освобождает слот только на `complete`. Если план закончился словом `stalled`
(`RunTerminal(state="stalled")`, например `unknown` на шаге с `attempt_bound=1` или halt), run
держит слот навсегда:

- слот `stuck`, и desk предлагает release;
- release делает pause или revoke, и они дают 422 по той же причине, `RunTerminal`.

Доказательство: `test_r12b_triggers.py::test_sibling_stalled_terminal_keeps_the_slot_and_refuses_control`.
Без исправления видно `stalled/admission_refused`, с исправлением R1.2b — `stalled/stalled`
(`sibling_with_fix.log`); меняется только `reason_code`.

R1.2b это не чинит, и чинить его здесь нельзя. Если освобождать слот на любом `run_state != "open"`,
`automation_view` для такого run покажет `restart_required/explicit_resume_required`, то есть
пообещает resume, который будет отвергнут. Нужно решение Codex или владельца о строке таблицы 4.4.6
и о `policy_view`. Это отдельная задача.

    status, payload, _ = _request(run.subject, "GET", "/command/queue")
    assert status == 200, payload
    return payload["slot"]


def frames_of(run):
    """The frames the driver publishes from now on, each with the holder at that moment."""
    policy = run.subject.command_api._policy
    frames, publish = [], policy.notify
    policy.notify = lambda run_id: (frames.append((run_id, run.holder())), publish(run_id))
    return frames


def lose_the_seed(run):
    """The task's folder goes away (a person, an editor, git); a tick the test wakes sees it."""
    shutil.rmtree(folder_of(run))
    run.subject.policy_driver.wake("run")
    assert run.until("the seed block", lambda: run.reason() == "seed_blocked") == "seed_blocked"


def freed(run, frames):
    """The ending's own tick freed the slot and then published exactly one frame."""
    run.until("the slot freed", lambda: run.holder() is None and bool(frames))
    assert frames == [("run", None)]
    assert run.automation() == ("complete", "plan_ended") and slot_of(run) == FREE


def gated(*steps):
    """A chain whose roads out of a human step open on its approval."""
    flow = chain(*steps)
    for link, source in zip(flow["links"], steps):
        if source["type"] == "human":
            link["when"] = "approved"
    return flow


class HeldTick:
    """Stands where the seed settler stands and holds the one tick the test woke, before it asks."""

    def __init__(self, seeds):
        self.seeds, self.armed, self.entered, self.go = seeds, Event(), Event(), Event()

    def settle(self, run_id):
        if self.armed.is_set():
            self.armed.clear()
            self.entered.set()
            assert self.go.wait(10), "the test never let the tick go"
        return self.seeds.settle(run_id)


def test_a_seed_lost_at_the_result_gate_does_not_keep_the_rejected_run_in_the_slot(cycle):
    run = cycle(LINEAR)
    assert empty_seed(run)[0] == 201
    run.start()
    at_result_gate(run)
    lose_the_seed(run)
    assert slot_of(run) == {"state": "stuck", "run_id": "run", "reason_code": "seed_blocked"}
    frames = frames_of(run)
    status, body = run.decide("result", "reject-result", action="reject")
    assert status == 201, body
    assert run.plan_state() == "complete" and run.terminal()
    freed(run, frames)


def test_a_seed_lost_between_the_decision_and_the_tick_it_wakes_does_not_keep_the_slot(cycle):
    run = cycle(LINEAR)
    assert empty_seed(run)[0] == 201
    run.start()
    at_result_gate(run)
    policy = run.subject.command_api._policy
    held = policy.seeds = HeldTick(policy.seeds)
    frames = frames_of(run)
    held.armed.set()
    try:
        run.subject.policy_driver.wake("run")
        assert held.entered.wait(15), "the woken tick never reached the settler"
        status, body = run.decide("result", "reject-result", action="reject")
        assert status == 201, body
        shutil.rmtree(folder_of(run))
        assert run.holder() == "run" and frames == []
    finally:  # a failure above must not leave the driver's thread held past the teardown
        held.armed.clear()
        held.go.set()
    freed(run, frames)


def test_a_seed_never_settled_does_not_keep_a_run_its_first_gate_ended(cycle):
    run = cycle(gated(step("approve", "human"), DOER, step("result", "human")))
    root, folder = run.store.project_root, folder_of(run)
    with gate_held(root):
        assert empty_seed(run)[0] == 202
    folder.mkdir(parents=True)
    (folder / "late.txt").write_bytes(b"written by something else")
    run.start()
    assert run.until("the seed block") == "seed_blocked"
    frames = frames_of(run)
    status, body = run.decide("approve", "reject-approve", action="reject")
    assert status == 201, body
    freed(run, frames)
    assert run.steps() == [] and (folder / "late.txt").read_bytes() == b"written by something else"
    assert seed_state(root, read_seed(root, BENCH_TASK)) == "staged", "an ended run moves nothing"


def test_an_unknown_result_does_not_keep_a_run_a_gate_correction_ended(cycle):
    run = cycle(gated(review("plan"), step("approve", "human"), review("analyst"),
                      step("result", "human")), outcomes={"analyst": ["unknown"]})
    run.start()
    run.until("the approval gate", lambda: run.reason() == "waiting")
    assert run.decide("approve", "approve-1")[0] == 201
    reason = run.until("the unknown result", lambda: run.outcomes("analyst") == ["unknown"])
    assert reason == "admission_refused" and run.plan_state() == "open"
    frames = frames_of(run)
    status, body = run.decide("approve", "reject-1", action="reject", supersedes="approve-1")
    assert status == 201, body
    assert run.plan_state() == "complete" and run.terminal()
    freed(run, frames)
    assert run.steps() == ["plan", "analyst"]


def test_a_seed_lost_on_an_open_plan_still_holds_the_next_dispatch(cycle):
    """The settler is asked on every tick: a folder lost after the first action holds the next."""
    run = cycle(LINEAR)
    assert empty_seed(run)[0] == 201
    real = run.doer.execute

    def execute(prepared):
        if prepared.request.node_id == "analyst":
            shutil.rmtree(folder_of(run))
        return real(prepared)
    run.doer.execute = execute
    run.start()
    assert run.until("the seed block") == "seed_blocked"
    run.subject.policy_driver._tick("run", "grant")
    assert [row.node_id for row in run.records("action_proposal")] == ["analyst"]
    assert run.plan_state() == "open" and not run.terminal()
    assert run.holder() == "run" and run.automation() == ("stalled", "seed_blocked")
    folder_of(run).mkdir(parents=True)
    run.subject.policy_driver.wake("run")
    at_result_gate(run)
    assert run.steps() == ["analyst", "do"], "the folder back, the next tick could"


def test_an_unknown_result_on_an_open_plan_still_refuses_every_proposal(cycle):
    run = cycle(chain(review("analyst"), DOER, step("result", "human")),
                outcomes={"analyst": ["unknown"]})
    run.start()
    reason = run.until("the unknown result", lambda: run.outcomes("analyst") == ["unknown"])
    assert reason == "admission_refused" and run.plan_state() == "open"
    with pytest.raises(ContractError, match="unknown action requires human reconciliation"):
        run.subject.policy_driver._tick("run", "grant")
    assert [row.node_id for row in run.records("action_proposal")] == ["analyst"]
    assert not run.terminal()
    assert run.holder() == "run" and run.automation() == ("stalled", "admission_refused")

Что закрепляет каждый тест:

| Тест | Закрепляет |
| --- | --- |
| A | сценарий А скептика 1: seed потерян у result gate, затем reject |
| B | сценарий Б: затвор держит тик, который тест разбудил до решения; решение и удаление папки происходят, пока тик держится; после отпускания тот же тик освобождает слот |
| C | seed не устроен с начала, первый gate отклонён; ничего не перенесено |
| D | `unknown` и коррекция gate |
| E | контроль: seed, потерянный на открытом плане, не даёт стартовать следующему dispatch, `_tick` вызывается напрямую; после возврата папки следующий тик идёт дальше |
| F | контроль: `unknown` на открытом плане по-прежнему отказывает (`_tick` бросает) и ничего не предлагает |

Во всех тестах `TICK_SECONDS=60`, поэтому слот освобождает только тик, разбуженный решением.
Фиксированных пауз нет: только ожидание факта через `FlowCycle.until`.

## 9. Не проверено

- macOS, Linux и Python 3.11: только Windows и 3.12.14. Тесты не зависят от платформы
  (`shutil.rmtree`, `root_turn`, без symlink), но подтверждение остаётся за CI.
- Desk в браузере: кадры `busy/plan_ended` → `free` после исправления глазами не проверялись.
- Исключение, вылетевшее из settle на **открытом** плане (не из кортежа `except`), по-прежнему
  даёт `admission_refused`. Run держит слот, но pause работает. Не меняется.
- Что сделал бы dispatch в отсутствующей папке, я не исследовал. Гарантия «не стартовать на
  потерянном seed» сохранена, а не заменена.
- Старые журналы, где план `complete`, а `RunTerminal` нет: V3 их не покрывает. Правка D(i)
  покрывает. Без `RunTerminal` pause и revoke разрешены, человек может освободить слот сам.
