# Проверка набора Kimi для Windows

**Итог.** На этой машине настоящий Kimi Code 0.38.0 открывает локальную ACP-сессию в изоляции с фиктивным входом. Исполнение команды через Git Bash остаётся заблокированным на уровне MSYS. Сборщик и свидетель находятся в `36e625d`. В продукте Kimi dispatch по-прежнему закрыт.

## Состав и способ проверки

`scripts/kimi_windows_kit.py` создаёт новый каталог для проверки либо проверяет существующий, печатает JSON-опись и возвращает код 2 при отказе. Для каждого файла сверяются размер и SHA-256. Каталоги допускают наследование прав, файлы должны быть обычными, с одной ссылкой. Проверка перед запуском держит открытыми оба каталога и все три файла. Раскладка закрыта для лишних файлов, в том числе DLL с новым именем. Этот инструмент рассчитан на доверенную временную папку владельца.

| Артефакт | Байт | SHA-256 |
| --- | ---: | --- |
| Исходный Windows ZIP Kimi 0.38.0 | 56242443 | `80e4de3f2bd7c33ba10cfe3c2282492b0758fae9887537f4ff79ec2022957004` |
| `kimi.exe` | 150901248 | `b7e658d06176284384d1e9eb627d11e5a26627b3964bf8787f197915d1484b1e` |
| `shell/sh.exe` | 2465552 | `e769a06bace817d96a4448f985ea2b48526c6cab042417229665f6b446e038dd` |
| `shell/msys-2.0.dll` | 3388816 | `a4f38fafec60affc988a0ccc9a51255b86469326ead9730ec7b1af87ce95579e` |

ZIP ранее сверили при K1a. Образец Git for Windows взят из уже установленного локального комплекта. Его происхождение этим срезом подтверждено до пути установки и конкретных байтов. Независимая сверка с издателем и условия распространения этого комплекта остаются частью будущей установки. Пара `sh.exe` и `msys-2.0.dll` покрывает локальные зависимости в таблице статических импортов этих двух образцов. Полнота окружения Git для произвольных команд не установлена.

Следующие команды выполняются в PowerShell из рабочего дерева с установленным в venv пакетом `conductor`. В новой установке пути к фиксированным исходникам задаются явно. `$Copy` должен быть новым дочерним каталогом в доступной владельцу папке. Сборщик отклоняет защищённый корень December Command и существующий каталог назначения.

```powershell
$Py = (Get-Command python -CommandType Application).Source
$Archive = Join-Path $env:USERPROFILE 'Documents\Codex\work\kimi-native-038\kimi-code-win32-x64.zip'
$GitBin = Join-Path $env:USERPROFILE '.cache\codex-runtimes\codex-primary-runtime\dependencies\native\git\usr\bin'
$Copy = Join-Path $env:TEMP ("kimi-kit-" + [guid]::NewGuid().ToString('N'))
& $Py -I -B scripts/kimi_windows_kit.py stage $Archive $GitBin $Copy
if ($LASTEXITCODE -ne 0) { throw 'Kimi kit stage failed' }
& $Py -I -B scripts/kimi_windows_kit.py verify $Copy
if ($LASTEXITCODE -ne 0) { throw 'Kimi kit verify failed' }
```

Нативные тесты сами собирают временную копию, повторно проверяют её после выдачи прав и указывают Kimi точный `KIMI_SHELL_PATH`. Стандартные проверки не требуют скачиваний, профиля подписки, запросов модели или сетевой возможности AppContainer.

```powershell
$env:CONDUCT_TEST_KIMI_ARCHIVE = $Archive
$env:CONDUCT_TEST_KIMI_SHELL = Join-Path $GitBin 'sh.exe'
& $Py -m pytest -q tests/test_kimi_session_state_native.py -k native_session_before_a_prompt
```

Отдельный тест проверяет, может ли реальный шелл хотя бы напечатать свою версию с теми же ограничениями. Сегодня этот тест возвращает ошибку; он намеренно остаётся доступным как критерий будущего исправления.

```powershell
$env:CONDUCT_TEST_KIMI_SHELL_EXEC = '1'
try {
    & $Py -m pytest -q tests/test_kimi_session_state_native.py -k shell_can_report_its_version
} finally {
    Remove-Item Env:CONDUCT_TEST_KIMI_SHELL_EXEC
}
```

## Наблюдения

- В UTF-8 и штатной кодировке Windows проверки набора, длины строк и окончаний файлов дали по 260 passing. Изолированное изменение ровно одного байта по очереди в каждом из трёх настоящих файлов возвращало отказ по SHA-256. После восстановления всех трёх полная проверка прошла. Замена одного из проверяемых файлов во время владения дескриптором отвергнута Windows.
- Начальный нативный запуск выявил, что `tempfile.mkdtemp()` создаёт каталог с защищённой DACL. Наследуемая выдача прав со стороны install-каталога обрывалась. Новый сборщик создаёт временный каталог с наследованием и проверяет границу наследования для каждого элемента. На исходной версии проверка отсутствовала. Мутанты, пропускавшие проверку SHA, состава каталога шелла или наследования, дали соответственно 3, 2 и 1 красных теста.
- По три нативных ACP-проверки прошли в каждой кодировке. На синтетических входных файлах подтверждены ответы на `initialize`, `authenticate` и `session/new`, создание одноимённой сессии во временном состоянии, а также чистая уборка. Контроли с read-only home и отсутствующим шеллом воспроизводят соответствующие отказы. Чтение учебных файлов по запросу пользователя, выполнение задания моделью и реальный подписочный вход здесь не испытывались.
- Реальный `sh.exe --noprofile --norc --version` завершился с `0xC0000142` до печати версии. MSYS сообщает, что `NtCreateDirectoryObject` для `\BaseNamedObjects\msys-…` получил `0xC0000022` (access denied). В выделенном тесте это воспроизводится как `MSYS named-object access denied=True`. Проверка уборки попытки и профиля прошла. Устанавливать расширенные разрешения ради запуска не требуется для воспроизведения.
- Перед работой и после неё перечитаны фактические байты всех 63 файлов защищённого harnesses-каталога. Они совпадают с эталоном v3. SHA-256 самого v3 `08c6de01b1f60b603b2ad892cbc28a3d95725b4bdd37e0e1c293450020003e85`, отпечаток канонической таблицы размеров и хешей `2ee9d98a6a45cc2cd3ee1fa5b9523d3f9d60f23102ab9ed0230cd2e9830e3b9e`. Отдельно сверены байты файлов описи и защищённого скрипта preflight.

## Перед подключением

Сначала нужен документированный, работающий в текущей Windows-изоляции способ запустить поддерживаемый Kimi шелл. Следующий локальный критерий — зелёный тест печати версии и безвредная команда в папке задачи. Если подходящего способа нет, область возможностей Kimi надо согласовать явно и подтвердить отдельно, что предполагаемая задача может выполняться в этих пределах.

Перед будущей выдачей прав необходимо оформить версионированный защищённый кандидат, проверить происхождение и всю опись, закрыть запись посторонних и привязать выбор точного пути к полномочиям запуска. Текущие 63 файла и опись v3 должны остаться пригодными для уже работающих Codex и Grok. После этих шагов остаётся живая приёмка на подписке владельца.
