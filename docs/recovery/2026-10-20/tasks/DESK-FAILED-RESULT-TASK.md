# Desk: объяснить пустой результат Do

В учебном запуске `dalio-codex-grok-normal` от 7 ноября процесс Do завершился
с кодом 0, три файла сохранили прежние хеши, и проверка вернула
`verification_failed`. Открывая задачу на Desk, человек должен увидеть причину
рядом с её названием до просмотра трассы или журнала.

Использовать прочитанные записи выбранного запуска. Причину «исполнитель не
изменил файлы» показывать только для соответствующей квитанции неудачной
проверки, связанной с шагом записи. Старый отказ после следующей попытки,
другая причина, отсутствующий или завершившийся успехом запуск не должны
получать это объяснение. Запись учебного проекта и реальные провайдеры
для этой проверки не нужны.

Проверка через Chromium на RU/EN, включая ширину 375 px. Разрешённые файлы:
`desk-scene.js`, `desk-copy.js`, `browser_tests/test_desk_failed_result.py` и
отчёт этой задачи. Сначала получить воспроизводимое падение браузерного теста.

На визуальной проверке тот же терминальный запуск показал в пульте принятую
квитанцию под заголовком «Нужно решение». Дополнительный критерий техлида:
в остановленном запуске видимая карточка записанного решения называется
«Решение записано» / “Decision recorded”. Техлид правит отрисовку карточки,
проверка входит в этот же RU/EN сценарий.
