# Штатные провайдеры и подключаемые утилиты

TASK `3aa6433`. Владелец выбрал оба режима. Встроенные Claude Code, Codex, Grok и Kimi Code
сохраняют собственные адаптеры и инструкции входа. На экране участников дать одну кнопку
добавления. Посетитель видит штатные варианты и может выбрать произвольную свою утилиту.
Для штатного провайдера Studio показывает конкретный следующий шаг локальной настройки:
доверенный путь и подписочный вход задаются через существующий `conduct providers`.
После настройки и перезапуска состав перечитывается.

Для произвольной утилиты предусмотреть два способа. В ручном режиме оператор сохраняет
подключение, копирует введённую задачу в родную CLI и записывает её ответ. В режиме
`stdio-v1` он отдельно запускает локальный мост для совместимого исполняемого файла.
После явной отправки из Studio мост сам доставляет задачу и возвращает ответ.
Подпиской и входом сторонней утилиты управляет её владелец. Веб-страница не пишет путь
к исполняемому файлу, не запускает установленный бинарник и не получает секрет.

Рассмотрены автопоиск/старт любой программы по браузерному пути и обмен с ранее
запущенным владельцем мостом. Выбран второй. На wire используется отдельный ограниченный
запрос `GET/POST /command/project/utilities`, с обычными проверками origin/CSRF и проектной
принадлежности. В view допускается только чтение. Интерфейс предлагает передать явно
выбранный текст. В профиле проекта сохраняется id/имя/режим, а не командная строка.
Внешний обмен не служит свидетельством независимой проверки, не выдаёт грант Далио.

Замечания к границам:
1.1. Для ручного обмена закреплены id, исходный текст и итог. В автоматическом обмене
сначала фиксируется claim (хеш одноразового токена, который мост создал до запроса).
Только создавший claim ответ 201 даёт мосту право вызвать утилиту. Ответ на повторный
claim 200 и сетевой сбой не инициируют второй запуск. Исполнение с неизвестным исходом
оператор может закрыть как unknown. Повторный неизменённый ответ идемпотентен.
1.2. Для стороннего протокола мост принимает только явный адрес loopback Studio и один
локальный выбор программы. Протокол NDJSON `arachnid.utility.v1`: один запрос
`{protocol,utility_id,exchange_id,text}` и один ответ той же формы с теми же идентификаторами.
Ограничены длины, время ожидания и вывод; сырой stderr не публикуется. Каждый новый
обмен отдельно разрешается оператором в Studio. Автоматический путь требует реального
соответствия протоколу. Встроенные проверки квоты/запуска поставщиков остаются отдельными.
1.3. Проверить запись, открытие после обновления, две CLI с разными id, отсутствие
неявного запуска, реальную передачу в совместимую тестовую программу и ручной ответ,
инверсию токена/дубликаты/сбой, доступность Kimi Desktop отдельно от проверенного CLI.
