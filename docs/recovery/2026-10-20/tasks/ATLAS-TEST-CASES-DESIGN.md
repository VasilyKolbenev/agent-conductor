# Исходные проверки и свидетельства выполнения

У выбранной попытки уже есть tests.cases (путь, строка, имя, первый assert) и
tests.protocol (связь с действием, команда, полный вывод). Сопоставляем их на
стороне Studio после обычной проверки попытки. Альтернатива — отдельный серверный
запрос — не даёт новых данных и добавляет риск подмены текущей попытки.

1.1. Три одинаковых по числу источника не равны по смыслу. Код говорит, что задано;
verbose unittest печатает имена методов и результаты, но не значения аргументов.
Для краткого протокола показываем только общий результат. Сырые строки доступны
для сверки. Не угадываем статус метода по счётчикам, частичному имени или отсутствию ошибок.
1.2. Чужая попытка, неясное соответствие и отсутствие одного источника не мешают
показать то, что известно; нельзя выдавать информацию из соседней попытки за текущую.
1.3. По дополнительному контексту из diff пользоваться только строками этого метода
из снимка; при недоступности достаточно сохранённого assert с путём и строкой.

Браузерный шов: одна цепочка из пяти реплик, реальный verbose, краткий/неполный вывод,
узкая и широкая панели. Отдельно сверить установленный интерфейс с запечатанной попыткой
и журналом до/после. Не рассчитывать проценты покрытия или поштучные записи утверждений.
