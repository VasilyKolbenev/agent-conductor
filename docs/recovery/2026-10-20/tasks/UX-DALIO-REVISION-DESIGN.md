# Ревизия для запуска

Мастер получает номер вместе с выбранной карточкой. Для опубликованной карточки
стандартного мастера берёт диагностику аргументов, ролей и бюджет у сервера по точному
номеру. Снова проверяет этот же номер перед созданием запуска. Не создаёт или публикует
черновик и не выводит проверку ролей из локального списка предложений. Источники, которые
владелец создаёт из нового стартера, проходят существующий путь компиляции.

Вариант с загрузкой черновика и восстановлением его после подготовки отброшен: это может
потерять параллельное изменение. Для чтения выбранной версии используем отдельную форму
проверки в существующем маршруте flow с закрытым составом запроса. Ответ содержит точный
номер использованной ревизии. У задач, сохранённых до появления этого номера, остаются
прежние данные. В новом черновике задачи номер сохраняется для восстановления после reload.

Красный контроль — запуск по опубликованной версии, когда текущий черновик непригоден.
Зелёный — две подтверждённые роли, состояние исходного черновика и версия запуска в журнале.
Проверка допуска на модели, живые подписки и кандидат основного запуска за пределами задачи.
