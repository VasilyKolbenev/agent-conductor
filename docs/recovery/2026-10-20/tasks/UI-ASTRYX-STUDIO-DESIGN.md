# Панели и контекст выбранной попытки

TASK — `UI-ASTRYX-STUDIO-TASK.md`. База продукта — `ff2fbce`.

## Решение и варианты

Вариант A — прямое подключение компонентов Astryx, с React 19 и новой сборкой.
Вариант B — собственные ES-модули, CSS-переменные и изученные паттерны компоновки.
Владелец выбрал B. Использовать опубликованные подходы к панелям, плотности,
темам и фокусу. Геометрию орбиты и серверную привязку доказательств сохранить.

## Компоновка

1. Выше 920 px показывать три региона. Начальные размеры боковых панелей
   240 и 420 px. Пределы слева 184–320, справа 320–720 px, с сохранением
   минимум 360 px для Атласа.
2. На 701–920 px навигация открывается существующей выдвижной панелью.
   Справа можно менять ширину, минимум чата 280 px. При 700 px и уже
   использовать существующий нижний инспектор и управление фокусом.
3. Разделители имеют семантику separator, имя, ориентацию и числовые пределы.
   Мышь/перо — pointer capture. Клавиатура — стрелки, Home/End, крупный шаг
   с Shift. Escape и pointercancel завершают незаконченный жест.
4. Хранить только числовые предпочтения ширины в браузере. Повреждённое,
   недоступное хранилище и узкий экран не ломают рабочее место.
   Изменение окна ограничивает фактические размеры, сохраняя желаемые.
   Единственное исключение из старого запрета localStorage — модуль
   `arachnid-layout.js` и фиксированный ключ `arachnid.panel-widths.v1`.
   Запись содержит только два конечных числа `sessions` и `inspector`.
   Чат, доказательства, идентификаторы проекта и авторизация туда не попадают.
   Остальные модули сохраняют запрет; остальные sealed API запрещены и здесь.
5. Центр имеет собственную прокрутку, сообщение Атласу доступно при открытом
   инспекторе на desktop. Смена темы и выбранной сессии сохраняет ширины.

## Материалы Do

Использовать имеющийся bounded GET и проверку run/node/action/attempt.
Заголовок инспектора явно показывает выбранную попытку. Вкладки diff,
тестов и вердикта находятся в той же панели и сохраняют выбранное действие.
Поздний ответ другой попытки не заменяет текущий. Пустые и ошибочные
состояния сообщают фактическое отсутствие данных. Принятый архив используют
через штатную view-дорогу, новых записей и процессов провайдеров нет.

## Проверки и доказательства

Браузерные регрессии сначала воспроизводят отсутствие изменения ширины.
Проверить drag обеих границ, клавиатуру, пределы, сохранение, повреждённое
хранилище, responsive-переходы, отсутствие горизонтального скролла и POST.
Для доказательств использовать два действия с различимыми материалами.
В реальном принятом архиве проверить diff, фактический отчёт тестов и
отдельный verdict. Скриншоты и временные стенды находятся вне репозитория.

Изменение серверных полномочий, схем журналов и протоколов CLI не входит
в этот срез. Для обычного вклада выполнить проверки затронутого поведения,
ограничений исходников и вёрстки. Широкую проверку выбрать по фактическому diff.
