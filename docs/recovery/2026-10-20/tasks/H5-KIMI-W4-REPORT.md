# H5-KIMI-W4. Доступ к исходной учётной записи через Windows folder loan

## Измерено на Windows

Старый runner открыл контролируемому процессу в AppContainer файл под фиктивным соседним
Kimi login, когда только у этого файла имелась ACE `S-1-15-2-1:R`. Тест запустил PowerShell
с двумя ProviderConfig проекта, выдал ему relay Claude, вызвал OpenRead и сразу закрыл
handle. Ни один байт не читался. Без ACE тот же вызов получил ERROR_ACCESS_DENIED (0x80070005).
Папки login и credentials имели закрытые ACL. Число сравнений исходной версии — 1 failed,
1 passed. Две первые попытки в sandbox завершились CreateAppContainerProfile 0x80070057;
они не учитываются в измерении RED.

Исправление проверяет исходные пути всех настроенных Kimi по уже прочитанным строкам
ProviderConfig. FolderLoans сохраняет путь в точном написании и реальный путь для проверки
пересечений. Каждый grant проверяет только два региональных имени под `credentials`.
Дескрипторы закрепляют цепочку от корня тома. Во время выдачи прав повторяются проверка DACL
и сравнение идентификаторов. При позднем отказе runner восстанавливает выданные права.
Проверка не перечисляет содержимое каталогов за пределами прежнего контракта, не читает
байты исходных файлов и не изменяет разрешения исходного login.

## Отклонения и чужие правки

В sandbox шесть существующих junction-fixture получили Access denied при mklink. Две длинные
строки, затем ещё одна в тесте custom пути, были исправлены после проверки CAPPED. В первой
пробе обычного loan не был передан обязательный home=None, упали четыре случая до обращения
к Windows. Первоначальный рецепт M4 удалял запись журнала вместо проверки в конце grant;
не засчитан, затем пересобран и запущен по конкретной строке. Эти результаты не входят
в приведённые финальные числа. Общая ветка и работа других исполнителей не затрагивались.

## Открытые вопросы и передача

Гарантия относится к проверяемой выдаче прав на папки проекта. Windows позволяет доверенному
владельцу позже самостоятельно изменить ACL; W4 не является блокировкой такого действия
на весь срок процесса. Прямой runner без folder loan находится вне этого среза.
Ранняя readiness будущего Kimi relay и копирование токена остаются у следующего K2.
Код `68bdc32`, новый модуль находится в CAPPED. Следующий шаг — независимое ревью и
перенос кодового и документных коммитов ведущим. Полная CI и приёмка публичной альфы
за пределами этой проверки.

## Ревью Codex

Техлид принял исправление локально. Тест на Windows отразил различие между
опасной ACE и обычным профилем. По замечанию ревью исходные каталоги Kimi
проверяются по протоколу из конфигурации проекта, включая безопасные
нестандартные пути. Проверяются ACL и identity, без чтения содержимого.
В recovery перенесено как d67da2d. Это защита на момент выдачи прав,
а не разрешение подписочного dispatch Kimi.
