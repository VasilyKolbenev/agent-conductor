# RS1-CREDENTIAL-DEPTH

Владелец 11.11.2026 поручил закрыть остаток RS1: глубокий login JSON на
поддерживаемых версиях Python, локально, без моделей/повторного цикла, стоп 15%.
База 0aeb943, recovery/2026-10-20, repo чистый, стартовый остаток 17%.
WORKING-STANDARD обязателен. CI проверяет Python 3.11/3.12; установленный 3.12.14
не бросил на depth600 в прежнем probe, это не доказательство поведения 3.11.

Сначала найти доступные интерпретаторы и различающее воспроизведение настоящего
bounded fake JSON: parser принимает его, затем credential_values должен сохранить
все длинные значения без RecursionError. Не объявлять parse refusal тем же дефектом,
не понижать глобально recursionlimit ради искусственного «естественного» RED.

Если причина подтверждена — минимальный итеративный обход вместо рекурсии,
порядок/дедуп/порог/surrogatepass сохраняются, никаких skip/truncate/depth cutoff,
которые теряют значения. Превышающий возможность parser документ остаётся unreadable,
Q10 запрещает публикацию. Другие recursive readers исследовать, но не менять без RED.

Разрешены login_home.py, новый tests/test_credential_depth.py, CAPPED root.
