# Grok подписался на задачу, но не вернул диагноз

В запуске `grok-g6-alpha` владелец разрешил один `diagnose` на диагностической
сборке `a9044e1`. Работа по подписке до содержательного результата ещё не доказана.

| Что проверили | Результат |
| --- | --- |
| Разрешение и расход действий | Одно разрешение, один запрос, один результат. Повтор не выполнялся. |
| Что ответил CLI | Exit 1. Между событиями начала исполнения и наблюдения результата прошло 4,765 с. Квитанция сохранила `unclassified service error`. |
| Приёмка | Артефакт `artifact-causes` отсутствует. Квитанция не подтверждает расход токенов и не позволяет установить, дошёл ли запрос до модели. |
| Уборка | ACL, loan и profile помечены `retired`. Каталоги попыток и рабочий Grok-home пусты. Файлы учебного проекта и AGENT.md совпали с начальными SHA-256. Время изменения настоящего auth.json предшествует запуску. Сервер остановлен через Ctrl+C, проект вернул `closed`. |

Квитанция `result-2972b608aa2f7db545f18e892d494a60`. SHA-256 журнала
`cf5a7b7a2ef53a78c48e5373714756e105799e27699b903ee9bbadabbce08e90`.
В старой Studio владелец сначала получил общий отказ по истёкшему просмотру;
после обновления условий разрешение было записано. Исправленная Studio основной
ветки сопоставляет `preview_stale` с инструкцией обновить условия.

У входа, проверенного до запуска, не было полей `has_grok_code_access`,
`user_blocked_reason` и `team_blocked_reasons`. Отсутствие полей оставляет
право на выполнение задач неизвестным. TCP-соединение наблюдалось ещё до выдачи
разрешения. Оно не свидетельствует об отправке модельного запроса.

**Следующий различающий шаг.** Сначала проверить отдельным тестом на
синтетических данных, что ответ ACP authenticate до создания сессии можно
свести к признаку наличия `gate`, без вывода текста и без запроса к модели.
В 1.0.5 положительный признак означал бы, что CLI увидел ограничение при этой
проверке. Отрицательный не доказывал бы доступ. Сегодня такой обмен не входит в
разрешённые две последовательности RPC продукта. Не вызывать его через обходной
скрипт, не менять каталог настоящего входа и не повторять оплаченный diagnose.
Полный цикл Codex → Grok остаётся открытым.

После этого выполнен локальный эксперимент на 11 искусственных ответах через
штатный парсер SubscriptionRpc. Один ответ с gate дал фиксированный признак
ограничения, три без gate оставили доступ неизвестным, семь повреждённых или
неавторизованных ответов отклонены. Текст причины и поля аккаунта не выходят
из парсера. Прототип не добавляет разрешённый RPC в продукт. CLI не запускался.
Для перехода к реальной проверке нужен узкий дозволенный обмен в изоляции с
access-only копией и неизменностью исходного входа. Историческую причину
неудачной попытки такой обмен задним числом не устанавливает.
