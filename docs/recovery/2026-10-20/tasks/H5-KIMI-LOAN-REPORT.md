# K2b.1 — Kimi прочитал фиктивный вход через настоящий read-only Windows loan

Итог: локально проверено в отдельной ветке codex/kimi-k2b-loan, база e948f63, TASK/DESIGN 3c6ceab и уточнение cce66bd, код 8cb677c. Это работа над приложением после кандидата 0148af5. В нём нет этой правки. Подписочное выполнение Kimi пока закрыто.

**Измерено на Windows.** Кем бы ни был будущий пользователь, HTTP и поля формы не поставляют identity. Создатель открыл синтетический home эксклюзивно относительно сохранённого Windows directory handle и удерживал его до завершения. Доверенный ProcessRunner использовал полученную identity. До записи loan и назначения прав runtime повторно сравнил её с identity действительного grants handle. Этот handle удерживается через attach и возврат прав. Холодное восстановление умеет прочесть запись с новым правом read именно на home. При отсутствии нового параметра прежние grants, регистрации и права сохраняют прежнее поведение.

- Sentinel в настоящем AppContainer без internet capability прочитал credential. При записи, переименовании и создании окна записи в home получил Windows ERROR_ACCESS_DENIED (0x80070005) во всех трёх случаях. Запись в штатный runtime scratch достигла файла, байты входа и его путь сохранились. Финальная команда: 1 passed, 0,79 с.
- Отдельно: официальный Kimi 0.38.0, архив Windows x64 SHA-256 80e4de3f2bd7c33ba10cfe3c2282492b0758fae9887537f4ff79ec2022957004, был извлечён в новый тестовый install. Настоящий ACP получил result на initialize и authenticate в этом же типе product loan. Поддельный токен без refresh остался прежним. Нет сетевого capability, промпта модели, подписки или настоящих данных входа. Финальная команда: 1 passed, 5,11 с.
- Переносимые сценарии дополнительно воспроизводят подмену после проверки пути (на месте новое корректное дерево), необоснованные AAP/package/capability allow ACE на каждом из четырёх объектов, защищённого ребёнка, лишний файл, ACL-сбой после выдачи и восстановление. До исправлений 7 failed на исходном поведении и отдельно 13 failed на входной DACL; теперь 23 локальных проверки выбранного шва зелёные. Расширенный набор с предыдущими snapshots и guards: 486 passed/UTF-8 (28,75 с), 486 passed/cp1251 (28,69 с). Файловый guard — 9 passed.
- На изолированной копии M0 — 23 passed. Ни один из семи мутантов не пережил свой сценарий: удаление preflight, удаление проверки удержанного объекта, выдача modify, допуск чужого контейнера, игнорирование лишнего имени, неверный наследуемый ACL и отсутствие проверки после выдачи. Свидетели в Documents/Codex/work/kimi-sub-k1a/k2b-*.txt. Первые прогоны выявили пять отказов sandbox при создании junction, несовместимость тестового конструктора и затем три длинные строки. Для junction использован штатный Windows-контекст, для старого конструктора сохранён прежний вызов, строки разделены без ослабления проверок.

**Граница.** Доказан project-minted .kimi-home с известной формой и фиктивным credential. До реального k-* relay требуется W3: связать региональный bootstrap и expiry с долговечной описью от stage до recovery, доказать сохранность исходного аккаунта и отказ после частичного grant/cleanup, включая отключённый провайдер и внешнюю подмену. Затем независимо проверить эту границу и пройти вход и одну содержательную задачу на оплаченной подписке владельца. ACP без сети не доказывает полномочия настоящего сервиса.
