# K2b.1 — контракт только для trusted runner

Вариант A — дать второму слою уже открытый произвольный grants handle и научить его закрывать чужую аренду. Это меняет имеющуюся модель владения recovery. Выбран B: внутренний AttemptFolders может нести readonly_home_identity (идентичность, захваченная создателем). Явная identity одновременно требует, чтобы home был только для чтения. Передать значение через ProcessRunner/ProfileJournal до FolderLoans. Перед созданием профиля проверить текущую identity для очевидной подмены и обязательно повторить проверку на фактическом grants hold до записи что-либо в loan и до выдачи каких-либо прав на целевой объект. Тот же grants hold сохраняется до возврата из контекста. Прежние аргументы и формат грантов при отсутствии identity неизменны. Пользовательская команда, UI, HTTP и provider registry не задают эту identity.

Права нового home: каталог и вложенные каталоги — read/traverse; файлы — read без execute/delete/write. Закрытый класс прав «read» применим только к строке home в уже существующей схеме журнала. Existing restore удаляет ACE конкретного SID у того же объекта по проверенной identity. Scratch — отдельный writable runtime каталога попытки; рабочая папка в review — read-only. Несовместимость CLI с read-only home должна остаться явной, а не приводить к повышению прав.

В первоначальном нативном срезе home — известный project-minted путь только с синтетическими данными (не новый production relay). Объект создаётся эксклюзивно относительно удержанного каталога и удерживается создателем через фактический grant и attach. Проверить точные коды Windows при write/rename из изоляции и отсутствие изменений; write в scratch должен реально произойти. Последующая задача W3 привяжет защищённую внешнюю раскладку, долговечную опись stage, права scratch, отказ восстановления и k-prefix. Реального входа до подписки владельца нет.
