# F5 первого черновика

Проверено локально. Восстановление проходит через ограниченный сервис памяти одного активного проекта. В history лежат только ID подтверждённого проекта и непрозрачный ключ. Данные не сохраняются в браузерном storage, файлах, событиях, workflow или run. Исходные TASK/DESIGN `832e12e`, правка `eb484bd` на базе `0148af5`; отдельная проверенная интеграция с pin `ce77ba5` — `111cc23` → `c7ca856` → `791e665`. В основной ветке два первых коммита перенесены как `b6c93fa` → `3996d91`.

POST `/command/project/task-draft` использует прежнюю закрытую транспортную дверь, регулярные Origin/CSRF и обязательный project claim. Сервер принимает только указанную схему редактируемых полей, включая роли, модели, инструкции и правки к материалам. Размер ограничен 32 КиБ UTF-8, хранится не больше 16 строк, TTL 30 минут. Чтение и сохранение неизвестного ключа ничего не выделяют. Сервер генерирует ключ только при `open`. Прежний workflow draft не подходит, потому что публикует другую сущность через другую границу полномочий.

RED до реализации: один реальный запрос вместо обязательного отказа по project claim видел неизвестный маршрут. Теперь проверены конкурентные окна, запрет чужой записи по старой ревизии, capacity, expiry/restart, неправильные поля, отсутствие эха в отказах и отсутствие task/run событий. Первые чтения и несохранённые изменения явно разделены в UI. До ack правка отмечена как ещё не сохранённая; выход предупреждает. Потеря сервера не гарантирует восстановление.

**Закрытие и потерянное подтверждение.** Владелец закрывает форму и сразу убирает history pointer. Если сервер ещё не получил save, discard удаляет строку и опоздавшая запись получает 404. Если сервер принял save, но ACK удержан, совпадение конкретного edit ID даёт удалить собственную следующую ревизию. Сохранение другой вкладки по другой операции этим discard не стирается. Конфликт не является разрешением на перезапись/создание.

Chromium на интегрированной версии: основной мастер, F5 с источниками и отдельными полями, Codex pin и пустая модель Grok, отсутствие повторного открытия иной задачи. Порядки «приостановлено до запроса» и «приостановлено до ACK» прошли в обычном браузере на реальном локальном сервере. В финальной адресной cp1251 проверке — 10 passed (`test_project_task_draft` и именно SEALED wire-door guard), 5 passed (F5, material, model pin, оба Close/ACK). Оба новых Python-файла включены в CAPPED. Полный core, wheel, нативные harness и рынок этим срезом не проверялись. На точной `ce77ba5` широкий модуль source отдельно выявил актуализацию счётчика строк studio-model после pin; его статус относится к интеграции, не к неизменному списку запрещённых API. Модельных вызовов нет.

Последний доказанный шаг — защищённое F5 на тестовых проектах через обычный пользовательский путь. Следующий шаг — собрать конечный интегрированный SHA и пройти общий core. Не повторять: сохранение текста в browser storage или перенос grant/actor в черновик.
