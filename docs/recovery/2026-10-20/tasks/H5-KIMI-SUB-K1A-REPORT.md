## Как воспроизведено

Свидетель запускает тестовый CLI и наблюдает code-owned значение у двух фактически созданных процессов. Для проверки ACP и локального сервера квоты используется ProcessRunner на границе со штатным adapter. До правки три проверки упали по отсутствующему выключателю. Родительский 0 попадал в дочерний процесс. Второй отдельно воспроизведённый дефект — 2 failed, 3 passed: Windows алиасы Kimi_Code_No_Auto_Update оставался в env_allow и Kimi_Code_OAuth_Host не вызывал отказ до spawn. В журнале тестового CLI для выключателя хранится только boolean.

Мутанты на отдельной копии исходников с проверенным импортом: M0 — 4 passed. Удаление выключателя и его замена на 0 каждое дали 3 failed, 1 passed. Сохранение написанного иначе обновляющего ключа и регистрозависимая проверка OAuth host каждое дали 1 failed, 3 passed. После каждой подмены исходный SHA файла проверен, временная копия удалена.

Первые широкие прогоны из файловой песочницы получили 13 failed, 436 passed: WinError 5 при атомарном переименовании файлов журналов тестовых проектов. Диагностика на двух файлах воспроизвела тот же WinError; 13 failed, 15 passed. Вне песочницы в короткой временной папке выявилась другая причина: 1 failed, 448 passed, test_the_spawn_log_stores_names_and_booleans_and_never_a_value отверг новое поле fake CLI. Форму журнала дополнено только boolean и повторно проверено на детектирование утечки. После этого 469 passed дважды до Windows-среза, после него — указанные выше 470. Отклонение: неподконтрольный путь среды исправлен в команде проверки, а не в продукте. Чужие незавершённые UX/Grok изменения соседних исполнителей не вошли в коммит.

Ревью Codex: фильтрация согласуется с Windows, исходный отказ подписочных задач сохранён. Запрошенные свидетели digest и допустимого API режима проверены. Общий RelaySpec не менялся. Без подтверждённого нативного входа и настоящей задачи приемка Kimi остаётся открытой.

## Передача K1b

Последний доказанный — профиль Kimi принудительно отключает обновления на дорогах адаптера. Первый несделанный — проверка имени, расположения и формы настоящего управляемого входа при чтении квоты. Исполнитель владеет kimi_code.py и tests/test_kimi_quota.py; общей функции login_home.py или RelaySpec требует отдельный дизайн и ревью. Вход на время тестов синтетический.

На public quota_plan_for/read проверить config.toml обоих регионов, что выбран единственный правильный лист в credentials, неверный ключ/регион, отсутствующий файл, неподдержанный формат и вложенный reparse до первого spawn. Фиктивный результат /api/v1/auth не должен превращать отсутствующий либо неподдержанный вход в успешное чтение. Не использовать минимальный запас срока для relay как условие учёта квоты: вход вне попытки имеет другой контракт. Затем отдельно — согласовать чтение/создание вложенного relay, его guard до HTTP refresh и нативные свидетели по DESIGN. Не повторять: fake quota, зелёные snapshot и установка Desktop не подтверждают модель или подписочный dispatch.
