## Границы результата

В корне временного home дано право создавать файлы, но нет права создавать подкаталоги
или удалять дочерние объекты через родителя. Уже существующие `sessions/` и `logs/`
допускают запись, как и два предварительно созданных листа `device_id` и
`workspaces.json`. Эта конфигурация достаточна на проверенном стенде. Не доказано,
что нужен каждый из перечисленных листов, или что достаточно дать право записи только
заранее известным файлам. В отдельном контроле без создания файлов в корне остался
permission denied. Имя операции и файла этого первого отказа не установлено.
В успешном scratch появились `migrations-effort.json` и `session_index.jsonl`.
Текстовая диагностика в предыдущем широком тесте «not found» не доказывала нехватку
shell; здесь это проверено парой с противоположными ответами session/new.

Конфигурация, `credentials/` и токен имели отдельные защищённые DACL и handles;
после выхода байты исходников и копий совпали. Папка попытки и регистрация
AppContainer исчезли, список активных процессов runner пуст. Эти наблюдения относятся
только к фиктивному профилю и данному запуску; это не crash recovery.

## Воспроизведение

В окружении проекта Git for Windows из локального набора инструментов предоставил
`usr/bin/sh.exe` (GNU Bash) и `msys-2.0.dll`. В переносимой опциональной проверке
хеши архива Kimi, извлечённого kimi.exe, sh.exe и DLL сверяются до запуска.
Передайте `CONDUCT_TEST_KIMI_ARCHIVE` с архивом 0.38.0 и `CONDUCT_TEST_KIMI_SHELL`
с неизменённым sh.exe из этого набора. Запустите отдельно
`python -m pytest -q tests/test_kimi_session_state_native.py`
с уникальным временным каталогом. Тест missing-shell требует машину без другого Git
в явно проверяемых путях поиска; на машине с Git выполняются два остальных контроля.
Новые загрузки, профили пользователя и shell из PATH не нужны.

Финальный SHA в UTF-8 и cp1251 — по 3 passed, 0 skipped. В них проверена связь
response ID с каталогом сессии, исходные байты и уборка. Мутанты на отдельной копии:
M0 3 passed. Убрать shell — 1 failed. Убрать право создавать обычный файл —
1 failed. SHA файла после возврата каждого мутанта проверен, копия удалена.

382 смежных регрессии на исходной ветке дали 381 passed и один прежний отказ
`test_command_adapters` по импортам `codex_patch.py`, отдельно воспроизведённый.
Передано техлиду; исправление этого базового барьера он ведёт на `375caa7`.
Это не выпускная матрица. Экспериментальные записи находятся в
`Documents/Codex/work/kimi-session-state-1108-evidence`.

## Диагностика стенда

Попытка выдать только создание файлов не дошла до CLI: лабораторная DACL не передала
системе и владельцу наследуемые права на новый каталог. Во время сбора мусора часть
одноразового project layout уже удалили, поэтому штатный recover-containers отказал
по ownership. После сверки оставшегося журнала, SID, moniker и displayName восстановили
права лишь на пустую синтетическую папку, удалили именно тот AppContainer и временное
дерево. Следующие прогоны создали независимые контейнеры с проверкой полного возврата.
В раннем положительном запуске обычный путь в уборке тестовой папки превышал 260
символов. Применён штатный extended path, ранний положительный исход не засчитан.
При переносе в pytest первая попытка имела 2 failed, 1 passed до проверки сессии:
в ожидаемой DACL регулярного файла были наследуемые флаги каталогов. После исправления
предусловий заново проверены и сами байты DACL, и результат ACP.

## Передача

Последний доказанный шаг — штатная сессия Kimi до prompt в изоляции со своим shell и
ограниченным синтетическим состоянием. Для W3 предстоит спроектировать доверенное
размещение shell и привязку его содержимого к конфигурации, ввести тип временного
состояния, ограничения имён/размера, журнал и восстановление после частичного сбоя.
Переносить произвольный `KIMI_SHELL_PATH` из окружения владельца в продукт нельзя.
Проверки K1b для регионального входа и его файлов остаются обязательными; в продукте задача
по подписке по-прежнему закрыта. Следом потребуется живая подписка и независимая
приёмка результата. Доказанный тракт ACP не подтверждает исполнение штатного prompt.

Отклонения по продукту отсутствуют. Ревью Codex: ожидает.
