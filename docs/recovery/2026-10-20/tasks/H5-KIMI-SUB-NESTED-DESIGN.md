# Предложение K2a — вложенный credential Kimi. Общая граница ждёт ревью

Для TASK 9e9f382, DESIGN 8c22a47 и K1b 884df9a. Ниже предлагается следующий контракт. Сам по себе документ не разрешает Kimi создавать рабочую копию токена, выполнять задачи или читать новый файл из других harness.

## Почему нужна отдельная дорога

Сейчас RelaySpec.credential и files — bare names. В login_relay.ready/copy_in, _write_exclusively, relay_attempt._read_relay_home и discard/sweep эта форма даёт целый контракт. Поля профиля сериализуются буквально в ProviderAuthority.facts и определяют digest утверждённого разрешения. Claude, Codex и Grok уже хранят вход в плоских файлах. Kimi хранит обычный config.toml и ровно один вложенный secrets-файл, имя которого определяется регионом. Открытие разделителей пути в общем списке разрушило бы прежнюю гарантию, что родитель файла — ровно тот relay, который проверили.

Рассмотрены два интерфейса. A — допустить относительный путь в существующем credential/files и поручить всем существующим операциям его безопасное разрешение; это меняет договор каждого провайдера и всех потребителей имени. B — сохранить старые строки и добавить ограниченную раскладку только Kimi. Предлагается B. Тип расположения хранит отдельные проверенные компоненты, расстояние до листа фиксировано в коде. Граница не получает произвольного path, TOML строки, разделителя, glob, symlink или функцию из конфигурации.

## Видимый контракт и неизменность грантов

- Зафиксировать в Kimi-профиле кортеж из двух допустимых расположений: (credentials, kimi-code.json) и (credentials, kimi-code-env-0e4f99c69cc27850.json). Одновременно выбирается только одно по точной паре host и закрытой схеме уже существующего managed-профиля. Корень relay получает один config.toml, каталог credentials — один выбранный credential. Других изначальных имён нет. Время, регион и перечень полей/расширений проверяются на реальном пинованном формате.
- Не добавлять dataclass-поля даже со значением None старым RelaySpec/HarnessProfile: это меняет asdict и старые grants. При необходимости добавить методы с прежним поведением для плоской раскладки; декларацию новой формы держать в Kimi-подклассе. Не записывать адреса/функции в digest. Порядок и результирующие байты имеющихся ProviderAuthority snapshots должны совпадать. Отдельно доказать, что изменение выбора региона/дерева Kimi при подготовке меняет digest или делает прежнюю готовность недействительной.
- Login credentials Kimi уже читаются через nested_credentials managed-профиля. Сделать проверяемым совпадение разрешённых региональных имён, чтения утечек, _hold_relay и результата. Файлы, допустимые для перепроверки после запуска, отделить от разрешённых для копирования до него. Не объявлять весь каталог credentials входным файлом. Для Kimi-попытки добавляется ровно префикс k-<16 hex> к relay_home.HOME_NAME, типичной ошибке, recovery и тестам маршрута; предшествующие имена и правила остаются прежними.

## Жизненный цикл и устойчивость к подмене пути

1. Прочесть под арендой входа проверенную пару региональных адресов, конфигурацию и единственный credential. Проверить взятые из конфигурации модель и разделы, затем собрать новый минимальный config.toml. Не переносить исходные байты TOML, server.token, per-user инструкции, расширения, MCP, файлы сессий или refresh.
2. Удерживать по компонентам Windows-каталоги от проверенного корня продукта до auth-home и credentials, без follow-reparse и sharing DELETE. Удерживать оба исходных файла неперемещаемыми на время взятия снимка. Требовать обычный объект, identity, единственную hardlink, отсутствие reparse/delete-pending и ограниченный размер. Читать через полученный handle. Проверить порядок захвата между арендой login и временем жизни handles — CLI metadata, который штатно ротирует токен, не должен параллельно разделять арендованный снимок. При невозможности взять hold — отказ до spawn.
3. До записи в проверенный пустой relay заново получить тот же регион, конфигурацию, credential, срок и полномочия под теми же правилами. После повторной проверки удерживать handles до завершения создания. Подлинные expires_at/expires_in и триггер max(300, expires_in/2) сохраняются; к нему добавляется action horizon. Содержимое временной credential допускает только вышедшие из проверки access и метаданные, refresh пуст. digest связывает старый исходный credential, канонический bootstrap и фактический регион. Угадать имя пользователя/аккаунта по токену нельзя.
4. Удерживать проверенную цепочку до каталога назначения; пустоту проверять через удерживаемую directory identity. Создать дочерний credentials исключительно, сразу открыть no-follow и проверить прежнюю identity; создавать файлы с CREATE_NEW, запретом reparse, через удерживаемого родителя. Не использовать «проверить существование, затем обычный open for write». При любом совпадении имени, изменении identity или чужом содержимом — отказ. До выдачи доступа контейнеру проверить DACL и точное дерево (два уровня, оба известных файла, отсутствие лишних имён). Изменение разрешённых байтов и выдача lease связываются с той же директорией. Нативный тест на race обязателен.
5. Перед spawn и при возврате использовать существующий закрытый набор полномочий и ожидаемую сигнатуру. Послезапускное чтение не разыменовывает по строке прежний nested ticket: повторно берёт защищённые handles и сверяет identity, схему и отсутствие refresh. Подмена папки/файла, присоединение дополнительной ссылки или попытка записи секрета дают безопасный отказ с очисткой. Учитывать законные scratch-файлы отдельно от credential. Процесс не должен видеть исходный login-home.
6. При частичной записи чистить только созданные этим действием объекты по их identity. После аварии и при sweep сверять тип, корень, префикс и форму пути, не идти через junction; сначала удалять секретное содержимое, затем дерево. Если не удалось доказать отсутствие временной credential или удалить её, не запускать новую попытку и дать владельцу понятный статус восстановления. Настоящий вход не удаляется и не получает write-back.

## Обязательные свидетели до включения

| Граница | Проверка, включая поломку |
| --- | --- |
| Формат трёх существующих CLI | Их current config, grant digest и снимки реальных аргументов и окружений побайтово равны исходной версии. Изменённая форма Kimi не меняет результаты прежних cleanup/sweep. |
| Вложенное дерево | Обе валидные формы создают точное дерево; другой регион, третий файл, второй valid credential, alias по регистру, ADS, dot/dotdot, UNC или reparse/hardlink до и после выбора дают отказ. Синтетическое значение refresh нигде в relay/журнале, исходные байты и DACL не меняются. |
| Гонка и сбой | Управляемый противник пытается подменить родителя или лист между inspect/open/recheck и attach. Он должен получить запрет или задача останавливается до spawn. Убить создание до/после каждого из двух файлов, потерять grant после recheck; ни один частичный результат не допускает запуска, ни один внешний файл не меняется. |
| Права и статусы | Readiness из quota K1b не разрешает dispatch. Реальный Windows AppContainer с известным CLI, синтетическим fresh/expired/forced входом, запретом refresh HTTP и проверкой cleanup. Затем отдельная приёмка владельца. Ни один fake или чтение квоты не выдаёт готовность подписочного исполнения. |

Открыты для двух независимых ревью: где гарантируется атомарная связь identity между созданием дочернего каталога и удержанием его handle; какой код возвращает креденциальный файл в cleanup после частичного отказа; какие digest и DACL доказывают неизменность поведения трёх старых harness. До решения техлида общие runtime-модули не менять.
