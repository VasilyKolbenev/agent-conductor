# Передача файлов при подготовке патча

Воспроизведение на Windows разделяет два наблюдения. В AppContainer этого адаптера
в режиме review закреплённый CLI прочитал оба файла через fs/readFile. Через
обычный exec с локальным синтетическим Responses endpoint тот же CLI отклонил
обе команды Get-Content политикой инструмента. Журнал живой попытки не сохранил
команду обращения к файлу.

Для профиля implement-patch-v1 отправить на stdin текущие UTF-8 тексты из рабочей
папки. Atlas выделяет имена из исходного запроса человека до добавления критерия
советника. Он показывает их перед выдачей разрешения и записывает закрытый список
в instruction-plan под маркером conduct.patch-sources.v1. Хеш этой инструкции
уже входит в разрешение. Прежние инструкции без списка работают по-прежнему.
Использовать только привязанную инструкцию без source_action_id. Чтение
ограничить точным work_scope и work_item_id из запроса. Сверять прочитанные байты
с начальным снимком действия. Сохранять ограничения размера, отказ при подмене,
чтении защищённого значения и нерегулярном файле. Отдельный checker продолжает
получать изменения после публикации.

Альтернатива с разрешением произвольной оболочки увеличивает права каждого Do
и всё ещё зависит от команды, которую сгенерирует исполнитель. Источник данных в
stdin переиспользует существующую проверку пути и текущий бюджет запроса.

Свидетель на входе процесса проверяет два точных содержимых и отсутствие данных
из соседней задачи и имени из сгенерированного плана. Проверить отказ до вызова
исполнителя при небезопасном входе. Нативный контроль и стенд не требуют модели.
