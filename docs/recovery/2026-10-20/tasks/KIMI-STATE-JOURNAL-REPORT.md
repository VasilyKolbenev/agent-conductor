# Владение временным состоянием Kimi

TASK/DESIGN `09bfb8e`; реализация `0a68edb`, усиление по итогам ревью `47662d3`.
База `107e461`, собственное worktree. Чужих правок нет.

Внутренний вызов ProcessRunner может подготовить именованное дерево только в offline
review с уже закреплённой identity staged home K2b. До запуска в существующем журнале
Windows ACL записаны profile SID, boot witness, owner nonce, исходные ACL и файловые
identity корня, sessions, logs и credentials. Пути задаёт код. Корень разрешает создание
обычных файлов, sessions/logs разрешают запись данных, credentials даёт SID только чтение
каталога. Новые обычные объекты не получают право исполнения. Настройка задач и UI не
предлагают эту служебную опцию; новый grant по подписке ею не создаётся.

Уборка проверяет идентичность учтённых каталогов, форму дерева, отсутствие порталов/
многоссылочных файлов и неизвестных имён в корне и credentials. До удаления появляется
durable-фаза retiring. Повтор после частичного удаления проверяет сохранившиеся identity.
При исчезновении именованного каталога до intent, подмене или неожиданном файле данные
остаются для разбора. Активные конфигурации и записи старого формата не мигрируются.
Старый бинарник не умеет читать запись, созданную с новой явно выбранной раскладкой.

## Границы и передача

- В случае сбоя создания **до** записи первой проверенной описи каталог нельзя удалить
  по одному имени. Существование неучтённого дерева теперь препятствует снятию профиля.
  Автоматическая уборка такого остатка не доказана; никакие credentials и модель на этой
  стадии не нужны. Учтённое дерево после доказанного restart прошло повторное восстановление.
- Это открытая только доверенному runner возможность выделить **состояние**. Будущая
  запись реального регионального credential, проверка его access-only формы, entitlement и
  horizon, идентичность config/листа до чтения и до удаления, ограничение байтов и подход
  к неожиданным именам нужны до живого использования. В профиле Kimi подписочный dispatch
  по-прежнему закрыт. Содержимое обрабатывается только в пределах общей границы 5000
  записей уборки; это не ограничение объёма записи CLI на диск.
- В защищённой установке продукта нет Kimi/shell. Для следующего шага нужны проверенный
  источник shell и зависимостей и зафиксированный их набор: закрытая относительная
  раскладка под install, хеши в provider authority и согласованных условиях, проверка
  отсутствия чужих прав записи с удержанием identity на время процесса. Не перенаправлять
  произвольный `KIMI_SHELL_PATH` владельца и не искать запасной shell по PATH. Хеши
  фактически проверенного набора Git for Windows записаны в предыдущем нативном свидетеле
  `913cf94`; происхождение защищённой продуктовой установки они не доказывают.
- Последний доказанный шаг — нативная сессия с уборкой journaled state и отдельный crash
  witness на синтетической раскладке. Следующий — связать проверенный install и перенос
  только разрешённых данных входа с теми же средствами recovery, затем провести
  подписочную приёмку. Не повторять старую попытку direct dispatch или настоящий вход.
