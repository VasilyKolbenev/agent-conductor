# Причина отказа после открытия сессии

Итог: локально проверено | 7de5cdd | 765 passed в UTF-8 и 765 passed в cp1251 |
живого вызова не было. Защищённая установка остаётся на 112cc6d.

В 112cc6d декодер проверял тип и согласованность терминальной ошибки, затем возвращал
одну и ту же фразу для всех ошибок с открытой сессией. Отказ последнего живого
grok-g6-session необратимо свёрнут в эту фразу. Его первопричина неизвестна.

В новом коде структурный предел ходов, отказ, отмена и предел токенов имеют свои
фиксированные причины. Узнаваемые терминальные сообщения дают категорию, включая
отказ доступа, 429, серверную ошибку и отклонение блока задания. При нескольких
разных или неизвестных причинах остаётся свидетельство этапа. Журнал принимает
только целую фразу из закрытого словаря. Исходный текст ошибки не публикуется.

До изменения 6 из 9 новых примеров падали. В интеграционном контроле тестовый CLI
сначала выдаёт ID сессии, затем отказ доступа с приватной строкой. После повторного
открытия хранилища квитанция содержит этап и категорию, приватная строка отсутствует,
выходного артефакта нет. Обычный JSON и успешный потоковый review сохранены.

На точном Grok 1.0.5 с искусственным входом, текстовым prompt и отключённой сетью
контроль закончился по таймауту 30 секунд. Три ресурса сняты, временная папка удалена.
Этот контроль не воспроизводит наблюдавшийся за 4,523 секунды exit 1 и не исключает
другие сетевые ошибки. В доступных системных событиях за окно отказа не найдено
записи, связывающей его с Grok. Журнал DNS отключён, Security был недоступен.
Квитанция — `Documents/Codex/work/g6-offline-plain-20261103/result.json`.

Следующий различающий эксперимент — отдельно согласованный короткий контроль той же
подписки в официальном CLI вне December Command. Его результат определит, исследовать
ли доступ самой подписки или различия между штатным вызовом и изолированным запуском.
Старый запуск не повторять. Успешный живой diagnose не подтверждён.
