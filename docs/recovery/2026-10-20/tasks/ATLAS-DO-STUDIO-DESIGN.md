# Чтение материалов выбранной попытки

TASK `3aa6433`. Сохранить маршрут Studio Runs и его обычные решения. Вариант, который
берёт общий latest checked_changes, неверно связывает старые попытки с последней.
Выбран отдельный bounded GET `/command/runs/{run}/steps/{node}/actions/{action}`.
Проекция подтверждает run, node, action и attempt, проверяет frozen plan, request,
result и указанное им доказательство отдельного checker. Ошибка чтения или повреждение
материала не подменяется успехом. Прежний latest API сохраняет свой контракт.

1.1. В исходном манифесте modified хранится только новый blob. Для старой стороны diff
использовать сохранённую базу seed. В active допустим только штатный pinned Git read;
в view — ноль дочерних процессов. Импорт базы в локальную архивную копию проверяет
цепочку Git tree и blob от seed.base_tree. Новые имена требуют доказательства отсутствия,
удалённые — совпадения старого материала. Ни HEAD, ни нынешний каталог задачи не являются
источником diff. Ограничить размеры/число файлов, проверки путей, binary и чувствительных
данных; при отсутствии основания явно сообщить об этом.

1.2. Старый независимый oracle сохранил агрегат, ссылки на run, action, манифест, commit
и хеши файлов. Хранить такой отчёт отдельно от квитанции checker. Статус recorded
означает наличие валидированного внешнего отчёта, а case из исходника — метод из
проверенного снимка. Не приписывать отдельному методу поимённый исход, которого источник
не сообщил. Публичный GET только читает. Доверенная локальная загрузка принимает данные
лишь для совпавших run/action/attempt/manifest/base и сверенных файлов; сохраняет через
exclusive publication и действующего владельца проекта. Незаписанный отчёт явно отличается
от записанных нуля ошибок и от повреждения.

1.3. В центре рабочего экрана остаётся Атлас, в подтверждённом контексте выбранного
запуска. В этой сцене он отвечает локально по материалам попытки. Выбор узла и действия
не меняет журнал. Поздний HTTP-ответ другой попытки отбрасывается. Телефон даёт возврат
на выбранный шаг; основная навигация, прежние команды, режимы просмотра/исполнения и
действия владельца сохраняются. Правую панель наполняют только данные продукта.

Проверки: два шага/попытки, отрицательные привязки, старый и повреждённый отчёт,
изменённый живой файл, очистка и поздние ответы, приёмка результата на wheel в
копии реального проекта. Параллельные задачи ведутся в отдельных worktree; базовые
файлы, серверная проекция и интерфейс имеют раздельных исполнителей.
