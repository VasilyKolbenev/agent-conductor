# H5-KIMI-SUB — подключение подписки Kimi Code

Решение владельца от 02.11.2026. Для публичной альфы пользователь должен подключить свой аккаунт к каждому из четырёх harness. Этот срез отвечает за Kimi Code в Windows. Проверка UX идёт первой. Подготовка технического контракта Kimi возможна параллельно и не требует доступа к аккаунту.

## Результат

Пользователь устанавливает проверенный Kimi Code CLI 0.38.0, входит в отдельный профиль продукта через официальный OAuth, видит доступные окна квоты и выполняет одну явно разрешённую задачу под своей подпиской. История показывает проверенный результат и изменение учебного проекта. Отсутствие сведений о квоте означает «нет данных». Kimi Desktop и ключи API не закрывают эту приёмку.

## Порядок работ

1. K0. Изучить именно исходники тега 0.38.0. Проверить формат входа, регион, обновление токена, квоту, команду задачи, загрузку локальных инструкций и автоматическое обновление CLI. Записать варианты изоляции и швы тестов в DESIGN. Это исследование не устанавливает CLI и не запускает модель.
2. K1. Офлайн на синтетических данных проверить распознавание поддерживаемого профиля и токенов, границу срока и защиту рабочего пространства от конфигурации и расширений. Доказать, что текущие Claude, Codex и Grok не изменили контракт или гранты. Возможность исполнения остаётся закрытой до нативной проверки.
3. K2. На Windows проверить долгие и кириллические пути, ACL и уборку, затем подлинный закреплённый CLI на фиктивной учётной записи с контролируемой сетью. Доказать сохранность исходного входа. Изменение версии, региона, способа входа или допуск нового полномочия требуют отдельного решения.
4. K3. Владелец выполняет вход и разрешение в приложении. Сначала проверяются версия, состояние и квота; затем одна задача с наблюдаемым изменением и проверкой результата независимым участником. Чистый профиль и установка из проверенного wheel входят в приёмку. Ни один технический тест не заменяет этот шаг.

## Стоп и передача

Любое из условий останавливает переход к следующему срезу: требуется настоящий refresh-токен внутри попытки, неизвестен формат или источник токена, CLI читает непроверенный инструмент или инструкции, обнаружена утечка, повреждение входа, неубранная попытка либо нет аккаунта для живого этапа. Возобновление после неизвестного исхода не запускает задачу повторно. Платный вызов требует отдельной проверенной карточки приложения и нажатия владельца. Свидетель и первый недоказанный шаг фиксируются без данных авторизации.
