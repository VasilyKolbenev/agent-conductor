# Временная конфигурация Read в принадлежащей продукту попытке

**Итог.** В `a3080fd` штатный `ProcessRunner.container_profile` подготавливает и удерживает конфигурацию ограниченной роли Kimi. На Windows настоящий CLI вернул из этого профиля контрольную запись каталога моделей и создал ACP-сессию. Подмена конфигурации и запись в credentials были отвергнуты. Срез проверен автономно, без сети и вызовов модели.

## Что привязано к попытке

- `read_role_config` принимает только проверяемый управляемый профиль и закрытый список инструментов `("Read",)`. Из разрешённого региона, OAuth-параметров и выбранной модели он заново строит минимальный TOML. Исходный профиль с внешним провайдером, API-ключом или собственной секцией инструментов получает отказ. Опциональные поля поставщика не переходят в сгенерированную конфигурацию.
- Предварительный результат хранит два SHA-256 — всех байтов проверенного профиля и всего сгенерированного TOML. В существующем контексте offline review источник повторно читается из удерживаемого staged home. Изменение одного байта, даже если TOML по смыслу прежний, прекращает подготовку до передачи управления дочернему процессу.
- `config.toml` создаётся эксклюзивно под уже учтённым каталогом временного состояния. Windows выдаёт SID попытки только чтение файла. До запуска в существующую запись ACL с ID попытки и SID добавляются оба SHA-256 и identity файла. Источник и целевой файл удерживаются во время использования. Уже созданную запись подготовки перезапуска такой операцией изменить нельзя.
- После смерти процесса восстановление сверяет identity и SHA-256 уцелевшего config.toml. Если файл заменён или изменён, состояние сохраняется для разбора. Отсутствие файла допустимо только после записи намерения очистить дерево. Старая форма записи без роли по-прежнему поддерживается.

## Доказательства

1. В настоящем AppContainer Kimi Code 0.38.0 получил три локальных сообщения ACP — `initialize`, `authenticate`, `session/new`. Ответ содержал ID созданной на диске сессии. В каталоге моделей появился ровно один элемент с контрольным именем `acp-bound-config-17` из сгенерированного config.toml. Поле `currentValue` было пустым, поэтому выбор модели для инференса этим опытом не подтверждается.
2. Независимый дочерний процесс с тем же SID прочитал config.toml и вычислил ожидаемый SHA-256. Попытки изменить его, записать фиктивный credential или создать ещё один файл в credentials получили Windows `ERROR_ACCESS_DENIED`. Исходные байты и identity профиля сохранились.
3. После действительной аварийной остановки владельца и имитации более позднего boot witness изменение Read на Bash в оставшемся файле остановило восстановление. Возврат исходных байтов позволил закончить штатную уборку. Повторная уборка не запустила CLI.
4. Обработчик проверки инструментов из точного EXE получил список из фактически генерируемого продуктом TOML. Для `Read` он дал разрешение, для `Bash`, `Write`, `Edit`, `Agent`, `select_tools` вернул отказ. Этот опыт вызывает обработчик отдельно от выполнения задания моделью.
5. До реализации 9 тестов не могли импортировать новый bootstrap. В UTF-8 и штатной кодировке Windows выбранный набор Kimi, ACL, восстановления, границ модулей и оформления дал по 307 passed и 1 skipped. Пропущена отдельная приёмка исполнения Git Bash. Мутанты с отключённой проверкой изменения источника, произвольным набором инструментов, пустым TOML и игнорированием подмены при восстановлении дали соответственно 1, 4, 1 и 1 красных теста.

Для повторения задать локальные `CONDUCT_TEST_KIMI_ARCHIVE` и `CONDUCT_TEST_KIMI_SHELL`, как в `KIMI-OFFLINE-KIT-REPORT.md`. Проверка самого обработчика инструментов требует локальный Node.

```powershell
python -m pytest -q tests/test_kimi_read_config.py tests/test_kimi_read_config_native.py
python -m pytest -q tests/test_kimi_session_state_native.py -k 'read-role'
python -m pytest -q tests/test_kimi_read_role_policy.py tests/test_kimi_state_journal_native.py
```

**Следующий шаг.** Данный API доступен только вместе с учтённым временным состоянием, в review без сети и с проверенным staged home. Реальный access-only файл для подписки этот код не создаёт. Для выпуска остаются защищённый комплект Kimi и shell, первая подписочная попытка с привязкой этой политики к полномочиям запуска и чтение учебного файла реальным `Read`. Протокол трёх измеренных ACP-сообщений не вызывает этот инструмент; отдельный транспорт для имитации чтения не вводился.
