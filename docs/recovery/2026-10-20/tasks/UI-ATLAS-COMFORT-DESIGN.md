# Atlas comfort — дизайн v2

TASK: `UI-ATLAS-COMFORT-TASK.md`. База — UI `d7aa206`, документация `4677f3c`.

## Варианты и граница

A: добавить новые серверные endpoints и собственный автомат подтверждений.
B: использовать подтверждённый read, существующие формы, write-host/flow и
единственную дверь transport. Выбран B. Не менять протоколы, полномочия,
бюджеты, глубину выполнения и причины отказа; не создавать скрытых повторов.
Внутри текущего shell открываются штатные подтверждения, не iframe другого UI.

Предварительные независимые линзы нашли и учли:

- D1: `scene.ending.ended` истинно и для stalled. Успешную приёмку нельзя
  выводить из этого флага или exit 0; использовать durable terminal и решения.
- D2: первый answerable gate не обязательно нужные пользователю ворота.
  Карточка и запись привязаны к точным run/task/node/standing/supersedes.
- D3: fallback на последний request меняет контекст после SSE. Выбор хранит
  точные action/attempt; исчезнувший request не заменяется соседним.
- D4: сохранённый факт чата должен показывать, к какой попытке он относился.
- D5: native dialog не наслаивается на открытую модалку утилиты; Escape
  закрывает поиск, а не лежащий под ним инспектор. Draft/caret сохраняются.
- D6: на принятом архиве поиск `Do` выбрал стоящий раньше `Confirm Do`.
  Точное совпадение названия должно предшествовать частичным совпадениям,
  включая выбор Enter. При одинаковых названиях остаются различимые группы/ID.

## Следующее действие

`createNextAction(host, door) -> {sync(ctx), close(), dispose()}`.
Root передаёт `#nextAction` в центре, подтверждённые project/mode/ready/locale,
run/task/detail. Ведущий проверяет binding перед каждым эффектом; модуль
повторно проверяет точное соответствие run/task/detail и текущий контекст.
Door предоставляет существующие readAutomation/submit/refreshRun/stop/id,
valid и openStep; сам модуль не владеет сетью и таймерами.

Порядок статусов: нет достоверного чтения → нейтральное ожидание/ошибка;
неотвеченный action → ожидается результат указанного участника;
нужное человеческое решение → один CTA «Рассмотреть …»; остановка/исчерпание
попыток → объяснение без предложения автоматического повтора; обычный Policy
без гранта → CTA предпросмотра; завершение → CTA просмотра Do.
Конкретный выбор определяется проектором графа и policy, не выдуманным порядком.
Принятый view-архив предлагает только просмотр. Runnable не означает разрешение.

Использовать `decisionRows` + `mountDecisionCard` и существующий writer либо
узкий adapter к decisionWriters с точным draft. Для Policy — automationFlow
и mountAutomation. Actor изначально пуст и появляется только из ввода человека.
Раскрытая поверхность сохраняется, input не перерисовывается без изменения.
Flow.sync не вызывается из собственного refresh→paint цикла. Поздние ответы
и неопределённые записи не становятся успехом. Повтор не создаёт новый receipt.

## Сводка и контекст

Данные сводки берутся только после `matchesAtlasAttempt` из того же bounded GET.
`files_total=null` отличается от 0; неполный список помечен. Тесты — только
recorded/external summary, не число case definitions. Outcome, тесты и verdict
остаются разными фактами. Loading/offline/foreign payload убирает старый успех.

Внутри сессии scope — весь цикл либо точные node/action/attempt. Явный выбор
узла закрепляет текущую попытку; смена select меняет пару. Закрытие инспектора
и просмотр лимитов не меняют scope. Отдельный «Весь цикл» сбрасывает его.
В cycle-scope вопрос про diff не выбирает Do молча; явная быстрая команда
«проверить тесты Do» может выбрать известный Do и показать изменённый scope.
Ответ с фактами помечен исходной попыткой. Новая сессия имеет отдельный scope.
Conversation дополнительно предоставляет read-only `paletteSteps()` и
`openStep(runId,nodeId)` с проверкой выбранного run и frozen nodes.

## Палитра и визуал

`attachPalette(dialog,{catalog,choose,restore,locale,stop})` возвращает
`{open,refresh,dispose}`. Root строит каталог из подтверждённых sessions,
members, external utilities и paletteSteps. Ключ — kind/scope/id.
Перед choose запись повторно сверяется; stale пункт не открывается.
Harness navigation не меняет lead. Утилита открывает существующий UI.
Enter никогда не означает grant/approve/model call.

Native dialog содержит доступный поиск, группы результатов и управление
стрелками/Enter/Escape. Ctrl/Cmd+K действует и из чата, без перехвата IME,
Alt-комбинаций и повторного keydown. После отмены возвращается исходный focus
и выделение, после выбора — фокус назначения. Кнопка видима на 375 px.
Никаких фоновых поисковых запросов. Ожидание честно показывает реальную фазу.
Переходы короткие, без таймеров, и отключаются при prefers-reduced-motion.
