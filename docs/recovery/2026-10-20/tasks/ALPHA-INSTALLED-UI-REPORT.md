## Воспроизводимый дефект предыдущего wheel

Порог 82 символа в руководстве относится к пути проекта. Auth-home — отдельный абсолютный путь из настроек провайдера. Его квитанции находятся в соседнем каталоге `.conduct-login-<digest>`, поэтому короткий путь проекта сам по себе не гарантирует короткого имени квитанции.

1. На Windows взять `1e1117a8`; создать временный проект длиной 80 UTF-16 units и отдельный синтетический auth-home длиной 144. Для сравнения использован тот же тест с auth-home длиной 101. Никаких настоящих токенов не требуется.
2. В Desk ввести цель, открыть советник, посмотреть условия, подписать один учебный совет. При длинном auth-home Windows открывает `active.json` (230), но отказывает в публикации `closed-<nonce>.json` (263). В журнале есть одно разрешение и одно действие, результат — `unknown`. Цепочка отказа: `NativeOwnershipError` → `login_owner_busy` → `OwnershipError`. Внешний вызов модели не происходит.
3. Та же нативная операция отдельно прошла при длинах назначения 250 и 259; на 260, 261, 263 и 280 обычный абсолютный путь дал WinError 206. При передаче расширенного имени тому же handle Windows завершила операцию и сохранила байты. То же поведение наблюдалось при проекте 123 и auth-home 144; для доказательства дефекта этого неподдерживаемого пути проекта не требовалось.

`da814a6` применяет уже имеющуюся нормализацию Win32 только к длинному абсолютному назначению и использует его же при проверке identity после переименования. Открытый handle, проверка до публикации, отказ замены существующего файла и проверка после публикации сохранены. RED: ошибки 206 на 260 и 263. GREEN: 55 проверок нативного rename, логинов, владения проектом и длинных путей в каждой из двух кодировок. Негативная проверка сохранила существующий файл и его identity даже при обращении через Win32-псевдоним.

На финальном установленном wheel длинный случай завершился успешным применением предложения, для трёх временных заимствований записаны три закрытые квитанции длиной 263, активной записи нет. Испытание относится к поддержанному входу с доступным исходным `active.json` и длинным именем назначения.
