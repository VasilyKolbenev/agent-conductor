# Источник рабочих файлов для коллеги

Итог: исправлено на `bb070e8`. В Chromium коллега закрепил Git в учебном профиле,
переоткрыл проект и дошёл до предпросмотра с теми же целью и материалом.
Коллега с проектом без репозитория по-прежнему выбирает пустую рабочую папку.

## Доказательства

На `53a99c1` Chromium показал, что при существующем репозитории и отсутствии
закреплённого Git кнопка «Далее» ведёт к последующему отказу подготовки.
Подробный мастер утверждал, что репозитория нет. После исправления шага «Источник
файлов» отдельный красный свидетель нашёл вторую потерю: когда новый процесс уже
читает Git, форма всё ещё объявляла сохранённым черновик из памяти старого сервера.
Обычное обновление страницы очистило введённую цель.

Теперь первый экран показывает, что в папке есть `.git`, предлагает закрепить
исполняемый файл и переоткрыть проект на том же порту. После нажатия «Проверить
источник файлов» и подтверждённого ответа нового процесса открытая вкладка сохраняет
ответы в его хранилище черновиков. В подробном мастере цикл без исполняемых шагов
сохраняет прежний путь. Для проектов без репозитория остаётся явный выбор пустой папки.

- Чистая сборка из Git-архива `bb070e83ea3627943a9573cfa29966a6b0cd4fe9`.
  SHA-256 wheel `bd69b2d86db645a7d32bddf2c4aa9227fc0da9a6a35c55ba3d86f8e52d65704d`.
  Импорт родительского и обоих дочерних серверных процессов проверен по пути
  чистого venv.
- Из установленного wheel прошли 6 проверок Chromium. В RU/375 и EN/1280 после
  перезапуска на том же порту прочитан правильный коммит. Обновление страницы сохранило
  цель, заголовок и текст материала. Штатная подготовка перенесла точные байты
  `source.txt` в рабочую папку задачи и отправила материал на сервер.
  Явный выбор пустого каталога отдельно проверен на каждом языке в двух конфигурациях
  учебных адаптеров. Границы дошли до предпросмотра. Разрешений на запуск не выдавали.
- 455 тестов прошли в UTF-8 и 455 в CP1251. 39 проверок Chromium прошли по Git,
  материалам, мастеру и пустому пути.
- Визуальные доказательства в `.pytest_cache/pin-wheel-proof/`.
  Снимки `ru-source.png` и `en-source.png` показывают действие для владельца.
  Там же лежат снимки и видимый текст после восстановления и перед разрешением.

## Мутанты

| Изменение | Результат |
| --- | --- |
| M0, неизменённая копия | 2/2 прошли |
| M1, разрешить переход при недоступном Git | Кнопка «Далее» оказалась включена, свидетель упал |
| M2, пропустить сохранение ответов после смены процесса | После обновления страницы цель стала пустой, свидетель упал |
| M3, назвать существующий репозиторий отсутствующим | Упал двуязычный регрессионный набор на русском тексте |

Исходные файлы в копии восстановлены после каждого мутанта, их SHA-256 сверены.
При настройке свидетеля два сервера в одном Python-процессе оставляли соединения
браузера со старым Git reader; штатный перезапуск проверен двумя отдельными процессами.
После обновления страницы разрешение на запуск может ждать имени владельца. Условие
этой задачи — подготовка копии, поэтому свидетель проверяет сам предъявленный
предпросмотр и содержимое диска. Установка Git, защищённые сборки и сервер владельца
не затрагивались.
