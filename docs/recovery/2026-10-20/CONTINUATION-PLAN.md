### R0. Проверка восстановленной среды

Выполнено; пункты ниже описывают процедуру восстановления, а не новую очередь
повторных проверок. Полный core suite остаётся отдельной проверкой R5.

1. Записать `git rev-parse HEAD`, `git branch --show-current`, `git remote -v`, `git status --short`; не менять identity Git на выдуманное имя.
2. Использовать Python 3.11+ и отдельную `.venv`. Установить `.[dev,browser]`: даже core suite импортирует Playwright через `tests/test_browser_gate.py`. Chromium нужен для настоящих браузерных проверок.
3. Проверить `conduct --help`, импорт пакета и `conductor.__version__`. У CLI нет `--version`.
4. Запустить демо и проверить, что оно реально обслуживает локальную страницу. Demo не требует входа к провайдерам и использует временную копию данных.
5. Зафиксировать результаты выбранных проверок и что не запускалось. Для полноценного базового прогона core: `python -m pytest -q --basetemp <короткая-временная-папка>`.
6. На Windows использовать короткие пути временных данных. CI специально использует `pt`, `bg`, `bgr`: длинные пути способны вызвать предусмотренный контрактом `windows_path_too_long`. Не «исправлять» продукт, расширяя лимит только ради длинного каталога теста.

### R1. Вернуть понятный результат проверок

Последний сохранённый CI: run `39149580847`, HEAD `4d0e3af`.
Windows core на Python 3.11/3.12, сборка wheel, Ubuntu browser gate и installed-wheel road Ubuntu/macOS прошли. Core Ubuntu/macOS и browser Windows/macOS содержали failures.

Первичный разбор уже выполнен: см. [CI-BASELINE-NOTES.md](CI-BASELINE-NOTES.md).
Не повторять общий поиск причин с нуля. Очередь конкретных задач:

1. **R1.1 — первое исправление.** Во всех четырёх POSIX unit jobs тест
   `tests/test_adapter_boundary_launch.py::test_a_confined_adapter_over_the_shipped_runner_starts_no_task_child`
   получил необработанный `ImportError` из `_winlaunch.py:17` вместо ожидаемого
   `adapter.error`. Opus прослеживает границу преобразования исключения и задаёт
   минимальное исправление; Sonnet реализует его, Codex проверяет отказ до запуска
   task child, cleanup и сохранение Windows-защиты. Существующий POSIX-тест должен
   проходить без превращения в skip. На Windows можно проверить соседние контракты,
   но окончательное подтверждение требует POSIX-окружения.
2. **R1.2 — отдельное расследование.** macOS / Python 3.11:
   `test_rejected_review_completes_the_run[the human rejects the result]`
   увидел завершённый plan, но holder оставался `run`. Сначала выяснить
   контракт порядка завершения; не лечить добавлением sleep или удалением assert.
3. **R1.3 — Windows browser 10055.** Использовать сохранённые логи и спроектировать
   минимальное воспроизведение. AFD-попытка 13 октября, commit `cd215778`,
   действительно состоялась, но оба порядка прошли и `failures_total=0`.
   Причину 10055 она не установила. Если нужна новая трассировка, отдельно
   определить её цель, ограничения и ожидаемые данные.
4. **R1.4 — macOS browser setup timeout.** Reverse gate упал на setup
   `test_choosing_each_tab_shows_that_screen_and_only_that_screen` из
   `test_studio_rendered.py`. Причинная связь с предупреждениями macOS не доказана;
   не объединять случай с Windows 10055.

Для каждого исправления сохранять минимальное воспроизведение, команды и числа
passed/failed/skipped. Свежие локальные ошибки доступа из первого sandbox-прогона
не попадают в эту очередь: вне sandbox те же проверки прошли без правок продукта.

Критерий завершения R1: нет необъяснённых падений в затронутых проверках; каждый оставшийся платформенный пробел явно назван. Локальный успех Windows не заменяет результат Linux/macOS.

### R2. H5: запись в login-home

Факт текущего кода: `LOGIN_LOAN_OPEN = False` в
`src/conductor/command/adapters/process_boundary.py`.
Права на обновление credentials сейчас позволяют изменять и исполняемую vendor-конфигурацию, которую позже могут читать процессы вне boundary.

Прочитать вместе:

- `process_boundary.py`, `process_loans.py`, `process_acl.py`, `process_profile.py` и `harness_attempt.py` в `src/conductor/command/adapters/`;
- `src/conductor/command/execution_boundary.py` и `boundary_entry.py`;
- `tests/test_process_loans_scope.py`, `test_process_loans_native.py`, `test_process_loans_recovery.py`, `test_process_loans_overlap.py`, `test_process_loans_mutex.py`;
- `tests/test_production_door_boundary.py`, `test_execution_boundary_refusal.py`, `test_adapter_boundary_roads.py`.

Opus составляет матрицу по harness: что требуется читать/записывать, какие объекты содержат credentials, какие могут менять последующее исполнение, как переживаются прерывание, перезапуск, параллельная попытка, подмена пути и reparse point. Выводы подкрепить текущим кодом и, при необходимости, первичными vendor-документами.

Codex проверяет границу и записывает новое решение с причиной. После этого Sonnet получает ограниченную реализацию.

Критерии: запрещённая запись действительно отклоняется; разрешённое обновление работает; отказ происходит до побочных эффектов, где это обещает контракт; выдача и возврат прав корректны после ошибок и прерываний; production-отказ и фактический launcher не расходятся. Простое включение флага задачу не закрывает.

Критерии:

## Как сохраняем контекст дальше

Для каждой задачи хранить в Git короткое задание и отчёт: исходный HEAD, ожидаемое поведение, изменённые файлы, реально выполненные команды, результаты, непроверенное, решение ревьюера, следующий шаг. Не включать аккаунтные секреты, raw vendor output и большие CI-архивы в обычные коммиты.

Разделять причины статусов: «реализовано», «локально проверено», «проверено CI», «принято ревью», «принято владельцем». Перед передачей фиксировать `git status`; при параллельных задачах использовать отдельные ветки/worktree или непересекающиеся файлы. Обновлять старый план по итоговому состоянию, а не накапливать противоречивые списки.

После завершённых этапов сохранять проверенные коммиты в согласованном remote. Публикация в GitHub не выполнялась в рамках подготовки этого плана.
