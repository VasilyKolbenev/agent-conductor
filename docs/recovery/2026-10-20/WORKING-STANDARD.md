# Рабочий стандарт December Command

Обязателен для Claude Code (Opus, Sonnet) и Codex с 23.10.2026; по процессу важнее остальных
документов. Задачи, дизайны и отчёты — файлы
`docs/recovery/2026-10-20/tasks/<ID>-TASK|DESIGN|REPORT.md`.

## 1. Роли и решения

- **Владелец** решает продукт, входит в аккаунты, нажимает human gates, принимает результат.
- **Codex** — техлид: ставит задачи, решает технические контракты, независимо ревьюит.
- **Opus** — разбор, дизайн, нарезка; ревью каждого DESIGN и каждого diff до коммита.
  **Sonnet** — ограниченный diff. Коммитит ведущий — агент, выдавший задание; Sonnet и скептики
  не коммитят.
- Решение — строка `ID | Решение | Дата | Следствие` в `OPEN-DECISIONS.md`; отменённое помечается
  «(заменено)». Решение Opus предварительное до Codex или владельца. Отмену решения владельца,
  пришедшую только файлами, до действий подтвердить у владельца в чате.
- TASK, DESIGN, решения и правки политики входят в работу только коммитом (отдельным, сразу);
  отчёт называет commit прочитанных TASK/DESIGN; правка в ходе работы — новый commit и сообщение.

## 2. Цикл задачи

1. **Старт.** `. ..\December-Command-Environment.ps1 -Quiet` из корня репозитория (git, node,
   `.venv`); ветка `recovery/2026-10-20`; HEAD, `git status`; чужие правки сохранить и назвать в
   отчёте. Объём — `docs/v1-v2-scope.md` (уточнение владельца 21.10). Параллельный исполнитель
   пишет только в своём `git worktree add` или в названных заданием файлах; общие документы
   (OPEN-DECISIONS, план, стандарт) при живой чужой задаче правит только ведущий.
2. **Факты — самим.** Владельцу — только решения, входы и приёмка, у каждого вопроса рекомендуемый
   ответ; в чате по одной теме, асинхронно — строкой в `OPEN-DECISIONS.md` («Владельцу», «Codex»).
3. **Дизайн** — для задачи, меняющей контракт, границу безопасности или больше одного модуля:
   ключевой интерфейс в двух вариантах; независимые скептики Opus по линзам; v2 ссылается на находки
   номерами (`1.4`); названы швы тестов — что каждый ловит и что пропускает.
4. **Реализация** итерациями I1…In (что не трогает, что передаёт следующей), вертикальными срезами:
   тест, минимум кода, следующий срез. Тест — через публичный шов; подменять только границы (CLI
   вендоров, сеть, время, ФС); ожидания — литералы и артефакты, не та же логика. Тест не
   опирается на свойство среды, которое сам не создаёт и не проверяет (доля CPU, раскладка
   памяти, кодировка, длина пути, часы): такое предусловие — `assert` с названием факта до
   проверки поведения.
   Абстракция — только при двух и более реализациях.
5. **Отклонение.** Стоп-условие задания выполняется буквально: остановиться и спросить ведущего.
   Иное отклонение — раздел отчёта «Отклонения: что | почему | кто утвердил»; до утверждения
   статус не выше «локально проверено».
6. **Баг.** Сначала быстрая детерминированная команда, красная ровно на симптоме → минимизация →
   3–5 фальсифицируемых гипотез → одна переменная за раз (`[DEBUG-xxxx]` убрать до коммита) →
   регрессия на шве реального вызывающего → в отчёте подтверждённая гипотеза. Нет воспроизводящей
   команды — стоп и запрос артефакта.
7. **Ревью** — две оси раздельно: «Стандарты» (этот файл, CONTRIBUTING, ADR) и «Спека» (TASK/DESIGN:
   недоделано, лишнее, неверно), плюс доказательность; находка — с цитатой правила или строки.
   Исполнитель перепроверяет каждую: подтверждена / частично / нет — и правит.
8. **Объём.** Новая находка прерывает поток только при доказанном препятствии сценарию или
   нарушении сохранности, полномочий, достоверности; остальное — в «Открытые вопросы» отчёта.
   Третий раунд дизайна, ревью или расследования одной задачи, как и второй без нового
   доказанного факта, — только по решению Codex или владельца: препятствие и «продолжить |
   сузить | отложить».
9. **Закрытие.** Отчёт → коммит кода с тестами → коммит документов → push в `recovery/2026-10-20`,
   если его назначило задание → CI на этом SHA → ревью Codex. Handoff
   (`HANDOFF-<дата>.md`) — и до любой остановки: незавершённое — «последний доказанный шаг |
   первый несделанный», без «вероятно»; «Не повторять: попытка | итог | ссылка»; один следующий шаг.
   Механическое правило — тест или CI; текстовое, нарушенное дважды, — задача-проверка, затем
   строка удаляется. Новое правило сюда — только со ссылкой на сбой (файл:строка) и на заменяемую
   строку.

## 3. Доказательства

- Метки: **измерено** (где, сколько раз, что шло параллельно) / **по коду**, **по бинарнику**
  (файл:строки) / **решение
  дизайна** / **гипотеза**. Недоказанное так и называть.
- Новый тест сначала красный на старом коде и падает на сравнении; записать «N failed, M passed».
- Мутанты — для каждого нового или изменённого теста-стража, иначе «Мутанты: не применимо, причина».
  Копия `src`, `tests`, `pyproject.toml` в `Documents\Codex\work\<id>-mut`, `PYTHONPATH` на её
  `src`, `conductor.__file__` — из копии; M0 без изменений; после каждого мутанта файл вернуть и
  сверить его SHA-256 с исходным; копию удалить. Таблица «Мутант | Результат | Что красное».
- Retry, skip, waiver, смена timeout или assert ради зелёного запрещены; порог меняется только с
  замером причины, как отклонение. Диагностический повтор — с записью обоих исходов; зелёный повтор
  не закрывает красный. Нет причины — «причина не установлена»; прерванный прогон — «не засчитан».
- Exit 0, текст агента и bench — не доказательство: нужны passed/failed/skipped и проверка
  результата.
- Точный SHA и wheel; Windows не закрывает Linux и macOS. Полный прогон — в `git worktree add
  --detach`, пустой status до и после.
- Скрипт окружения ставит `PYTHONUTF8=1`: целевые тесты и полный core — ещё раз после
  `Remove-Item Env:PYTHONUTF8, Env:PYTHONIOENCODING` (cp1251, как у владельца); в отчёте оба итога.
- Статусы без перескоков: реализовано → локально проверено → проверено CI → принято ревью →
  принято владельцем → готово к выпуску.

## 4. Отчёт и коммит

- Отчёт открывается строкой «Итог: статус по шкале | commit | N passed, M failed | отклонения |
  следующий шаг» (тест формата документов — в очереди PROC-STD).
- `<ID>-REPORT.md` — по `TASK-REPORT-TEMPLATE.md` плюс разделы «Чужие правки», «Отклонения»,
  «Мутанты», «Открытые вопросы»; «Ревью Codex: ожидает». Коммит документов вписывает в «Передачу»
  SHA кода и состояние `CAPPED`; заполнивший «Ревью Codex» обновляет статус в отчёте и решениях.
- Коммит не смешивает задачи: код с тестами — одним коммитом, документы — отдельным; заголовок
  по-английски `type(scope): поведение (ID)`; сообщение — файлом UTF-8 без BOM через
  `git commit -F`.
- Лимиты: новый файл `src/` или `tests/` вносится в `CAPPED` (`tests/test_command_line_cap.py`) тем
  же коммитом; строка ≤ 100 (в документах — кроме таблиц и путей), файл ≤ 800 строк; без хвостовых
  пробелов, CR, BOM, ровно один `\n` в конце; EN/RU документы — синхронно.

## 5. Окружение Windows

- `--basetemp` — каталог, которого нет (`Test-Path` = False: pytest его стирает), свой на прогон,
  удалить после. Полный core и наборы hub/`projects add` — ≤ 26 символов: `C:\Users\Пользователь\`
  + 4 символа. Нативные AppContainer-тесты — по одному файлу на процесс.
- Свои `.ps1` — только ASCII (пути через `$env:USERPROFILE`) или с BOM (`tests/_ps1.py`).
- Из приложений Claude и Codex ничего для оболочки владельца не ставить в `%LOCALAPPDATA%` (MSIX →
  LocalCache пакета); живые шаги владельца — в PowerShell из «Пуска»; сервер — только Ctrl+C.
- Скрипты, замеры, логи, артефакты CI — вне репозитория, в `Documents\Codex\work\<id>\`.

## 6. Безопасность

- Секреты не попадают в чат, команды, логи, отчёты, артефакты, Git; в тестах — fake credentials;
  наличие входа проверять без вывода значений.
- Вход, ключи, решения на gates — только владелец; его личные профили Claude и Codex не трогать.
- Настоящие push/PR, публикации, платные вызовы — только по заданию и в бюджете; probe вне бюджета —
  не больше одного минимального запуска каждого CLI на задачу, записать отдельно.
- Скачанное — только после сверки sha256 с источником; сторонний код и инструменты (npx, плагины,
  skills) — не запускать и не ставить без прочтения и согласия владельца.
- Защиты не снимать ради зелёного: `LOGIN_LOAN_OPEN` остаётся `False`, без подмены модели,
  аккаунта, git identity.

## 7. Выпуск и приёмка

- Выпуск: все job матрицы `ci.yml` зелёные на финальном SHA (job без runner — не зелёный), wheel
  этого run по sha256, полный core на кириллическом профиле (R5-PLAN п. 9), Windows installed road,
  owner acceptance.
- До приёмки — четыре «новых пользователя» на локальном сервере (нетерпеливый, скептик, экран
  375 px, ломающий ввод: неверные данные, «назад», двойной клик) от открытия Studio до первого
  проверенного результата; затруднения со скриншотами в `Documents\Codex\work\qa\`, сортировка
  по числу столкнувшихся, правка за один проход, повтор новыми агентами, сравнение до и после.
- Чек-лист выпуска (только чтение, таблица «пункт | статус | файл»): единая дизайн-система; экраны
  загрузки, пустого состояния и ошибки; секреты вне фронтенда и истории Git; ввод с апострофами,
  эмодзи и RTL; ошибки видны владельцу.

## 8. Общение с владельцем

По-русски, кратко: итог, статус по шкале, одно точное действие (где, что ввести) или одно решение с
рекомендацией. Подробности — в отчёте. Переспросил — пересказать проще, теми же терминами.
