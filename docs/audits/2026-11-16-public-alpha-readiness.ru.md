## Новые проверки на Windows

- Запустили обычный START.cmd из копии ZIP с подтверждённым SHA-256 в новом окружении,
  с кириллицей и пробелами в пути. Во второй задаче воспроизведены две проверки первой,
  проверяющий и ссылка на источник. Три правки в чате сохранили исходную запись.
  После штатного закрытия обе задачи открылись снова, SHA-256 журнала совпал.
  В браузере было ноль внешних и записывающих запросов. Черновик плана живёт во вкладке.
- На отдельной установленной Studio сверили происхождение двух diff, фактический вывод трёх
  unittest и заключение независимого Codex с сохранённым ответом принятой попытки
  `counter-src-19956c8-r1`. Исходный журнал сохранил все 46 записей и SHA-256.
  Офлайн-пример Pilot 1 показывает сводные числа внешней проверки; полный нативный вывод
  проверен на оригинальном архиве. Циклы и модели в аудите не запускались.
- Из 58 профильных проверок памяти, коррекции, утилит и сводки в стандартной длинной
  временной папке 57 прошли, одна упала при создании квитанции. С короткой временной
  папкой по правилам проекта те же 58 прошли. Причина различия проверена отдельно
  на опубликованном колесе и поставляемом first_task.py, см. пункт 2 ниже.

Первичные журналы этой проверки остались у автора аудита. Повторить проверку двух задач
на текущем выпуске можно по [публичному сценарию приёмки](../acceptance-two-tasks.ru.md).

## До широкой выдачи

1. **Самостоятельное подключение подписок и допустимый способ входа.** В активном проекте UI
   регистрирует ручную утилиту. Совместимой CLI нужен локальный мост; роли и квоты требуют
   адаптера. Встроенный путь ведёт в PowerShell и требует остановки сервера. Для Kimi карточка
   предлагает вход, хотя живая роль ещё не подтверждена. Приёмка: чистая Windows, собственный
   аккаунт, из карточки — официальный вход, проверенная роль и источник доступной квоты,
   затем реальный результат по каждому из четырёх харнессов. Codex + Grok уже дали один
   принятый совместный результат; для Claude есть изолированный Goal, для Kimi — офлайн-сессия.
   [Пользовательский путь](../first-run-v1.md) ·
   [Результат настоящего цикла](https://github.com/VasilyKolbenev/agent-conductor/blob/3304810f645b0e515b95934328009f1456139c58/docs/recovery/2026-10-20/tasks/DALIO-FIRST-COMPLETE-REPORT.md).

   Для Claude есть отдельный вопрос модели интеграции. Anthropic допускает личный вход
   в официальный неизменённый Claude Code при своих условиях и отдельно ограничивает
   обработку сессионных токенов сторонними разработчиками. Реализация Arachnid создаёт
   временную access-only копию. До публичного заявления о поддержке этого пути получить
   подтверждение именно этой схемы либо проверить вариант, где входом и токеном целиком
   управляет официальный CLI. Технический результат Goal сам по себе этого не доказывает.
   [Схема адаптера](../../src/conductor/command/adapters/claude_relay.py) ·
   [Официальная документация Anthropic](https://code.claude.com/docs/en/legal-and-compliance#authentication-and-credential-use).

2. **Длинный путь при сохранении первой задачи на Windows.** На установленном колесе Pilot 2
   одна и та же первая задача записалась в короткой папке. После добавления 65 символов
   в путь система вернула FileNotFoundError при создании временной квитанции; её полный путь
   имел длину 285 символов. Падение профильного теста пришлось на ту же операцию.
   Штатная установка в чистом профиле выше прошла. Приёмка исправления: сохранение обеих задач
   и повторное открытие из глубокой рабочей папки с кириллицей без потери источника.
   [Запись квитанции](../../src/conductor/command/run_files.py) ·
   [Подготовка первой задачи](../../distribution/windows-two-task/first_task.py).

3. **Инструкция приёмки должна совпадать с колесом.** В обеих версиях инструкции в разделе
   «Факты этой сборки» остались Grok 1.0.5 и неуспешный Diagnose. В принятом цикле
   диагностику выполнил Grok 1.0.13. Кроме того, инструкция ручного переноса Pilot 1
   называет кнопку «Отправить задачу», в интерфейсе — «Подготовить передачу».
   Перед выдачей следующего комплекта сверить версии, правдивость статусов и подписи
   с установленной сборкой на русском и английском.
   [Приёмка RU](../owner-acceptance.ru.md) · [EN](../owner-acceptance.md) ·
   [Инструкция Pilot 1](../../distribution/windows-pilot/HARNESSES.txt).

4. **Один выпускной кандидат и внешний проход.** На выбранном SHA получить зелёную CI-матрицу,
   wheel из этого прогона и SHA-256, пройти полный Windows core, установку, четыре UX-сценария
   финальной Studio и приёмку владельца. До этого коллега уже может самостоятельно пройти
   именно опубликованный пилот. Отдельно для обещания длительной автономной работы показать
   на подписках задачу с замечанием, доработкой, возобновлением и проверенным итогом.
   [Стандарт приёмки](../recovery/2026-10-20/WORKING-STANDARD.md#7-выпуск-и-приёмка).
