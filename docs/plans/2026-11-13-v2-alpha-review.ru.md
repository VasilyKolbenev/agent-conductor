# Arachnid 2.0 — предложение по составу альфы

Срез на 13 ноября 2026 года. Windows Pilot 1 построен из CI-коммита 7f6b825.
Следующие пункты относятся к кандидату на 2.0. Дата выпуска зависит от живой приёмки.

## Что меняется для оператора

Предлагаемый сценарий: «Исправь причину сбоя. Если проверка отклонит правку,
передай замечания исполнителю. Вернись с проверенным результатом».

Атлас показывает доступные роли и способ доступа каждого участника. Оператор видит
границы до запуска. Если первая правка отклонена, исполнитель получает конкретные
замечания и протокол тестов. Вторая попытка оставляет свой diff, тесты и вердикт.
Обе попытки доступны в том же чате. При исчерпании разрешения работа останавливается.

## Что уже есть и что довести

| Направление | Состояние | Критерий следующего шага |
| --- | --- | --- |
| Studio с Атласом, историей слева, орбитой и материалами справа | Поставлено в пилоте. Есть просмотр одной попытки, передачи, diff, тестов и вердикта. | Сохранить тот же контекст для второй попытки и показать, какие замечания закрыты. |
| Планирование через чат | Принятый сценарий Codex + Grok работает. В планировщике закреплены ведущий, роли и цикл. Редактор собственных циклов существует отдельно. | Атлас предлагает только подтверждённых участников, объясняет ограничения, даёт заменить роль до разрешения. |
| Подключение внешних CLI | Работают ручная карточка и текстовый мост. | До добавления виден способ передачи; после обмена виден источник ответа. Для штатного исполнения нужна проверка конкретного адаптера. |
| Исправление после отказа | Ядро dalio-v6 умеет вернуть замечания независимого проверяющего в Do, повторно проверить и остановиться на лимите. Это покрыто локальным HTTP-сценарием с двойниками. Текущий планировщик Атласа выдаёт по одной попытке. | В чате явно предложить бюджет на доработку, затем на подписках показать два diff, оба заключения и исполнение предела. |
| Полезность для сложных задач | Есть одно принятое исправление счётчика, три unittest и независимый проверяющий. | Провести ещё один составной сценарий, измерить вмешательства человека, длительность и достигнутые критерии. |
| Личная память, перенос между проектами, до трёх одновременных задач | Направления V2 остаются актуальными. История сессии и сохранённый журнал уже доступны. | Сначала проверить перенос одного решения между двумя задачами с источником и согласием оператора. Параллелизм оценивать отдельно на четырёх задачах с лимитом три. |

Августовское расписание и пункт «впервые пройти цикл Codex + Grok» переведены в историю.
Рынок расширений, обучение стратегии по накопленным данным и автоматическая консолидация
памяти сохраняются в долгосрочном плане. Готовность одного поставщика не переносится на другие.

## Четыре дополнительных варианта

**Qwen Code.** Нативная CLI на Windows. Qwen документирует вход через аккаунт
chat.qwen.ai с подпиской Plus/Pro и сервер ACP. Документация подтверждает две возможности
по отдельности. Работа подписки из Arachnid и расход её квоты требуют отдельной проверки.
Alibaba Cloud Model Studio Coding Plan — другой продукт, его условия ограничивают
использование ключа интерактивными поддерживаемыми инструментами. Для автономного пилота
это не запасная замена Qwen OAuth.
[Вход Qwen](https://qwenlm.github.io/qwen-code-docs/en/users/configuration/auth/) ·
[Реализация ACP](https://github.com/QwenLM/qwen-code/blob/ddeba2fd3436d86780dc90cf621e46e67542656e/packages/cli/src/acp-integration/acpAgent.ts) ·
[Условия Alibaba](https://www.alibabacloud.com/help/en/model-studio/coding-plan).

**GLM.** Собственный харнесс Z.ai — ZCode; OpenCode с Z.AI Coding Plan — отдельный
поддерживаемый клиент. У ZCode есть JSON-вывод CLI и app-server. У OpenCode есть ACP.
Ключ Coding Plan внутри поддержанного клиента расходует подписку по правилам плана.
Прямой вызов из произвольного приложения, общий ключ для пользователей и перепродажа
доступа выходят за эти условия. Проверять один конкретный поддержанный вариант
с личным входом владельца и явно согласованным режимом работы.
[Настройка ZCode](https://zcode.z.ai/en/docs/configuration) ·
[OpenCode с планом GLM](https://docs.z.ai/devpack/tool/opencode) ·
[Условия Z.ai](https://docs.z.ai/legal-agreement/subscription-terms).

**Antigravity.** Google описывает agy acp для интерактивных редакторов и agy -p для
собственных скриптов и CI. Обёртывание agy сторонним агентом или приложением по consumer-плану
официально не поддерживается. Для этой подписки оставить ручной перенос из официального
клиента там, где он доступен.
[Документация ACP](https://antigravity.google/docs/ide/extensions/acp/) ·
[FAQ Google](https://antigravity.google/docs/faq#can-i-use-antigravity-cli-headless-mode-in-third-party-coding-agents-or-automate-account-switching).

**DeepSeek.** В 7f6b825 уже есть штатный deepseek-harness для @deepseek-ai/dsh
0.1.0-rc.7 с ролью dispatch. Он использует прямой API-ключ и денежный баланс.
Восемь локальных проверок на двойниках прошли. Вариант с месячной подпиской и
запуск на реальном аккаунте этим результатом не подтверждаются.
[DSH](https://www.deepseek.com/harness/en/) ·
[Баланс API](https://api-docs.deepseek.com/api/get-user-balance/).

## Критерий первого нового участника

Первым исследовать Qwen Code. Зафиксировать CLI и разрешённый способ его использования,
проверить запуск без личного профиля и согласование протокола до задачи. Затем —
одна явно разрешённая задача на чтение учебного файла по собственной подписке, отдельная
проверка ответа и показания квоты с указанием источника, если поставщик их выдаёт.
Текстовый ответ произвольной CLI сохраняется как ответ утилиты. Роль участника цикла
становится доступной только после интеграции с исполнением, разрешениями и проверкой.

Для широкой выдачи остаются четыре личные подписки по ALPHA-FOUR, четыре пользовательских
прохода финальной Studio, приёмка владельца, зелёный CI и wheel именно финального SHA.
